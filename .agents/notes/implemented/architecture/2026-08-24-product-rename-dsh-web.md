# Agent Note: Product rename from dsh-web-ui to dsh-web

Status: implemented

## Problem

The product name dsh-web-ui carried a redundant -ui suffix and no longer matched a family that ships a Workshop store, a skin pipeline, and remote-access tooling alongside UI plugins. A rename touches four independent layers with very different reversibility: the GitHub repository slug, documentation and display copy, the published npm aggregate package name, and runtime identifiers persisted in user profiles. Treating the rename as one atomic string swap would have broken installed profiles and orphaned the published package.

## Decision

The product is renamed to dsh-web at the display and source layers, while every runtime, wire, and storage identifier is frozen:

- Renamed: the GitHub repository slug zhu1090093659/dsh-web (old URLs redirect), the aggregate package directory packages/dsh-web-all and its npm name @linxin666/dsh-web-all, the settings package directory packages/dsh-web-settings (its published npm name @linxin666/dsh-client-ui-web-ui-settings is unchanged), the shared workspace package name dsh-web-shared (private, never published), the seven repo-local skill directories dsh-web-*, docs/dsh-web-banner.png, and all prose/URL occurrences outside frozen history.
- Frozen because they persist in user profiles or on the wire: the web-ui-* cordis bundle id namespace (19 aggregate rows), the dsh-web-ui-market settings section id, the /api/dsh-web-ui-settings bridge path and x-dsh-web-ui-settings-proxy-token header, and the dsh-web-ui-telemetry-visitor / dsh-web-ui-telemetry-day localStorage keys.
- Frozen because they are historical or external: docs/archive/, docs/release-notes/, .agents/notes/archived/, the JAVA-LW/dsh-web-ui fork reference, and local filesystem paths under /Users/zcl/code/dsh-web-ui (the local checkout directory keeps its name).
- npm migration: the next tag release publishes @linxin666/dsh-web-all and the final @linxin666/dsh-web-ui-all version side by side, then the old name is deprecated with a pointer message. Dual-publish runs for two releases, then the old package stops receiving updates. No shim package: the aggregate carries runtime compat code whose mount semantics do not survive re-export.
- docs/ and README pairs describe only the current name (no rename narration), per the documentation standard; the migration story lives in this note, the commit, and the release notes of the renaming release.

## Alternatives considered

- Display-layer-only rename (repository + docs, npm name untouched): rejected because the install entry point is part of the brand surface; the npm aggregate name was the user's explicit migration target. It remains the rollback floor: every frozen identifier keeps this change revertible at the display layer.
- Full rename including runtime identifiers (web-ui-* bundle ids, section id, telemetry keys): rejected. Those strings live in every installed profile and browser storage; renaming them requires a permanent migration-compat layer whose only payoff is identifier aesthetics, and a migration bug presents as lost plugins or reset settings.
- A different new name without the dsh web CLI-collision shape: not pursued; the user owns naming and chose dsh-web. Copy convention mitigates the collision: prose uses the spaced form "DSH Web" for display, dsh-web for slugs and URLs, and the family is always presented as community plugins for the official DSH Web GUI, never as the official dsh web command itself.

## Consequences

- Existing installs keep working with zero migration: bundle ids, section ids, API paths, and storage keys are byte-identical, so upgrading profiles resolve unchanged.
- Repository slug and npm install command diverge from the frozen identifier vocabulary; readers meet web-ui-* ids in profiles and must not "fix" them — the freeze list above is the authority.
- The old npm package name remains resolvable forever (npm names cannot be deleted after 24h of downloads); the deprecate pointer is the only migration channel.
- Verification: pnpm typecheck, pnpm test, pnpm docs:check, pnpm test:scripts, and the aggregate/gallery/market/skin-center checks all pass on the rename commit; market/dist and gallery/ artifacts were regenerated by their builders, not hand-edited.
