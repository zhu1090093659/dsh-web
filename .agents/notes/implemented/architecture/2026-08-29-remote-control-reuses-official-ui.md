# Agent Note: Remote control reuses the official UI (mobile adaptation replaces the /m surface)

Status: implemented

## Problem

dsh-remote-web-ui shipped its own mobile UI: a standalone `/m/` surface (views, markdown renderer, mux bridge, theme, PWA shell, the `/m/api` allowlist proxy, and a paired model-catalog) served beside the official desktop GUI. Every official client change had to be re-implemented by hand on the phone surface, and the two surfaces drifted by design: the phone saw a thinner product (no settings, no plugin cards, no deliverables) while the desktop saw the real one. The reference implementation [dsh-LAN](https://github.com/MrMu666/dsh-LAN) solved the same problem the other way — since its v48 it deletes its own surface and injects a portrait-touch adaptation over the official UI — and this repository adopted that direction.

## Decision

- **One surface.** The `/m/` surface and its entire pipeline are deleted (mobile views, mux/rpc, markdown, PWA/service worker, `/m/api` proxy with its method allowlist, paired model catalog, `mobile-pending`, the `mobileEnterToSend` config). The QR link now points at the official Web GUI on the same origin for every device: phones get the injected adaptation, PCs get the full desktop.
- **Portrait-touch adaptation layer** (`src/client/mobile-adapt.ts`, ported from the dsh-LAN reference, MIT): while the viewport is portrait + coarse pointer + narrower than 1100px, the layer injects a CSS sheet keyed on CSS-Modules semantic suffixes (`[class$="_composerSeat"]`…) so selectors survive official hash churn, plus gesture JS — a draggable whale button as the collapsed-sidebar entry (wired to `ctx.layout.toggleSidebar()`), left/right swipe, long-press session menus, Enter-inserts-newline, 16px inputs against iOS focus zoom, safe-area padding, and a column layout for the settings modal. A sessionStorage opt-out (`dsh-remote-force-desktop=1`) disables it.
- **Host mode for paired remote desktops.** On the 0.1.2-alpha.1 line the host `/api` surface has no per-method privilege pin — the "configuration plane is local" behavior lives in the browser, where client plugins branch on `connection.isLoopback` (the settings mirror falls back to a memory scope, the document controller to a memory stub). The channel boot script therefore installs the transport hook `__DSH_TRANSPORT__ = { ownsHost: true }` on non-loopback origins before any boot entry: the official UI presents its full configuration surface, and every call still rides the gated `/remote` channel as a loopback-shaped request. This replaces the earlier plan of a dsh-LAN-style `/lanapi` proxy, which exists for lines that pin privileged methods host-side; no endpoint table is maintained.
- **The control planes stay physically local.** `/remote` still refuses `/api/pair/*`, `/api/update/*`, `/api/plugin-manager/*`, and `/api/dsh-desktop-launcher/*`. The family settings bridge (`/api/dsh-web-ui-settings`) is re-exposed to paired devices — full settings parity was the point. The stale dotted `LOOPBACK_ONLY_METHODS` table (an rc-line artifact; the contract pins had already been suspended) is gone.
- **The QR entry is a top-level route, `/pair-accept`.** A LAN device hits the harness browser-auth gate (authority-bound session cookie) before any pairing code can run, and the gate's token redirect drops query parameters. The route sets the device cookie, then 303s to `connection.authenticatedUrl(origin)` — the sanctioned launch-token seam — so one navigation clears both the auth gate and the pairing gate: `/pair-accept → /?token=<launch> → /`. `authenticatedUrl` requires an absolute URL, so the route passes the request origin (honoring `x-forwarded-proto` for tunnels).
- **Mobile plugin scope.** While the adaptation is active, the right-hand details column and the desktop-oriented tool surfaces (SSH terminal, skill explorer, task board, git graph, pet, perf, usage) are hidden - keyed on the L2 semantic roots (data-dsh-plugin) so ownership stays with the declaring plugin - and activation closes the details panel through the official ctx.layout.closeDetails(). These are render suppressions: the client bundles still load (roster composition belongs to the official web app, not this plugin).
- **LAN bind toggle with a static managed block.** The settings card writes a managed block into the profile `cordis.patch.yml` pinning the webserver bind (0.0.0.0 on, 127.0.0.1 off) plus the official row's port and compression keys. Same-id patch rows REPLACE the row config wholesale, so the block must be complete; and the user patch layer on this line cannot evaluate `webStartup`-dependent `!!js` expressions reliably (they resolve before the webStartup service mounts), so the values are static. The plugin re-asserts the block at every boot — CLI flags (`--host`, `--port`) win by rewriting the block — and the card reports the live bind, the firewall summary (Windows netsh; Linux firewalld/ufw/iptables; other platforms unmanaged), and a `pendingRestart` flag when the running bind has not caught up (compared against the effective desired bind, so a flag-managed host is not flagged forever). The CLI's `--host 0.0.0.0` rejection stays intact: deliberate LAN exposure happens through this configuration layer only.
- **Review round (same day).** The follow-up hardening note ([review-driven hardening round](../bug-fix/2026-08-29-remote-control-review-fixes.md)) completes this design with the channel's inner browser credential (the proxied `/api` re-issue otherwise 401s on this cohort), states the direct-`/api` pairing gap honestly, and fixes the lan-bind/firewall hygiene defects found by review.

## Alternatives considered

- dsh-LAN's persistent shared password as the access model: rejected by product decision — the QR pairing system (one-time tokens, per-device revocation, live roster, tunnel reachability) is this plugin's differentiator; a shared secret cannot revoke one device.
- A `/lanapi` privileged proxy mirroring dsh-LAN: rejected after source inspection — this line pins privileged behavior client-side, so the ownsHost hook achieves full parity without an endpoint table to maintain across SDK upgrades.
- Writing dynamic `!!js ctx.webStartup.*` expressions into the managed bind block (dsh-LAN's shape): rejected on measured evidence — the expressions resolve before the webStartup service is mounted in the user patch layer (hot-reload passes saw `port: undefined`, cold boots refused the config), so the block materializes static values and the boot re-assert keeps flags winning.
- Shadowing the official workspace directory picker for remote devices (dsh-LAN's in-app dialog): unnecessary on this line — the picker backend is a composition choice (ui-directory-picker-native vs -browse fill ui-workspace's slot holes), with no isLoopback branch.
- Related mechanisms that survive this refactor unchanged: the fence screen's manual pair-token input ([remote fence manual pair token](../feature/2026-08-26-remote-fence-manual-pair-token.md)) and the console LAN-reachability guidance ([desktop profile and LAN guidance](../feature/2026-08-26-desktop-profile-and-lan-guidance.md)) — the LAN log line now advertises the paired official GUI instead of the deleted `/m/` surface.

## Consequences

- The remote surface can no longer drift from the official one: adaptation is additive CSS/gestures, and the only selectors that can break are the semantic suffixes (re-verified per GUI QA round).
- A paired device is a full-control credential, now including the configuration plane and the family settings bridge. The README security model states this; the four control planes remain local.
- The LAN bind change takes effect on the next `dsh web` start; the card surfaces `pendingRestart` instead of pretending a live rebind happened (live patch reload proved profile-shape dependent and cannot rebind a listening socket).
- Removed with the surface: PWA installation, the mobile Enter-to-send config, and the workspace deep-link parameter (`?workspace=`) — the official UI has no such parameter, and multi-client state mirroring makes the desktop's current workspace the shared one.

## Required verification

- `pnpm typecheck && pnpm test && pnpm build` in the package (250 tests).
- Live GUI, isolated QA profile: LAN bind toggle round (patch write → restart → `bindHost: 0.0.0.0`, `pendingRestart: false`), desktop mint → `/pair-accept?pair=` → paired phone (390x844 touch emulation) boots the official UI with the adaptation active (portrait class, injected sheet, whale present) and `__DSH_TRANSPORT__.ownsHost === true`.
