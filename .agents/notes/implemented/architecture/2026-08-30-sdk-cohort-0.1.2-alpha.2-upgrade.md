# Agent Note: SDK cohort upgrade to 0.1.2-alpha.2

Status: implemented

## Problem

The DSH runtime moved to the 0.1.2-alpha.2 preview (upstream tag `dsh-v0.1.2-alpha.2`, commit 0a53fb5), and the repository had to follow. Beyond the routine version bump, alpha.2 carries two structural changes that break the repository as built against alpha.1: `dsh-settings` removed the standalone `installSettingsSection` / `settingsNamespace` / `deepEqualJson` exports in favor of the `ctx.settings` service seam, and the announced "peer dependency optimization" trimmed most sibling peers from the published manifests, which severed type-graph edges the plugins had been consuming transitively.

## Decision

The alpha.2 cohort resolves from `registry.npmjs.org` under the `alpha` dist-tag: manifest ranges read `^0.1.2-alpha.2`, and no `overrides:` block, cohort tarball store, or preview-cohort CI step remains. The transient workaround from [[2026-08-28-preview-cohort-tarball-overrides]] / [[2026-08-29-ci-rebuilds-cohort-tarball-store]] (the `scripts/build-cohort-tarballs.mjs` store, the `file:` overrides, and the CI Restore/Materialize steps) was removed once the alpha.2 publish landed. `minimumReleaseAgeExclude` keeps the freshly-published `@deepseek-ai/*` versions (cordis 4.0.2, loader 1.0.3, include 1.0.7, cosmokit 1.8.3, schemastery 3.18.2, and the dsh-* alpha.2 line) and their registry-coupling peers.

Settings consumers (doctor, desktop-launcher, ssh, perf, pet, market, liangshen, task-board, usage, git-graph, tool-describe-image, skin-center, remote-web-ui) migrate to the official pattern: `ctx.inject(['settings'], (settingsCtx) => settingsCtx.settings.installSection(ctx, ns, schema, entry, hooks))` with the hook shape unchanged, and namespace constants become `'literal' as SettingsNamespace` so every downstream consumer keeps the branded type. The web-settings bridge passes `ns as SettingsNamespace` straight to the provider `mutate`, whose signature is otherwise unchanged.

The tool-level consequence of the peer trimming is fixed at its cause: alpha.2 manifests require `@deepseek-ai/cordis ^4.0.2` (with `cordis-plugin-loader ^1.0.3` / `cordis-plugin-include ^1.0.7`), so the repository's own declarations move to `^4.0.2`. Without that, pnpm resolves two cordis copies (4.0.1 for the repository, 4.0.2 for the cohort) and every `declare module '@deepseek-ai/cordis'` service augmentation silently stops applying. The same trimming removed `dsh-client-ui-session` from `dsh-client-ui-conversation`'s reach, so `dsh-git-graph` — whose chip props rely on the `sessionId` / `useSessions` standard-props merge that ui-session contributes — now declares that package and pulls its client types explicitly.

`SessionEvent.ignorable` is restored upstream but the repository is unaffected: the dsh-perf migration core reads the marker off its locally typed legacy jsonl rows. The remote-web-ui cohort claims re-verified for alpha.2: nothing emits `api/gate`, and the one-stream-socket wire rules are unchanged (the contract tests pass against the new cohort unmodified).

## Alternatives considered

Re-merging peers into the packaged cohort to restore the alpha.1 type-graph reach was rejected: it would fabricate packaging the official cohort deliberately dropped. Keeping the source-built tarball store was rejected once the alpha.2 publish landed — the store existed only because the registry had no cohort. Keeping cordis at 4.0.1 was rejected: the augmentation split it causes fails every package typecheck. Wrapping the settings service in a shared repository helper was rejected as a new abstraction where each package already follows the official per-plugin pattern.

## Consequences

Bundles remain dual-cohort: no alpha.2-only runtime surface is consumed, so the built plugins still load on the alpha.1 host that currently runs; switching the host itself to `dsh-v0.1.2-alpha.2` is a user-side runtime upgrade and restart. CI is simpler than the alpha.1 cohort: it no longer caches or rebuilds a store, and a frozen install resolves straight from the registry. New type-graph edges may surface for other consumers when upstream trims more peers; the fix pattern is a declared devDependency plus an explicit type-only import.

Third-party consequence: the tarball `overrides:` block was also what force-resolved every `@deepseek-ai/dsh-*` peer of external aggregate plugins. Dropping it unmasked two externals that hard-import the alpha.2-removed `@deepseek-ai/dsh-client-runtime` face — `dsh-better-sidebar@0.15.2` and `@mlgbnb/dsh-archive-manager@1.0.7` — which fail the host loader's strict import resolution and abort `dsh web` boot. They are excluded from the `dsh-web-all` aggregate (aggregate.yml rows, package.json deps, regenerated patch) until upstream ships alpha.2 builds; `@morlay/better-session` stays (it only imports `cordis` / `dsh-invariants`, both present, and its row is inactive by default; removed 2026-09-02 — see [drop-deprecated-better-session-integration](../simplification/2026-09-02-drop-deprecated-better-session-integration.md)). Re-adding them requires the rows, deps, and the `scripts/aggregate.test.mjs` mounting assertions together. The tag-pipeline mount smoke (`tests/e2e/mount.e2e.ts`) initially still asserted the better-sidebar host div and failed the v0.3.9 release's `verify-release` job; it was rewritten to anchor boot on `[data-dsh-frame]` and assert the excluded externals are absent ([e2e-mount-excluded-externals-anchor](2026-08-31-e2e-mount-excluded-externals-anchor.md)).

Follow-up (2026-08-31): upstream shipped `dsh-better-sidebar@0.18.0-alpha.0` (npm `alpha` dist-tag, peers `^0.1.2-alpha.2`, `dsh.client.inject` now naming `@deepseek-ai/dsh-client-modules`), and the aggregate re-added it at that exact pin — see [re-add-better-sidebar-alpha2](2026-08-31-readd-better-sidebar-alpha2.md). The mount smoke asserts the better-sidebar host div again; `@mlgbnb/dsh-archive-manager` (latest still 1.0.7) remains excluded.

Follow-up (2026-09-01): the cohort bumped in line to 0.1.2-alpha.3 (npm `alpha` dist-tag, published 2026-08-31) as a routine prerelease bump: manifest ranges read `^0.1.2-alpha.3`, `minimumReleaseAgeExclude` entries were reconciled to the exact alpha.3 versions, and `shared/package.json` keeps its exact-pin convention. The published delta is confined to `dsh-api-session-controller` (additive `mode: 'queue' | 'steer'` and `PendingSubmissionPlacement`, the `ISession.loadThrough` turn-jump loader, and an internal switch to `dsh-attachment`'s `admitPromptContent`) and `dsh-subagent` (image admission behind model capability, `SubagentPromptContentPart` removed in favor of `PromptContentPart`, `admitPromptContent` moved to `dsh-attachment`, error code `subagent/attachment-unsupported` renamed to `subagent/attachment-invalid`). No repository source consumes any of those symbols; every other SDK package is type-identical, SDK package metadata changed only family-internal dependency ranges, and the emitted bundles are byte-identical to the alpha.2 builds. The full gate sequence (typecheck, build, test, test:scripts, runtime-deps, aggregate, community, docs, i18n, skin-center) and the e2e mount smoke (on the alpha.2 host CLI, token-URL carried verbatim) pass without source adaptation; no new SDK feature was adopted. Runtime rollout stays user-side: the link profile resolves external bundles' peer faces from the repository top-level `node_modules`, so the shared checkout's `pnpm install` to alpha.3 must follow, not precede, the host upgrade to alpha.3.

Follow-up (2026-09-02): the cohort bumped in line to 0.1.2-alpha.4 (npm `alpha` dist-tag, family-synchronized publish 2026-09-01 15:46–16:01 UTC; all 54 consumed packages present, cordis / cosmokit / schemastery unchanged). Manifest ranges read `^0.1.2-alpha.4` (`shared/package.json` keeps its exact-pin convention), `minimumReleaseAgeExclude` entries were reconciled to the exact alpha.4 versions, and the host floor moved with the cohort: `dsh.engines.dsh >=0.1.2-alpha.4` across the 21 family packages plus the plugin scaffold, the static README badge, and the `@deepseek-ai/dsh@0.1.2-alpha.4` mount-smoke pins in CI and release. This delta is not additive-only: `dsh-session` brands session sequence numbers (`SessionSeq` / `SessionLogOffset` constructor types, `Session.events` replaced by `eventAt` / `ownEvents`, fork headers reshaped from `seedLength` to `isSeeded` plus `inheritedEventCount`), `dsh-api-session-controller` formalizes a v0-compatible browser wire header, `dsh-client-ui-slots` adds the keyed-hooks compartment, the subagent continuation path was reworked, and the family-wide internal `invariant` helper was removed. Published-artifact comparison across all consumed packages plus a bail-free workspace typecheck surfaced exactly one repository consumer: `dsh-pet` test fixture, which now brands fixture sequence numbers through the exported `SessionSeq()` constructor. The same change drops the deprecated `@morlay/better-session` aggregate integration (see [drop-deprecated-better-session-integration](../simplification/2026-09-02-drop-deprecated-better-session-integration.md)). The host CLI was upgraded to 0.1.2-alpha.4 before the repository install (homebrew-prefix npm global); the runtime rollout stays user-side — the shared checkout `pnpm install` to alpha.4 must follow the host restart, not precede it. Full local gate sequence (typecheck, build, test, test:scripts, runtime-deps, aggregate, community, skin-center, docs, i18n) passes; the CI mount smoke re-proves the mount on the alpha.4 pin and managed-GUI acceptance follows the user-side host restart.
