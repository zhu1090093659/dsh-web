# Agent Note：SDK cohort 升级到 0.1.2-alpha.2

Status: implemented

## 问题

DSH 运行时推进到 0.1.2-alpha.2 预览版（上游 tag `dsh-v0.1.2-alpha.2`，commit 0a53fb5），仓库必须跟进。除常规版本推进外，alpha.2 带来两个结构性变化，直接破坏按 alpha.1 构建的仓库：`dsh-settings` 移除了独立的 `installSettingsSection` / `settingsNamespace` / `deepEqualJson` 导出，改为 `ctx.settings` 服务缝；同时发布说明中的「peer dependency 优化」裁掉了清单里绝大多数兄弟 peer，斩断了插件一直在传递消费的类型图边。

## 决策

alpha.2 cohort 从 `registry.npmjs.org` 的 `alpha` dist-tag 解析：清单 range 为 `^0.1.2-alpha.2`，仓库已不含任何 `overrides:` 块、cohort tarball store 或预览 cohort 的 CI 步骤。[[2026-08-28-preview-cohort-tarball-overrides]] / [[2026-08-29-ci-rebuilds-cohort-tarball-store]] 中的临时方案（`scripts/build-cohort-tarballs.mjs` 的 store、`file:` overrides、CI 的 Restore/Materialize 步骤）在 alpha.2 发布落地后移除。`minimumReleaseAgeExclude` 保留刚发布的 `@deepseek-ai/*` 版本（cordis 4.0.2、loader 1.0.3、include 1.0.7、cosmokit 1.8.3、schemastery 3.18.2 及 dsh-* alpha.2 线）及其 registry 耦合 peers。

settings 消费者（doctor、desktop-launcher、ssh、perf、pet、market、liangshen、task-board、usage、git-graph、tool-describe-image、skin-center、remote-web-ui）迁移到官方模式：`ctx.inject(['settings'], (settingsCtx) => settingsCtx.settings.installSection(ctx, ns, schema, entry, hooks))`，hook 形状不变；namespace 常量改为 `'literal' as SettingsNamespace`，下游消费的 branded 类型保持不变。web-settings 桥接直接以 `ns as SettingsNamespace` 调 provider `mutate`，其余签名未变。

peer 裁剪在工具链层面的后果从根因修复：alpha.2 清单要求 `@deepseek-ai/cordis ^4.0.2`（连带 `cordis-plugin-loader ^1.0.3` / `cordis-plugin-include ^1.0.7`），仓库自身声明随之升到 `^4.0.2`。否则 pnpm 会解析出两份 cordis（仓库 4.0.1、cohort 4.0.2），所有 `declare module '@deepseek-ai/cordis'` 服务增强静默失效。同一裁剪也使 `dsh-client-ui-conversation` 够不到 `dsh-client-ui-session`：git-graph 的 chip props 依赖 ui-session 贡献的 `sessionId` / `useSessions` 标准 props 合并，因此显式声明该包并引入其 client 类型。

`SessionEvent.ignorable` 上游已恢复，但仓库不受影响：dsh-perf 迁移核心读取的是本地类型的 legacy jsonl 行上的标记。remote-web-ui 的 cohort 断言对 alpha.2 重新核实：依旧没有任何组件发出 `api/gate`，单流 socket 的 wire 规则未变（契约测试对新 cohort 原样通过）。

## 备选方案

为恢复 alpha.1 的类型图可达性而在打包 cohort 里重新合并 peers——拒绝：那会伪造官方 cohort 有意裁掉的打包形态。alpha.2 发布落地后仍保留源码构建的 tarball store——拒绝：该 store 只因 registry 没有 cohort 才存在。cordis 留在 4.0.1——拒绝：增强分裂会让所有包 typecheck 失败。用仓库共享 helper 包一层 settings 服务——拒绝：各包已遵循官方 per-plugin 模式，不应新增抽象。

## 后果

bundle 保持双 cohort 兼容：未消费任何 alpha.2 独有的运行时面，构建产物仍能在当前运行的 alpha.1 宿主上加载；宿主本体切到 `dsh-v0.1.2-alpha.2` 属于用户侧运行时升级与重启。CI 比 alpha.1 cohort 更简单：不再缓存或重建 store，frozen install 直接从 registry 解析。上游继续裁剪 peer 时可能暴露更多类型图边，修复模式即：声明 devDependency 并加显式 type-only import。

第三方后果：tarball `overrides:` 块此前也负责强制解析外部聚合插件的每一个 `@deepseek-ai/dsh-*` peer。撤掉它后暴露了两个硬依赖 alpha.2 已删除的 `@deepseek-ai/dsh-client-runtime` 面的外部插件——`dsh-better-sidebar@0.15.2` 与 `@mlgbnb/dsh-archive-manager@1.0.7`——它们在宿主 loader 的严格 import 解析下失败，导致 `dsh web` 启动中止。两者已从 `dsh-web-all` 聚合排除（aggregate.yml 行、package.json 依赖、重新生成的 patch），直到上游发布 alpha.2 构建；`@morlay/better-session` 保留（只 import `cordis` / `dsh-invariants`，两者都在，且其行默认 inactive；2026-09-02 已移除——见 [drop-deprecated-better-session-integration](../simplification/2026-09-02-drop-deprecated-better-session-integration.md)）。重新加入需同时补回行、依赖与 `scripts/aggregate.test.mjs` 的挂载断言。tag 发布管线的挂载冒烟（`tests/e2e/mount.e2e.ts`）起初仍断言 better-sidebar 宿主 div，并在 v0.3.9 发布的 `verify-release` job 上失败；已改写为以 `[data-dsh-frame]` 锚定启动、并断言被排除的外部插件缺席（[e2e-mount-excluded-externals-anchor](2026-08-31-e2e-mount-excluded-externals-anchor.md)）。

后续（2026-08-31）：上游发布了 `dsh-better-sidebar@0.18.0-alpha.0`（npm `alpha` dist-tag，peer 均 `^0.1.2-alpha.2`，`dsh.client.inject` 已改用 `@deepseek-ai/dsh-client-modules`），聚合已按该精确 pin 重新加入——见 [re-add-better-sidebar-alpha2](2026-08-31-readd-better-sidebar-alpha2.md)。挂载冒烟改回断言 better-sidebar 宿主 div；`@mlgbnb/dsh-archive-manager`（latest 仍为 1.0.7）保持排除。

后续（2026-09-01）：cohort 沿 0.1.2-alpha 线常规升到 0.1.2-alpha.3（npm `alpha` dist-tag，2026-08-31 发布）：manifest 范围改为 `^0.1.2-alpha.3`，`minimumReleaseAgeExclude` 条目按精确 alpha.3 版本 reconcile，`shared/package.json` 保持精确 pin 约定。发布面差异只集中在两处：`dsh-api-session-controller`（新增 `mode: 'queue' | 'steer'` 与 `PendingSubmissionPlacement`、`ISession.loadThrough` 回跳加载器、内部改用 `dsh-attachment` 的 `admitPromptContent`）与 `dsh-subagent`（按模型能力准入图片、删除 `SubagentPromptContentPart` 改用 `PromptContentPart`、`admitPromptContent` 迁至 `dsh-attachment`、错误码 `subagent/attachment-unsupported` 更名为 `subagent/attachment-invalid`）。仓库源码不消费其中任何一个符号；其余 SDK 包类型逐字节一致，SDK 包元数据只有家族内部依赖范围升版，构建产物与 alpha.2 构建逐字节相同。全部门禁（typecheck、build、test、test:scripts、runtime-deps、aggregate、community、docs、i18n、skin-center）与 e2e 挂载冒烟（跑在 alpha.2 宿主 CLI 上，token URL 原样携带）均通过，无需源码适配；未采用任何新 SDK 能力。运行时上线保持用户侧操作：link profile 从仓库顶层 `node_modules` 解析外部插件的 peer 面，因此共享 checkout 的 alpha.3 `pnpm install` 必须在宿主升级到 alpha.3 之后进行，而不是之前。

后续（2026-09-02）：cohort 沿 0.1.2-alpha 线升到 0.1.2-alpha.4（npm `alpha` dist-tag，家族同步发布于 2026-09-01 15:46–16:01 UTC；仓库消费的全部 54 个包齐备，cordis / cosmokit / schemastery 不变）。manifest 范围改为 `^0.1.2-alpha.4`（`shared/package.json` 保持精确 pin 约定），`minimumReleaseAgeExclude` 条目按精确 alpha.4 版本 reconcile，宿主地板随 cohort 同移：21 个家族包加插件脚手架的 `dsh.engines.dsh >=0.1.2-alpha.4`、静态 README 徽章、CI 与 release 的 `@deepseek-ai/dsh@0.1.2-alpha.4` 挂载冒烟 pin。这次差异不再是纯增量：`dsh-session` 给会话序号加了品牌类型（`SessionSeq` / `SessionLogOffset` 构造器类型，`Session.events` 由 `eventAt` / `ownEvents` 取代，fork 头从 `seedLength` 重塑为 `isSeeded` 加 `inheritedEventCount`），`dsh-api-session-controller` 形式化了 v0 兼容的浏览器 wire 头，`dsh-client-ui-slots` 新增 keyed-hooks 舱位，subagent continuation 路径重构，家族范围的内部 `invariant` 助手被移除。对全部消费包的发布产物比对加免中止的全仓 typecheck 只找出一个仓库消费方：`dsh-pet` 测试夹具，现经导出的 `SessionSeq()` 构造器给夹具序号加品牌。同一变更移除了已弃用的 `@morlay/better-session` 聚合集成（见 [drop-deprecated-better-session-integration](../simplification/2026-09-02-drop-deprecated-better-session-integration.md)）。宿主 CLI 在仓库 install 之前升级到 0.1.2-alpha.4（homebrew prefix 的 npm 全局）；运行时上线保持用户侧——共享 checkout 的 alpha.4 `pnpm install` 必须跟随宿主重启，而不是先于它。本地全部门禁（typecheck、build、test、test:scripts、runtime-deps、aggregate、community、skin-center、docs、i18n）通过；CI 挂载冒烟在 alpha.4 pin 上复证挂载，托管 GUI 验收跟随用户侧宿主重启。
