# Agent Note：SDK cohort 0.1.5-rc.1

Status: implemented

## 问题

全家族停在 `0.1.5-alpha.2` 群体，而发布线已推进到 `0.1.5-rc.1`（全家族同步发布于 2026-09-10 03:12 UTC；仓库消费的全部 `dsh-*` 包齐备，cordis / cosmokit / schemastery 支持钉不变），且本机 host CLI 已先一步升到 rc.1。与一天前的 alpha.2 大跳不同，这是同一 `0.1.5` 线上的顺线小步，词汇断裂不在预期之内；但升级仍须在一个变更里移动全部群体面，并重新证明外部聚合插件的可挂载性——插件 SDK 决不能跑在 host 前面，而对齐 alpha.2 的 `dsh-better-sidebar` 构建保持钉住不动。

## 决策

整个仓库在 `sdk/rc1-cohort` 分支上以同一字面量移到 `0.1.5-rc.1` 群体，快进合回 `dev`：

- **依赖区间**：全部 `^0.1.5-alpha.2` 区间变为 `^0.1.5-rc.1`；桌面运行时的宿主 exact 钉变为 `@deepseek-ai/dsh@0.1.5-rc.1`。支持钉维持原值（`@deepseek-ai/cordis` `^4.0.2`、cosmokit `1.8.3`、schemastery `3.18.2`、plugin-include `1.0.7`、plugin-loader `1.0.3`）。
- **宿主下限，一份契约，四个面**：20 个家族包加 `scripts/plugin-template` 的 `dsh.engines.dsh >=0.1.5-rc.1`、`README.md`/`README.en.md` 的静态 `DSH >=0.1.5--rc.1` 徽章、`ci.yml`/`release.yml` 的 `npm install -g @deepseek-ai/dsh@0.1.5-rc.1` 挂载钉、`docs/publish-prep.md` 的 smoke 语句。提及 alpha.2 的历史性叙述保留为历史。
- **发布冷却策略**：两份 `minimumReleaseAgeExclude` 列表随迁到 rc.1 exact 版本（rc.1 今日发布，豁免行是承重墙）。桌面运行时的 `overrides:` 块（23 条不带 `@` 前缀的裸钉）必须同迁：第一遍安装只移了带 `@` 的豁免行，overrides 仍钉 alpha.2，产出了混合群体的桌面 lockfile（430 行 alpha.2），直到该块重新钉版本并重建 lockfile 才归一。两份 lockfile 现均在 rc.1 纯解析（各 2187 行家族引用，`lockfileVersion 9.0` 不变）。
- **上游打包缺陷在 rc.1 延续**：`dsh-client-store@0.1.5-rc.1` 仍运行时 import `immer`（及 zustand 面），`dsh-client-ui-primitives@0.1.5-rc.1` 仍 import `anser`、`clsx`、`katex`、`shiki`、`@shikijs/langs` 与 mdast/micromark 工具集，而两个已发布 manifest 依旧不声明 `dependencies`（2026-09-10 在 rc.1 tarball 中核实）。`packageExtensions` 补丁从 alpha.2 改钉到 rc.1、仅限这两个版本；不改任何已安装文件。
- **Shell 模块表**：rc.1 `dsh-web-frontend` 冻结表在既有种子旁新增 `@deepseek-ai/dsh-client-ui-dockkit` 行。`shared/web-platform.ts` 与镜像契约（`shared/tests/web-platform.spec.ts`）一同加行；仓库尚无客户端 bundle 导入该模块，产物不变。
- **注入面 parity**：rc.1 `dsh-web-app` 组装名册（读本机 host 的 `cordis.patch.yml`）仍携带 `scripts/inject-contract.test.mjs` 批准集的全部 12 个名字——只有增量；`dsh-client-ui-slots`/`dsh-client-store` 仍是文档化的 platform-table 行。
- **外部聚合**：`dsh-better-sidebar` 迁移时随 `0.19.0-alpha.1`——其 peer 声明 `^0.1.5-alpha.2`，按同一 `[0,1,5]` 元组的预发布序 rc.1 可满足，mount smoke 证明该配对成立；同日 [0.19.0 正式版重钉](2026-08-31-readd-better-sidebar-alpha2.md)后，聚合包移到 peer 直接声明 `^0.1.5-rc.1` 的版本。`@mlgbnb/dsh-archive-manager` 维持排除（无证据表明其构建不再 import 已移除的 `dsh-client-runtime` 面）。

## 已考虑的替代方案

- **在 rc.1 删除 `packageExtensions` 块**：否决——上游打包缺陷是对着 rc.1 tarball 重新核实的，不随版本号一并假设消失。
- **升级 `dsh-better-sidebar`**：迁移时否决——当时上游没有对齐 rc.1 的发布（最新即钉住的 0.19.0-alpha.1，对齐 rc.1 的正式版同日稍后发布），且其声明的 peer 区间已接受 rc.1。
- **桌面 `overrides:` 钉留在 alpha.2**：否决——overrides 存在的理由就是桌面载荷必须精确镜像单一群体；那里的混合 lockfile 正是群体纪律要防的模块实例割裂隐患。

## 测试

`pnpm typecheck`（22 包）、`pnpm build`、`pnpm test`、`pnpm test:scripts`、`pnpm runtime-deps:check`、`pnpm aggregate:check`、`pnpm skin-center:check`、`pnpm community:check`、`pnpm docs:check`、`pnpm i18n:check` 在 rc.1 全部通过。`pnpm install --frozen-lockfile --ignore-scripts` 证明两份 lockfile 可解析（根与桌面）。rc.1 shell 模块表读自已安装的 `dsh-web-frontend` dist bundle；workspace 注入并集对照已安装 host 的组装名册。`scripts/e2e-mount.sh` 把新打的聚合包装进 rc.1 CLI 下的 scratch profile：宿主帧启动、better-sidebar 挂载、被排除的 archive-manager 缺席、无头渲染 lane 绿。`test:scripts` 最初暴露了一个预先存在的基线缺陷——f28e2f62 orca-link 皮肤修复未再生已提交的 `market/dist`——本次变更以无 shell-dist 模式再生派生产物完成修复（`tryon/` 不动），同一失败已在基线提交上复现为证。

## 后果

声明的下限现在处处指名 rc.1，插件管理器的安装检查会把用户引向真正当期的 host 版本。两个 `packageExtensions` 块仍是常设债，直到 npm 以声明运行时依赖的方式重新发布 client-store/client-ui-primitives。桌面载荷的教训已记录，供今后每次群体升级参照：群体迁移必须同时扫两种钉形态——带 `@version` 的豁免行与裸 `overrides:` 值——否则桌面树会静默跑在割裂群体上；`scripts/rollout-verify.test.mjs` 现在还把 `desktop/runtime/host/package.json` 的 `@deepseek-ai/dsh` exact 种子钉在 scaffold floor 群体上，GH Actions 桌面打包不会再落后于任何一次升级。

桌面种子收口（同日）：预装 profile 载荷自 2026-09-03 起一直落后 npm（种子 0.3.14，而聚合已发布到 0.3.19——五个发布，全靠手工推进）。种子现已移到 0.3.19，release-age 豁免行同步前移（model-capabilities 与 preset-center 自 0.3.19 起加入聚合）；`desktop-release.yml` 现在在两个 job 里于打包前按 tag 播种 profile 载荷——用 registry 查询把种子解析到 tag 版本再 staging，npm 发布通道关闭时回退到已提交种子并告警——安装包从此不会带上比自己发布更旧的插件。0.3.19 插件集是 0.1.2-rc.1 时代的源码（其声明 floor `>=0.1.2-rc.1` 由 rc.1 host 满足）；完全 rc.1 对齐的配套要等本群体构建的下一次家族发布。

上线已于 2026-09-10 执行：合并后的 `dev` checkout 在 rc.1 上重装并重建，受管 `web` profile（链接本仓库）对照 3080 端口上运行中的 rc.1 host 复验，期间未重启服务。前后抓屏完全一致——宿主帧、任务看板、git-graph 与宠物均挂载，orca-link 皮肤正常渲染，两条预先存在的基线现象（反复出现的 `remote.session` inject pageerror 与 git-graph auto-isolation 降级警告）在两侧表现相同，故非本次群体迁移的回归。`DSH_WEB_PORT=3080 bash scripts/rollout-verify.sh --skip-profiles` 端到端通过（host 0.1.5-rc.1 满足 `>=0.1.5-rc.1`、根 lockfile 纯 rc.1、未认证根路径答 401）；不跳过 profile 的完整运行对 `trading-web` 报一项 FAIL——DSH Trading 桌面载荷内嵌套的 `@dshtrading/indicators` cosmokit 拷贝，该载荷拥有自己的群体（预先存在、不属本仓库范围，检查器自身的指引也把它路由到 dsh-trading 的 refresh 脚本）。用户会话内的真实 LLM 工具调用未执行；它防范的模块实例割裂崩溃类已被 cohort 检查器结构性排除——`web` profile 的全部家族行均为宿主 symlink。
