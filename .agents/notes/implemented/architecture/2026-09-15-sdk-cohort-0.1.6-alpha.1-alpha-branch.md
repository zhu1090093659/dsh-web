# Agent Note: SDK cohort 0.1.6-alpha.1 on a permanent alpha branch

Status: implemented

## Problem

The official family published an experimental `0.1.6-alpha.1` on 2026-09-15T03:23Z while the repository's release line stayed on `0.1.5-rc.1` (`next` is `0.1.5-rc.2`). The alpha line is a large change record: it removes `agent/session-start` in favour of an async serial `agent/created`, renames the PTC faces (package, context service key and types), adds the public `workspace.unarchiveSession` verb, ships a native archived-sessions settings page, adds a native SSH remote-workspace provider, and adds a runtime dependency to a published SDK package.

The family could not simply move `dev` onto a prerelease: the stable rc environment, the global `dsh` CLI and the user's live `web` profile must keep running the cohort they were accepted against. The upgrade therefore needed a permanent branch with its own worktree and its own DSH home, so the alpha cohort can be adapted and rebuilt without touching the rc environment, and so the adaptation work survives across sessions instead of living in a throwaway branch.

## Decision

`alpha` is a permanent branch carrying the experimental cohort, and it is maintained in an isolated environment:

- **Branch and worktree**: `alpha` is created from `origin/dev` and checked out at a dedicated worktree; every dependency mutation, build, generated artifact and gate runs there. The shared `dev` checkout, its `node_modules` and the global `@deepseek-ai/dsh` install are never moved to the alpha cohort.
- **Cohort**: every consumed `@deepseek-ai/dsh-*` range, the plugin scaffold, the root README badge, the CI and release mount-smoke pins, the desktop runtime pin and `docs/publish-prep.md` move to `0.1.6-alpha.1` together. `@deepseek-ai/cordis` (4.0.2), `cosmokit` (1.8.3) and `schemastery` (3.18.2) stay on their independent support pins, and the declared host floor becomes `dsh.engines.dsh >=0.1.6-alpha.1`.
- **Isolated runtime**: the alpha host CLI is installed into a separate home (`~/.dsh-alpha`) and the alpha profile lives under that home, so the alpha host's settings, sessions and plugin tree never touch `~/.dsh`. `dsh --profile alpha-web --dump-config` composes the alpha cohort with the family rows; booting a live alpha instance is left to the operator because it needs the credential store shared from the stable home.
- **Release-age policy**: `minimumReleaseAgeExclude` entries move to the exact alpha versions in both the repository workspace and the desktop runtime workspace; stale rc-only exclusions are dropped rather than carried.

## Compatibility and native-first outcomes

The published alpha tarballs were compared against rc.1 for every consumed package (declarations, exports maps, manifest metadata, service keys, slot keys and the shell's frozen module table). The whole repository typechecks after four source adaptations, and the client half needed none.

- **`agent/session-start` removed**: `dsh-tool-describe-image` now awaits its resting verdict inside the async serial `agent/created` listener, so the tool mask is applied before the first request's toolset is assembled instead of racing it, and the listener never rejects. `dsh-liangshen`'s preset merges its two stale, mis-shaped registrations into one correctly-shaped `agent/created` listener.
- **PTC service rename**: `ctx.get('codeRuntime')` becomes `ctx.get('ptcRuntime')` in the `dsh-liangshen` preset. Reading the old key would have silently disabled PTC staging for every session.
- **`@deepseek-ai/dsh-tools@0.1.6-alpha.1` imports a new required peer**: it statically imports `@deepseek-ai/dsh-sandbox`, which it did not do at rc.1. The root `devDependencies` carry it as a host face, because the workspace disables peer auto-install.
- **`@deepseek-ai/dsh-client-ui-primitives@0.1.6-alpha.1` imports `diff`** while its published manifest still declares no runtime dependencies at all. A `packageExtensions` entry restores it, alongside the existing zustand/immer, anser/clsx/katex/shiki and micromark/mdast entries.
- **Deprecated session readers**: `snapshotEvents`, `eventAt` and `ownEvents` are marked `@deprecated` ("new calls are prohibited") but still ship. The family's existing uses are tolerated, so they are recorded rather than migrated in this change.

## Overlap inventory and decisions

The cohort adds official features that overlap plugin surface. Each overlap was inventoried against the shipped native behaviour and decided; the native path is the base wherever it covers the capability.

| Official feature | Our implementation | Native now provides | Decision |
| --- | --- | --- | --- |
| `workspace.unarchiveSession` + the Archived sessions settings page | `dsh-session-archive`: its own first-level `settings.section` (id `dsh-session-archive`, order 152), plus an unarchive that reached into the registry's private `requireState`/`setState` handles because no public verb existed | A public idempotent unarchive verb, and an official `archived-sessions` section at order 25 | **Supersede, do not sit beside**: the private-state workaround is deleted in favour of the public verb, and the plugin now seats the official `archived-sessions` id and order instead of a parallel entry; `dsh-web-all` retires the official row through the aggregate's new `retire:` manifest section. The inventory, batch archive/unarchive, cascade physical delete and auto-maintenance policies are kept, because native ships none of them (the official page lists and restores only, and offers no deletion) |
| Native SSH remote-workspace provider (`dsh-ssh`, `dsh-fs-ssh`, `dsh-sandbox-ssh`, all first published at this cohort) | `dsh-ssh` | An SSH filesystem and POSIX sandbox provider that makes the standard file/command tools operate on a remote workspace | **Recorded exception, complementary**: native changes *where* the standard tools run; ours is a management surface (host CRUD, connection pool, SFTP browsing, tunnels, cluster execution) plus `ssh_*` agent tools. Mounting native neither replaces nor regresses ours. Adopting the provider as a workspace mode is follow-up feature work, not compatibility repair |
| Archived-session restore in the settings shell | `dsh-session-archive`'s own settings section | A dedicated restore page | **Kept**: the two sections have different scopes (restore list versus management console); no capability is duplicated by deleting either |
| Official plugin inventory settings page | `dsh-plugin-manager` | The `settings.plugins.tab` host section | **Already a native extension**: the manager registers a tab into the official section rather than mounting a parallel page |
| Sidebar terminal, file/document preview and their slot keys | External `dsh-better-sidebar` (aggregate dependency, not ours) | `dsh-client-ui-sidebar-terminal`, `sidebar-files`, `sidebar-documentpreview` | **Recorded**: no family code registers these slots. `conversation.input.permission` is single-occupancy and the sidebar tab seats are keyed by tab id, so any future family panel must use distinct keys |

## One archived-sessions entry, not two

The settings shell renders one nav row per `settings.section` registration, sorted by `order`, with no `id` de-duplication, and a section can only expose extension points that its own owner declared through `children`. The official `archived-sessions` page declares none and is mounted by the constant `dsh-web-app` roster, so a plugin cannot merge into it. Sitting beside it therefore always produces two near-identical first-level entries.

The consolidation is therefore a takeover plus a composition retirement:

- `dsh-session-archive` seats the official `archived-sessions` id at the official order 25 (the section already opened on the archived view), so the single entry keeps the position users know, and its `arch.nav` copy reads exactly like the official one.
- The aggregate gains a `retire:` manifest section that renders a bare `disabled: true` override naming a FOREIGN row id verbatim (never namespaced). `scripts/aggregate.mjs` validates that a retired id is a non-empty string, is not one of the aggregate's own rows, and is not listed twice.
- `aggregate.yml` retires `ui-settings-unarchive-sessions`. Verified on the composed alpha profile: the row reads `- id: ui-settings-unarchive-sessions` / `disabled: true` under `# == @deepseek-ai/dsh-web-app, patched by @linxin666/dsh-web-all`, so only the family entry mounts.

A standalone install beside the official page still shows two entries; the package READMEs tell the user to disable one row. That limit is inherent to the slot contract and is recorded rather than papered over.
## Alpha-only: no bundled better-sidebar

On 2026-09-17 the alpha branch dropped the aggregate's external right-panel plugin. `dsh-better-sidebar@0.19.1` declares every consumed `@deepseek-ai/dsh-*` peer as `^0.1.5-rc.1`, and a prerelease range only matches its own `[major,minor,patch]` tuple, so none of those peers is satisfied by the `0.1.6-alpha.1` cohort this branch builds against. The plugin is now absent from `aggregate.yml` (no `rows` entry), from the aggregate's own `package.json` dependencies, from `pnpm-workspace.yaml`'s release-age exclusion list and from the mount-smoke lane, whose assertions are inverted to prove the absence; `cordis.patch.yml` was regenerated without its row. The isolated alpha home was re-installed afterwards so its linked profile no longer resolves the package, and the right panel is therefore simply absent on this branch.

The stable `dev` line keeps it bundled at 0.19.1, so this removal is a standing divergence: every `alpha` rebase onto `dev` re-applies it. The plugin's DOM attribute stays in the family's surface-detection selector lists, because a user can still install it on demand (`dsh plugin --profile <name> add dsh-better-sidebar@latest`) as the READMEs now say.

## Alternatives considered

Keeping the alpha cohort on `dev` was rejected: it would have moved the user's live environment and the global CLI onto a prerelease, and it would have made the adaptation unreviewable against the accepted rc state. A throwaway upgrade branch was rejected for the same reason a permanent one is chosen here — the alpha line will keep moving, and the environment, not the branch, is what makes the isolation real. Removing `dsh-session-archive` wholesale in favour of the native page was rejected: native has no deletion, no batch operations and no retention policy, so the removal would have been a capability regression.

## Consequences

`dev` and the stable environment stay on the accepted rc cohort; the alpha line advances independently and can be rebuilt from the worktree at any time. Two cohort surfaces are now coupled: the repository workspace and the desktop runtime workspace each carry their own release-age exclusion list and overrides block, and both must move together. The `dsh` family's prerelease floors mean the alpha branch's packages are installable only on an alpha host.

## Testing

`pnpm typecheck`, `sync-shared:check`, `skin-center:check`, `community:check`, `libs:check`, `build`, `test`, `test:scripts`, `test:desktop`, `runtime-deps:check`, `aggregate:check`, `docs:check`, `i18n:check` and `market:check` pass in the alpha worktree. `dsh --profile alpha-web --dump-config` composes the alpha host with the family rows from the isolated home and shows `ui-settings-unarchive-sessions` disabled under `dsh-web-app, patched by @linxin666/dsh-web-all`, so exactly one archive settings entry mounts. Two tests pin the consolidation: `tests/section-identity.spec.ts` in dsh-session-archive asserts the seated id and order, and `scripts/aggregate.test.mjs` asserts every `retire:` entry renders a verbatim (non-namespaced) `disabled: true` override. Live GUI acceptance against a running alpha instance is not covered by this change and remains open.
