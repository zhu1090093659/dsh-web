# Agent Note: 常驻 alpha 分支上的 SDK 0.1.6-alpha.1 cohort

Status: implemented

## Problem

官方在 2026-09-15T03:23Z 发布了实验性的 `0.1.6-alpha.1`，而本仓库的发布线仍停在 `0.1.5-rc.1`（`next` 为 `0.1.5-rc.2`）。alpha 线是一份很大的变更记录：移除 `agent/session-start` 改为异步串行的 `agent/created`，重命名 PTC 各类面（包名、上下文服务键与类型），新增公开的 `workspace.unarchiveSession` 动词，内置归档会话设置页，新增原生 SSH 远端工作区提供者，并给某个已发布 SDK 包新增了运行时依赖。

本家族不能简单把 `dev` 移到预发布版：rc 稳定环境、全局 `dsh` CLI 以及用户正在使用的 `web` profile 必须继续停留在已被验收的 cohort 上。因此这次升级需要一条常驻分支、一个独立工作树与一个独立 DSH home，让 alpha cohort 可以在不影响 rc 环境的前提下适配与重建，也让适配成果跨会话保留，而不是停留在一次性的临时分支里。

## Decision

`alpha` 是承载实验性 cohort 的常驻分支，并在隔离环境中维护：

- **分支与工作树**：`alpha` 从 `origin/dev` 创建，检出到专用工作树；所有依赖变更、构建、生成物与门禁都在该工作树内运行。共享的 `dev` 检出、它的 `node_modules` 以及全局 `@deepseek-ai/dsh` 安装都不会被移到 alpha cohort。
- **Cohort**：所有被消费的 `@deepseek-ai/dsh-*` 范围、插件脚手架、根 README 徽章、CI 与 release 的 mount smoke 固定版本、桌面运行时固定版本以及 `docs/publish-prep.md` 一并移动到 `0.1.6-alpha.1`。`@deepseek-ai/cordis`（4.0.2）、`cosmokit`（1.8.3）、`schemastery`（3.18.2）保持各自的独立支撑固定版本，声明的主机下限变为 `dsh.engines.dsh >=0.1.6-alpha.1`。
- **隔离运行时**：alpha 主机 CLI 安装到独立 home（`~/.dsh-alpha`），alpha profile 也位于该 home 下，因此 alpha 主机的设置、会话与插件树不会触碰 `~/.dsh`。`dsh --profile alpha-web --dump-config` 能把 alpha cohort 与家族插件行组合起来；真实启动 alpha 实例交给操作者，因为它需要从稳定 home 共享凭据存储。
- **发布时限策略**：仓库工作区与桌面运行时工作区两处的 `minimumReleaseAgeExclude` 都移动到精确的 alpha 版本；只适用于 rc 的过期排除项被删除而非保留。

## 兼容与原生优先结论

对每个被消费的包，都把已发布的 alpha tarball 与 rc.1 做了对比（声明文件、exports 映射、清单元数据、服务键、slot 键以及宿主 shell 的冻结模块表）。四处源码适配之后，整仓 typecheck 通过，浏览器半区无需修改。

- **`agent/session-start` 被移除**：`dsh-tool-describe-image` 现在在异步串行的 `agent/created` 监听器内等待 resting 判定，使工具遮蔽在首个请求的工具集组装之前生效，而不是与之竞争；监听器也不会 reject。`dsh-liangshen` 的 preset 把两处过时且参数形状错误的注册合并为一个形状正确的 `agent/created` 监听器。
- **PTC 服务重命名**：`dsh-liangshen` preset 中的 `ctx.get('codeRuntime')` 改为 `ctx.get('ptcRuntime')`。继续读旧键会静默地让所有会话失去 PTC staging。
- **`@deepseek-ai/dsh-tools@0.1.6-alpha.1` 新增必需 peer**：它在模块顶层静态导入 `@deepseek-ai/dsh-sandbox`，rc.1 时并不如此。由于工作区关闭了 peer 自动安装，由根 `devDependencies` 以主机面的形式承载该包。
- **`@deepseek-ai/dsh-client-ui-primitives@0.1.6-alpha.1` 导入 `diff`**，而它已发布的清单仍然完全不声明运行时依赖。通过 `packageExtensions` 补齐，与既有的 zustand/immer、anser/clsx/katex/shiki、micromark/mdast 条目并列。
- **已弃用的会话读取接口**：`snapshotEvents`、`eventAt`、`ownEvents` 被标记为 `@deprecated`（"new calls are prohibited"）但仍然可用。家族中既有的调用被容忍，因此本次只做记录而不迁移。

## 重叠清单与决策

该 cohort 新增的官方特性与插件面存在重叠。每一项都对照已交付的原生行为做了盘点并给出决策；凡原生已覆盖的能力，一律以原生路径为底座。

| 官方特性 | 我们的实现 | 原生现在提供 | 决策 |
| --- | --- | --- | --- |
| `workspace.unarchiveSession` 与归档会话设置页 | `dsh-session-archive` 自己的一级 `settings.section`（id `dsh-session-archive`、order 152），以及当时因缺少公开动词而伸手进 registry 私有 `requireState`/`setState` 句柄的取消归档 | 公开、幂等的取消归档动词，以及 order 25 的官方 `archived-sessions` section | **接管而非并列**：删除私有状态变通实现改用公开动词；插件同时改用官方 `archived-sessions` 的 id 与 order，不再另起平行入口，`dsh-web-all` 通过聚合新增的 `retire:` 清单段关闭官方那一行。保留插件的清点、批量归档/取消归档、级联物理删除与自动维护策略，因为原生并不提供这些（官方页面只列出与恢复，且不提供删除） |
| 原生 SSH 远端工作区提供者（`dsh-ssh`、`dsh-fs-ssh`、`dsh-sandbox-ssh`，均在本 cohort 首次发布） | `dsh-ssh` | SSH 文件系统与 POSIX 沙箱提供者，使标准文件/命令工具作用于远端工作区 | **已记录例外，属互补**：原生改变标准工具"在哪里运行"，我们提供的是管理面（主机 CRUD、连接池、SFTP 浏览、端口转发、集群执行）与 `ssh_*` 智能体工具。挂载原生既不取代也不回退我们的能力。把该提供者作为工作区模式接入属于后续功能开发，而非兼容性修复 |
| 设置 shell 中的归档会话恢复 | `dsh-session-archive` 自己的设置区 | 专用的恢复页面 | **保留**：两者作用域不同（恢复列表 vs 管理控制台），删掉任何一方都不会造成能力重复 |
| 官方插件清单设置页 | `dsh-plugin-manager` | `settings.plugins.tab` 宿主区段 | **本就是原生扩展**：管理器是向官方区段注册标签页，而非另起平行页面 |
| 侧边栏终端、文件/文档预览及其 slot 键 | 外部 `dsh-better-sidebar`（聚合依赖，非我们所有） | `dsh-client-ui-sidebar-terminal`、`sidebar-files`、`sidebar-documentpreview` | **已记录**：家族代码未注册这些 slot。`conversation.input.permission` 是单占用 seat，侧边栏标签 seat 按标签 id 作键，因此未来的家族面板必须使用不同键名 |

## 归档只保留一条一级入口

设置外壳对每条 `settings.section` 注册各渲染一个导航项、按 `order` 排序、**不按 `id` 去重**；而一个 section 只能暴露其属主在注册时用 `children` 声明的扩展点。官方 `archived-sessions` 页面没有声明任何子槽位，且由 `dsh-web-app` 常量名册挂载，插件无法并入其中。因此与它并列必然产生两个近似的一级入口。

合并因此采用「接管 + 组合退役」两步：

- `dsh-session-archive` 注册官方的 `archived-sessions` id 与官方 order 25（该页面本就打开在已归档视图），单条入口保持用户熟悉的位置，`arch.nav` 文案与官方一致。
- 聚合包新增 `retire:` 清单段，渲染一条原样写出**外部**行 id 的裸 `disabled: true` 覆盖（绝不做命名空间化）。`scripts/aggregate.mjs` 校验：被退役的 id 必须是非空字符串、不得是本聚合自己的行、不得重复列出。
- `aggregate.yml` 退役 `ui-settings-unarchive-sessions`。已在 alpha profile 的真实组合上验证：该行输出为 `- id: ui-settings-unarchive-sessions` / `disabled: true`，位于 `# == @deepseek-ai/dsh-web-app, patched by @linxin666/dsh-web-all` 之下，因此只有家族入口会挂载。

单独安装并与官方页面并存时仍会出现两个入口，包 README 已提示用户在插件里停用其中之一。这是槽位契约本身的限制，记录在案而非掩盖。
## 仅 alpha：不内置 better-sidebar

2026-09-17，alpha 分支移除了聚合包的外部右侧面板插件。`dsh-better-sidebar@0.19.1` 把全部被消费的 `@deepseek-ai/dsh-*` peer 声明为 `^0.1.5-rc.1`，而带预发布标识的区间只匹配同 `[major,minor,patch]` 元，因此本分支构建所依据的 `0.1.6-alpha.1` cohort 一个都满足不了。该插件现已从 `aggregate.yml`（不再有 `rows` 条目）、聚合包自身的 `package.json` 依赖、`pnpm-workspace.yaml` 的发布时限排除清单以及挂载冒烟 lane（其断言改为证明「不挂载」）中消失；`cordis.patch.yml` 已按不含该行的清单重新生成。随后重装了隔离的 alpha home，使其链接 profile 不再解析该包；因此本分支上右侧面板直接缺席。

稳定线 `dev` 仍以 0.19.1 内置，所以这次移除是一处常驻分歧：alpha 每次 rebase 到 `dev` 都要重新应用。该插件的 DOM 属性仍保留在家族的表层探测选择器清单里，因为用户依旧可以按需安装（`dsh plugin --profile <name> add dsh-better-sidebar@latest`），README 现在正是这样写的。

## Alternatives considered

让 alpha cohort 留在 `dev` 上被否决：那会把用户的实时环境与全局 CLI 一起推到预发布版，也让适配无法对照已验收的 rc 状态评审。一次性升级分支同样被否决，理由与选择常驻分支一致——alpha 线会持续前进，真正带来隔离的是环境而不是分支。整体删除 `dsh-session-archive` 改用官方页面被否决：原生没有删除、没有批量操作、没有保留策略，删除会成为能力回退。

## Consequences

`dev` 与稳定环境继续停留在已验收的 rc cohort；alpha 线独立推进，并可随时从工作树重建。现在有两处 cohort 面相互绑定：仓库工作区与桌面运行时工作区各自持有发布时限排除列表与 overrides 块，二者必须同步移动。家族在预发布版上的下限意味着 alpha 分支的包只能在 alpha 宿主上安装。

## Testing

在 alpha 工作树中 `pnpm typecheck`、`sync-shared:check`、`skin-center:check`、`community:check`、`libs:check`、`build`、`test`、`test:scripts`、`test:desktop`、`runtime-deps:check`、`aggregate:check`、`docs:check`、`i18n:check`、`market:check` 均通过。`dsh --profile alpha-web --dump-config` 能从隔离 home 组合出 alpha 宿主与家族插件行，并显示 `ui-settings-unarchive-sessions` 在 `dsh-web-app, patched by @linxin666/dsh-web-all` 之下为 disabled，因此只挂载一条归档设置入口。两处测试锁定该合并：dsh-session-archive 的 `tests/section-identity.spec.ts` 断言注册的 id 与 order，`scripts/aggregate.test.mjs` 断言每个 `retire:` 条目都渲染出原样（未命名空间化）的 `disabled: true` 覆盖。针对运行中 alpha 实例的实时 GUI 验收不在本次变更范围内，仍是未完成项。
