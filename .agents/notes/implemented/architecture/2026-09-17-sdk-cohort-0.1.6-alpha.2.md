# Agent Note: SDK cohort 0.1.6-alpha.2 on the permanent alpha branch

Status: implemented

## Problem

The official family published `0.1.6-alpha.2` on 2026-09-17 while the alpha branch stood on the `0.1.6-alpha.1` cohort it was created for (see [SDK cohort 0.1.6-alpha.1 on a permanent alpha branch](2026-09-15-sdk-cohort-0.1.6-alpha.1-alpha-branch.md)). The release is a large change record, and its headline breaks the client session model this family's plugins were written against: the Client Session Controller drops its global `current` selection (`SessionListState.current`, `currentAddress`) and its `open()` / `openSubagent()` / `clear()` navigation verbs, and gains source-labelled references (`retain`, `using`, `retainInfo`, `SessionReference`, `SessionTarget`). View selection moves to the workspace UI, which owns the main-area reference and publishes it through `SessionSummary.retainedBy.mainView`; `ctx.uiWorkspace.openSession(target)` is the new navigation action.

The rest of the record adds the official Plugins sidebar page and settings section, end-of-turn changed-file cards with sidebar diff review, sidebar Office/browser/subagent/plan previews, a directory-hierarchy workspace list, the composer-footer context usage, runtime plugin dependency resolution with runtime unloading, the `dsh <profile>` CLI shorthand, and a tokenized `dsh web` root URL behind a browser-auth fence.

The alpha environment had to keep running its own cohort: the `alpha` branch and its isolated `~/.dsh-alpha` home are the only place this cohort is adapted, and the stable `dev` line and the global CLI stay on the accepted rc cohort.

## Decision

The family moves to `0.1.6-alpha.2` on the same permanent alpha branch and in the same isolated environment:

- **Cohort**: every consumed `@deepseek-ai/dsh-*` range, the plugin scaffold, the root README badges, the CI and release mount-smoke pins, the desktop runtime pin and `docs/publish-prep.md` move to `0.1.6-alpha.2` together, and the declared host floor becomes `dsh.engines.dsh >=0.1.6-alpha.2`. `@deepseek-ai/cordis` (4.0.2), `cosmokit` (1.8.3) and `schemastery` (3.18.2) stay on their independent support pins. The release-age exclusion lists in both the repository workspace and the desktop runtime workspace move to the exact alpha.2 versions; `@deepseek-ai/dsh-client-ui-workspace` joins the repository list because the family now consumes it directly.
- **Isolated runtime**: the alpha host CLI in `~/.dsh-alpha/host` is upgraded to `0.1.6-alpha.2`. The profile tree's `@deepseek-ai/*` copies are symlinks into that host, so they follow it and the host and the plugins keep one module instance each. The alpha profile is still driven through `dsh --profile alpha-web`.
- **One main-view derivation for every consumer**: `shared/client/main-session.ts` exports `mainViewSessionId(byId)`, the catalog-level reading of `retainedBy.mainView`, and `scripts/sync-shared.mjs` copies it into the seven packages that need it. Navigation goes through `ctx.uiWorkspace.openSession`.

## Multi-instance Client Sessions

Ten call sites across eight packages read the removed selection or navigation face. `list.current` and `sessions.open()` are gone, so a plugin that kept reading them would not fail loudly: the field is simply `undefined` and the feature silently stops working. Two of those sites (`dsh-git-graph` auto-isolation and `dsh-session-archive`) type-checked against local structural faces and never appeared in the compiler's error list, so the consumer inventory was built by searching for the removed names rather than by trusting `tsc`.

- `dsh-doctor` resolves the send-to-Harness target from the main-view marker.
- `dsh-pet` derives the bubble-leading session from it and jumps sessions through `ctx.uiWorkspace.openSession`.
- `dsh-liangshen`'s lever reads the main-view row for its blank/preset facts.
- `dsh-session-id` marks the main-view row instead of the removed selection.
- `dsh-task-board`'s framework-free controller port changed from a list snapshot to `{ current(), open(), subscribe() }`, and the wiring derives `current()` from the marker.
- `dsh-plugin-manager` navigates its repair session through the workspace UI.
- `dsh-git-graph` resolves the current session's workspace for automatic isolation and navigates new worktree sessions through the workspace UI.
- `dsh-session-archive` takes the main-view id as a resolver instead of reading the catalog shape.

The marker is used only where a view-level answer is correct. The upstream decision is explicit that source counts describe ownership, not visibility or authority, so the helper documents that it is not a business fallback.

## Native-first outcomes

- **Official Plugins page (sidebar panel + settings section + read-only Plugin list tab)**: the page is a new package at alpha.2 (`dsh-client-ui-plugin-manager`, absent from the alpha.1 registry). It installs any pnpm spec — registry, path, tarball, git — with an inspect dialog, build-script approval and cancellation, switches bundles and rows live, uninstalls, and dispatches plugin configuration through `plugins.item` / `plugins.bundle.config` / `plugins.row.config`. `dsh-plugin-manager` keeps only what native does not own: registry update checks with DSH-runtime compatibility gating, the conflict ledger with undo and repair handoff, the boot-failure ring, the safe-mode banner, and a read-only inventory that points at the official page. Its `pluginManager` cordis service keeps the full face because the Workshop installs through it and `dsh-doctor` quarantines a failing plugin with it.
- **Family plugin cards**: alpha.2 removed the keyed `settings.plugin.item` seat `ui-settings-plugins` declared and replaced it with the plugin manager page's `plugins.item` (official plugins), `plugins.bundle.config` and `plugins.row.config` (external bundles). `shared/client/settings/plugin-card-seat.ts` falls back to `plugins.bundle.config` keyed by the contributing package's own bundle name, so a standalone family install reaches its card again; the family list seat `web-ui.plugin.item` is unchanged.
- **Composer-footer context usage**: `dsh-usage` is a different capability (per-provider balance, coding-plan quota windows, the retained token ledger and the Token Bank), not a context meter. No overlap; kept.
- **Sidebar terminal / files / document preview / browser / subagent chat / plan cards / changed-file diff**: no family row registers any of those seats, and the official implementations engage on their own. The family's only adoption is `dsh-market`, whose Workshop-site, card-name, repository and skin-preview links now route through `sidebarRight.openTab('browser', ...)` when the shell claims that tab type, with the previous new-tab behaviour as the fallback.
- **pi-ai model input types**: the alpha.2 Models page edits a pi-ai entry's `input` modality itself (`ModelInputTypes`, shared by the DeepSeek and pi-ai catalog editors, plus `ModelListEditor`). `dsh-model-capabilities` drops its duplicate image-input editor and keeps the reasoning-effort editor and the provider disable/enable archive as a thin extension; a panel assertion pins that a save preserves the native `input` claim.
- **Runtime plugin dependency resolution and runtime unloading**: the alpha aggregate declares no external npm plugin at all (`dsh-better-sidebar` was already dropped on this branch), so no external hard-binding is unmasked. The unload path itself was audited: every long-lived host resource the family owns is fiber-scoped (`ctx.webServer.register` disposers, `UsageService.stop`, `janitor.stop`, `engine.dispose`, the remote-web-ui relay/tunnel/posture disposers), the client-side DOM hub disconnects its observer with its last subscriber, and `mountOnce` unmarks on disposal so a reload re-applies. `dsh-git-graph`'s route disposer — the runtime-unload path of the `/git` routes, the SSE heartbeat and the poll guard — is now pinned by a test.
- **Startup diagnostics**: alpha.2 classifies startup failures and renders `startupDiagnostic` / `activationDiagnostic` lines (`<id> (<name>): <detail>`, ` Package: <name>`, `startup failed: N required plugin(s) did not activate`). `dsh-doctor`'s boot attribution matched the two pre-alpha.2 shapes only, so a failed family row could no longer be attributed; it now matches the alpha.2 shapes first and keeps the legacy ones.
- **Creator-mode Cordis tools, subagent continuation capacity, user-terminal permissions, Inbox recovery, permission-mode approval**: no family implementation of those surfaces; nothing to remove.
- **Default model list (V4 Flash and V4 Flash Vision Exp removed)**: `dsh-usage` keeps billing historical usage at those ids on purpose; the default list is the composer model picker's.

## Upstream packaging defect

`@deepseek-ai/dsh-client-ui-primitives@0.1.6-alpha.2` imports `simple-icons` from its emitted `lib/index.js` while the published manifest still declares no runtime dependencies at all (the official source resolves it from the monorepo root). The workspace's `packageExtensions` entry restores it at the exact version the official source pins (16.31.0), beside the existing `diff`, shiki and micromark restorations; no installed file is patched. `micromark-util-types` is imported by type declarations only and needs no runtime restoration.

## The mount smoke carries the tokenized URL

The alpha.2 host prints the root URL with its launch token and fences `/` behind browser auth, so a parse that stops at the port hands the browser lane the 401 page. `scripts/e2e-mount.sh` already captures the printed URL up to the next token boundary and passes it verbatim to the Playwright lane; the pin and the parse both name the alpha.2 cohort after this change.

## Alternatives considered

Reading "the current session" from `sessions.retainInfo(id)` on every catalog row was rejected: it allocates a per-id observer for the Client root's lifetime and would leak one per session, where the list snapshot already carries the same counts. Keeping each package's own reading of the removed field was rejected: it type-checks against a structural face while returning `undefined` at runtime, which is exactly how two of the ten call sites escaped the compiler. Re-implementing a plugin-side "current session" store was rejected as recreating the coupling the upstream decision deliberately removed; a plugin may ask which session the main view owns, but it may not become the owner. Keeping the family plugin manager tab's install box, uninstall and enable/disable switches was rejected once the official page shipped them with live switching: the tab now keeps only what native does not provide — update checks, the conflict ledger, the failure ring and the safe-mode banner.

## The first pass missed one renamed slot

The alpha.2 release note announces the client-session work as "related APIs and slots changed", so the pass that adapted the session model also compared slot keys. That comparison only walked the workspace/sidebar packages and concluded "additive only; nothing removed or renamed". A complete diff over every declared `SlotMap` key of all 53 `dsh-client-*` packages at both tags shows 63 alpha.1 keys against 71 alpha.2 keys: nine added, one removed (`settings.plugin.item`), and two packages that do not exist at alpha.1 (`dsh-client-ui-plugin-manager`, `dsh-client-ui-sidebar-browser`). The removal silently disabled the family cards' official-seat fallback, which is why the diff is now recorded here and the seat migrated in the same pass. Slot keys are compared from the built packages of both cohorts, not from memory or from a subset of packages.

## Testing

In the alpha worktree: `pnpm typecheck`, `sync-shared:check`, `skin-center:check`, `community:check`, `libs:check`, `build`, `test`, `test:scripts`, `test:desktop`, `runtime-deps:check`, `aggregate:check`, `emoji:check`, `test:standards`, `docs:check`, `i18n:check` and `market:check` pass, and `pnpm install --frozen-lockfile --ignore-scripts` resolves the lockfile. The adapted behaviours are pinned by tests: `shared/tests/main-session.spec.ts` covers the derivation, `dsh-task-board`'s controller specs cover the new navigation port, `dsh-liangshen` and `dsh-doctor` cover the marker reading, and `dsh-git-graph`'s worktree-session spec covers navigation through the workspace UI. The follow-up pass adds: `dsh-plugin-manager`'s tab spec (read-only inventory, no enable/disable switch, host-recorded conflicts with undo, failure repair, safe mode, update gating), `dsh-model-capabilities`' panel assertion that the native `input` claim survives a save, `dsh-doctor`'s attribution specs for both alpha.2 shapes and both legacy shapes, `dsh-git-graph`'s route-disposer spec, and `dsh-market`'s external-link opener specs.

## Consequences

`dev` and the stable environment stay on the accepted rc cohort. The alpha line's cohort surfaces stay coupled: the repository workspace, the desktop runtime workspace and the isolated alpha home must move together. Every plugin that reads the main view now depends on the workspace UI being mounted; that is true of any profile mounting `dsh-web-app`, and the packages declare `uiWorkspace` in both their cordis `inject` list and `dsh.client.inject`.
