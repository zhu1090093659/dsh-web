# Agent Note: SDK cohort 0.1.6-alpha.2 on the permanent alpha branch

Status: implemented

## Problem

官方家族在 2026-09-17 发布了 `0.1.6-alpha.2`，而 alpha 分支仍停在它当初为之创建的 `0.1.6-alpha.1` cohort（见 [SDK cohort 0.1.6-alpha.1 on a permanent alpha branch](2026-09-15-sdk-cohort-0.1.6-alpha.1-alpha-branch.md)）。这是一份很大的变更记录，其核心变化直接打破了家族插件所依赖的客户端会话模型：Client Session Controller 去掉了全局 `current` 选择（`SessionListState.current`、`currentAddress`）以及 `open()` / `openSubagent()` / `clear()` 导航动词，改为带来源标签的引用（`retain`、`using`、`retainInfo`、`SessionReference`、`SessionTarget`）。视图选择移到工作区 UI：它持有主区域引用并通过 `SessionSummary.retainedBy.mainView` 发布，新的导航动作是 `ctx.uiWorkspace.openSession(target)`。

记录中的其余部分新增了官方插件侧边栏页与设置分区、回合结束的改动文件卡片与侧边栏逐文件 diff 审阅、侧边栏 Office/浏览器/子代理/计划预览、按目录层级分组的会话列表、输入框底部的上下文用量、插件依赖的运行时解析与运行时卸载、`dsh <profile>` CLI 简写，以及带 token、位于浏览器鉴权围栏之后的 `dsh web` 根 URL。

alpha 环境必须继续运行它自己的 cohort：`alpha` 分支与隔离的 `~/.dsh-alpha` home 是这个 cohort 唯一的适配场所，稳定线 `dev` 与全局 CLI 继续停留在已验收的 rc cohort。

## Decision

家族在同一个永久 alpha 分支、同一个隔离环境中整体迁移到 `0.1.6-alpha.2`：

- **Cohort**：所有被消费的 `@deepseek-ai/dsh-*` 区间、插件脚手架、根 README 徽章、CI 与发布的挂载冒烟 pin、桌面运行时 pin 以及 `docs/publish-prep.md` 一起迁移到 `0.1.6-alpha.2`，声明的最低宿主版本变为 `dsh.engines.dsh >=0.1.6-alpha.2`。`@deepseek-ai/cordis`（4.0.2）、`cosmokit`（1.8.3）、`schemastery`（3.18.2）保持各自独立的支持性 pin。仓库工作区与桌面运行时工作区两份 release-age 排除清单都移到 alpha.2 的确切版本；`@deepseek-ai/dsh-client-ui-workspace` 因为家族改为直接消费它而加入仓库清单。
- **隔离运行时**：`~/.dsh-alpha/host` 中的 alpha 主机 CLI 升级到 `0.1.6-alpha.2`。profile 树里的 `@deepseek-ai/*` 是指向该主机的符号链接，因此随之移动，主机与插件各自保持单一模块实例。alpha profile 仍通过 `dsh --profile alpha-web` 驱动。
- **所有消费者共用一个主视图推导**：`shared/client/main-session.ts` 导出 `mainViewSessionId(byId)`，即对 `retainedBy.mainView` 的目录级读取；`scripts/sync-shared.mjs` 把它复制进需要它的七个包。导航统一走 `ctx.uiWorkspace.openSession`。

## Multi-instance Client Sessions

八个包中共有十处调用点读取了被移除的选择或导航面。`list.current` 与 `sessions.open()` 已消失，继续读取它们的插件不会显式失败：字段只是 `undefined`，功能静默失效。其中两处（`dsh-git-graph` 的自动隔离与 `dsh-session-archive`）是针对本地结构类型通过类型检查的，从未出现在编译器的错误列表里，因此消费者清单是通过搜索被移除的名字建立的，而不是依赖 `tsc`。

- `dsh-doctor` 从主视图标记解析「发送到 Harness」的目标会话。
- `dsh-pet` 由它推导气泡栈首位的会话，并通过 `ctx.uiWorkspace.openSession` 跳转会话。
- `dsh-liangshen` 的拨杆从主视图行读取 blank/preset 事实。
- `dsh-session-id` 标记主视图行，取代被移除的选择。
- `dsh-task-board` 与框架无关的 controller 端口从列表快照改为 `{ current(), open(), subscribe() }`，由装配处从标记推导 `current()`。
- `dsh-plugin-manager` 通过工作区 UI 导航到它的修复会话。
- `dsh-git-graph` 为自动隔离解析当前会话的工作区，并通过工作区 UI 导航新建 worktree 的会话。
- `dsh-session-archive` 改为接收主视图 id 解析器，而不再读取目录形状。

标记只在视图级答案正确的地方使用。上游决策明确指出：来源计数描述的是所有权，不是可见性或权限，因此该 helper 也写明它不是业务兜底。

## Native-first outcomes

- **官方插件页（侧边栏面板 + 设置分区 + 只读插件列表 tab）**：该页在 alpha.2 是一个全新包（`dsh-client-ui-plugin-manager`，alpha.1 的 registry 里不存在）。它能安装任何 pnpm spec——registry、路径、tarball、git——并带检查对话框、构建脚本审批与取消；实时开关 bundle 与行；卸载；并通过 `plugins.item` / `plugins.bundle.config` / `plugins.row.config` 分派插件配置。`dsh-plugin-manager` 只保留原生不负责的部分：更新检查与 DSH 运行时兼容门禁、可撤销并转交修复的冲突对账、启动失败环、安全模式横幅，以及指向官方页的只读清单。它的 `pluginManager` cordis 服务保留完整 face，因为创意工坊通过它安装、`dsh-doctor` 通过它隔离启动失败的插件。
- **家族插件卡片**：alpha.2 移除了 `ui-settings-plugins` 声明的 keyed 槽 `settings.plugin.item`，改为插件管理页的 `plugins.item`（官方插件）、`plugins.bundle.config` 与 `plugins.row.config`（外部 bundle）。`shared/client/settings/plugin-card-seat.ts` 的 fallback 改为按贡献包自身的 bundle 包名注册进 `plugins.bundle.config`，因此单独安装家族插件时卡片重新可达；家族 list 槽 `web-ui.plugin.item` 不变。
- **输入框底部的上下文用量**：`dsh-usage` 是不同能力（各 provider 余额、编程套餐配额窗口、留存 token 台账与 Token 银行），不是上下文计量器。无重叠，保留。
- **侧边栏终端 / 文件 / 文档预览 / 浏览器 / 子代理会话 / 计划卡片 / 改动文件 diff**：家族没有任何行注册这些座位，官方实现自行生效。家族唯一的接入是 `dsh-market`：它的工坊站、卡片名称、仓库与皮肤预览链接现在会在宿主声明该标签类型时走 `sidebarRight.openTab('browser', ...)`，并保留原先的新开标签页作为兜底。
- **pi-ai 模型输入类型**：alpha.2 的 Models 页自己编辑 pi-ai 条目的 `input` 模态（`ModelInputTypes`，由 DeepSeek 与 pi-ai 两个目录编辑器共用，另有 `ModelListEditor`）。`dsh-model-capabilities` 删掉重复的图片输入编辑器，把推理档位编辑与 provider 禁用/归档保留为薄扩展；面板断言钉住「保存不改写原生 `input` 声明」。
- **插件依赖的运行时解析与运行时卸载**：alpha 聚合包不声明任何外部 npm 插件（`dsh-better-sidebar` 已在本分支移除），因此不存在被新解析模式暴露的外部硬绑定。卸载路径本身也已审计：家族持有的每个长生命周期宿主资源都绑定在 fiber 上（`ctx.webServer.register` 的 disposer、`UsageService.stop`、`janitor.stop`、`engine.dispose`、remote-web-ui 的 relay/tunnel/posture disposer），客户端 DOM hub 在最后一个订阅者离开时断开 observer，`mountOnce` 在销毁时解除标记以便重新加载。`dsh-git-graph` 的路由 disposer——`/git` 路由、SSE 心跳与 poll guard 的运行时卸载路径——现在有测试钉住。
- **启动诊断**：alpha.2 会分类启动失败并渲染 `startupDiagnostic` / `activationDiagnostic` 行（`<id> (<name>): <detail>`、` Package: <name>`、`startup failed: N required plugin(s) did not activate`）。`dsh-doctor` 的启动归因此前只匹配 alpha.2 之前的两种形状，启动失败的家族行因此无法再被归因；现在优先匹配 alpha.2 形状，并保留旧形状。
- **创造模式的 Cordis 工具、子代理续接容量、用户终端权限、Inbox 恢复、权限模式审批**：家族没有实现这些面，无需移除。
- **默认模型列表（移除 V4 Flash 与 V4 Flash Vision Exp）**：`dsh-usage` 有意继续按这两个 id 结算历史用量；默认列表是输入框模型选择器的事。

## Upstream packaging defect

`@deepseek-ai/dsh-client-ui-primitives@0.1.6-alpha.2` 在产物 `lib/index.js` 中 import `simple-icons`，而已发布 manifest 仍然完全不声明运行时依赖（官方源码从 monorepo 根解析它）。工作区的 `packageExtensions` 按官方源码 pin 的确切版本（16.31.0）恢复它，与既有的 `diff`、shiki、micromark 恢复项并列；不修补任何已安装文件。`micromark-util-types` 只被类型声明引用，无需运行时恢复。

## The mount smoke carries the tokenized URL

alpha.2 主机会打印带启动 token 的根 URL，并把 `/` 挡在浏览器鉴权之后，因此只解析到端口的写法会把 401 页面交给浏览器 lane。`scripts/e2e-mount.sh` 已经把打印出的 URL 截取到下一个 token 边界并原样传给 Playwright lane；本次改动后 pin 与解析都指向 alpha.2 cohort。

## Alternatives considered

改用 `sessions.retainInfo(id)` 逐行读取「当前会话」被否决：它会为 Client root 的整个生命周期分配一个 per-id observer，等于每个会话都泄漏一个，而列表快照本就携带同一份计数。让每个包各自继续读取被移除的字段被否决：它能通过结构类型检查，但运行时返回 `undefined`——两处调用点正是这样逃过编译器的。在插件侧重建「当前会话」存储被否决，因为那等于重新制造上游决策刻意移除的耦合；插件可以询问主视图持有哪个会话，但不能成为持有者。在官方页以实时开关提供安装/卸载/启停之后，继续保留家族插件管理 tab 的安装框、卸载与启停开关被否决：该 tab 现在只保留原生没有的部分——更新检查、冲突对账、启动失败环与安全模式横幅。

## 第一遍漏掉了一个改名槽位

alpha.2 的 release note 自己写明「相关 API 与 slot 有变化」，因此适配会话模型的那一遍也做了槽位键比较。但那次比较只走了 workspace/sidebar 相关包，结论是「纯新增，没有删除或改名」。对两个 tag 下全部 53 个 `dsh-client-*` 包的 `SlotMap` 声明键做完整比较后：alpha.1 63 个键、alpha.2 71 个键，新增 9 个、移除 1 个（`settings.plugin.item`），另有 2 个包在 alpha.1 根本不存在（`dsh-client-ui-plugin-manager`、`dsh-client-ui-sidebar-browser`）。那次移除让家族卡片的官方 fallback 席位静默失效，因此这里记录完整 diff，并在同一遍里迁移了席位。槽位键一律从两个 cohort 的已构建包中比较，不凭记忆、也不取包子集。

## Testing

在 alpha 工作树中：`pnpm typecheck`、`sync-shared:check`、`skin-center:check`、`community:check`、`libs:check`、`build`、`test`、`test:scripts`、`test:desktop`、`runtime-deps:check`、`aggregate:check`、`emoji:check`、`test:standards`、`docs:check`、`i18n:check`、`market:check` 全部通过，`pnpm install --frozen-lockfile --ignore-scripts` 可解析该 lockfile。被适配的行为都有测试钉住：`shared/tests/main-session.spec.ts` 覆盖推导，`dsh-task-board` 的 controller 规格覆盖新导航端口，`dsh-liangshen` 与 `dsh-doctor` 覆盖标记读取，`dsh-git-graph` 的 worktree-session 规格覆盖经工作区 UI 的导航。后续这一遍新增：`dsh-plugin-manager` 的 tab 规格（只读清单、无启停开关、host 记录的冲突与撤销、失败修复、安全模式、更新门禁），`dsh-model-capabilities` 面板断言「保存后原生 `input` 声明不变」，`dsh-doctor` 对两种 alpha.2 形状与两种旧形状的归因规格，`dsh-git-graph` 的路由 disposer 规格，以及 `dsh-market` 的外链打开器规格。

## Consequences

`dev` 与稳定环境继续停留在已验收的 rc cohort。alpha 线的 cohort 相关面保持联动：仓库工作区、桌面运行时工作区与隔离的 alpha home 必须一起移动。每个读取主视图的插件现在都依赖工作区 UI 已挂载；任何挂载 `dsh-web-app` 的 profile 都满足这一点，相关包在 cordis `inject` 列表与 `dsh.client.inject` 中都声明了 `uiWorkspace`。
