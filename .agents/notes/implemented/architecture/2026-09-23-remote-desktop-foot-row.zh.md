# Agent Note: 远程插件适配宽栏桌面底栏

Status: implemented

扩展 [远程控制复用官方界面](2026-08-29-remote-control-reuses-official-ui.md)：本插件的 shell 适配不再只限竖屏——宽栏桌面底栏由同一套语义后缀 CSS 层负责布局。

## Problem

官方侧栏底栏是两行堆叠：`sidebar.footer.action`（更新与远程触发器）在上，`sidebar.settings`（横跨整列的「设置」触发器）在下。于是在桌面宽栏里，「设置」触发器独占一整行、右半边全是空白，而本属同一簇的两个触发器却另占一行。用户要求这三个控件共用一行。

## Decision

1. `remote.module.css` 把宽栏底栏排成一个可换行的行，并以未折叠框架为作用域（`[data-dsh-frame]:not([data-sidebar-collapsed])`）。设置座位开启底部那一行（`order: 3`、`flex: 1 1 auto`），家族自己的底栏触发器以固有宽度收尾（`flex: 0 0 auto`、`order: 4`），于是「设置」触发器与动作对共用一行，「设置」触发器收窄到留给它的宽度。
2. 其余任何脚部子节点——用量速览卡、其它插件的块——在该行之上各占一整行（`flex: 1 1 100%`），因此共享行无需知道有哪些插件会追加子节点也保持稳定。
3. **动作座位不带盒子（issue #1710）。** 该座位是**共享**容器，而不是本插件自己的图标行：自 0.1.6/0.1.7 起，官方外壳把所有注册到 `sidebar.footer.action` 的条目收进同一个 `footerActions` div，其槽位宿主是 `display: contents`。因此给该座位加盒子会把第三方注册的内容一并放大——一个 339px 的额度栈把座位变成 417px 高的窄柱，把**设置**触发器（本插件并不拥有的外壳元素）挤成 102px 宽并在该柱内纵向居中（`y534 = 351 + (417-50)/2`），整块 footer 高达 515px 压住会话列表。现在座位是 `display: contents`，其占据者回归脚部自身的换行布局：非家族触发器的注册方各占一整行（`flex: 1 1 100%`、`order: 1`），家族触发器（`[data-dsh-part='entry']`、本插件自己的 `entryRow`）留在底行。两者取 `3`/`4` 而非 `1`/`2`，正是为了给外来行留出位于共享行之上的位置。
4. 折叠框架的栏轨保持官方原有的堆叠脚部：这些规则在 `[data-sidebar-collapsed]` 下一律不生效——栏轨按设计把圆形图标堆叠，56px 的列也放不下共享行。
5. **栏轨座位本身也改为纵排（issue #1678）。** 把栏轨完全交给官方外壳是错的：官方在栏轨下同样把 `sidebar.footer.action` 渲染成**居中的横向条**，于是两个 36px 圆形让该座位宽达 78px（图标列只有 35px），外侧圆形被推到 `x=-11` 与 `x=31`，而栏轨其它行都在 `x=10`。以折叠框架为作用域、并用本插件自己的 `data-rail='rail'` 占据者为锚点（`[class*='footerActions']:has([data-rail='rail'])`）的规则把该座位变成居中纵排、间距 4px，每个占据者因此保持 36px 的栏轨列。宽栏永不匹配该规则；若官方外壳自己就纵排脚部，该规则是等值 no-op。由于栏轨规则锚定座位自身的盒子，它是上面「去盒」决定唯一不触及的地方：在栏轨里官方给了该座位自己的盒子，它保持为盒子。

## Alternatives considered

- 用绝对定位把触发器叠到设置行上。否决：设置触发器仍是整行宽（而宽度正是被投诉的点），且位置依赖设置座位恰为脚部最后一个子节点。
- 把底部动作节点搬进设置行。否决：该节点的位置归槽渲染器所有；在 React reconciliation 之下重新挂载 DOM 正是用量速览卡通过自持 React 根来规避的坑。
- 放到用量插件里做（它的卡片本来就在脚部）。按归属否决：触发器属于本包，而且该布局在未安装用量插件时也必须成立。
- 不做栏轨作用域、无条件共享一行。否决：官方栏轨是 56px 的列，共享行会溢出并裁掉两个圆形图标。
- **用 `:has()` 给座位盒子加前置条件，而不是去掉盒子（issue #1710）。** 报告者更保守的备选是保留盒子并加一道前置条件，例如仅当座位里只有本插件的图标行时才应用同行布局（`:has(> [data-slot='sidebar.footer.action'] > :not([class*='entryRow']))`）。否决：这恰恰在出问题的配置下放弃了设计——只要第三方注册进来，「设置与触发器对同行」就会无声失效，而且该布局会依赖本插件并不拥有的元素的哈希类名。去掉盒子让该意图在任何注册组合下都成立，并把座位排布交还给脚部——那本来就是它该在的地方。
- **放弃同行意图，把整个脚部交回官方纵排。** 按原始诉求否决：这一层存在的理由就是「设置」触发器否则会独占一整行、右半空置。
- **给设置列写死宽度，让座位挤不动它。** 否决：这只是把一个硬编码数字换成另一个，且会破坏栏轨与窄列。

## Consequences

- 桌面宽栏下「设置」触发器不再独占一行，脚部动作占用者（远程触发器）与之并列；栏轨不受影响。
- 共享底行在 `sidebar.footer.action` 中出现任意第三方注册时仍然成立：陌生注册方在它之上各占一整行，「设置」触发器保持宽度而不会被挤成窄柱。本插件的规则不再依赖拥有该容器。
- 布局依赖官方后缀类 `footArea` / `settingsArea` / `footerActions`、框架上的 `data-sidebar-collapsed` 标记，以及家族的 `data-dsh-part='entry'` / `entryRow` 标记——与竖屏层相同的存活契约，每轮官方 GUI 升级都要重新视觉 QA。
- 任何向脚部追加块的插件都自动获得一整行；想让自己的块加入共享行的插件需要接受同样的 order/basis 契约。
- 栏轨下该座位把占据者纵向堆叠在图标列内，不再横向溢出。

## Testing

- `packages/dsh-remote-web-ui/tests/foot-row-css.spec.ts`：宽栏行的方向与换行、设置座位的伸展与 order、动作座位不带盒子（`display: contents`，且不含 `flex: none` / `align-items`）、其他脚部子节点的整行规则、非家族座位注册方的整行规则、家族触发器的固有宽度与底行 order、每条宽栏规则的折叠框架作用域，以及存在栏轨占据者时该座位的纵排方向。
- 真机：宽栏下「设置」触发器与动作对同处一行，设置触发器实测宽 182px（原 260px），用量卡在其上一行；栏轨保持 `flex-direction: column` 且动作图标仍堆叠。
- 尚欠：座位里存在第三方高条目（issue #1710 报告的配置）时宽栏脚部的真机测量。CSS 契约已由上述 spec 固定，但本次改动未产出该组合的截图或 computed 几何证据。
