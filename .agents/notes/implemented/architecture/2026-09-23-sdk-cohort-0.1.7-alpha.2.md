# Agent Note: SDK cohort 0.1.7-alpha.2

Status: implemented

## Problem

The integration line declared `0.1.7-alpha.1` while the machine's installed host — and the `dsh web` process serving this GUI — had already moved to `0.1.7-alpha.2` (published 2026-09-22, 162 commits and 300 files after alpha.1; the permanent alpha branch's own alpha.1 adaptation is recorded in [SDK cohort 0.1.7-alpha.1 on the permanent alpha branch](2026-09-22-sdk-cohort-0.1.7-alpha.1.md)). The repository's own `node_modules` resolved the older family, so every local gate validated the plugin cohort against a runtime the host no longer served. The compatibility scan filed as `docs/archive/sdk-compat-scan-0.1.7-alpha.2-2026-09-23.md` found the divergence concentrated in the UI surface:

- **The shell stopped publishing most of its custom properties inline.** The retired shell-only token contract held 278 `--dsw-*` names; alpha.2's shell bundle publishes 70 non-static names because the definitions moved into `@deepseek-ai/dsh-client-ui-theme`, whose `lib/client.js` now carries 290. The equivalent official surface is the union of the two, 293 names, and no contract token disappeared.
- **The first scan pass measured the delta against the wrong authority.** Comparing alpha.2 with the retired 278-name shell contract suggested five alpha.2 additions. Re-measuring alpha.1 and alpha.2 from their own published tarballs under the union rule gives 291 → 293: only `--dsw-alias-code-diff-added` and `--dsw-alias-code-diff-deleted` are genuinely new, and the other 13 names are pre-existing coverage gaps of the shell-only scan.
- **The class-name contract skins depend on is unchanged.** alpha.2 CSS Modules still hash as `_<local>_<hash>_<line>`, which is what the skin patch probes match on; the scan found zero source-level hard breakage across 1170 hand-written files.

Leaving the skew in place would have shipped a fallback-derivation universe authored against 278 names, stale mount-smoke pins, a stale desktop host pin, and an `engines.dsh` floor below the host the plugins run on.

## Decision

The whole cohort moves to `0.1.7-alpha.2` in one change, in an isolated worktree (`sdk/0.1.7-alpha.2`, based on `dev`) so the shared checkout and the running GUI are untouched until integration:

- **One family, one release.** Every consumed `@deepseek-ai/dsh*` specifier (258 across 25 manifests), the declared floor `dsh.engines.dsh >=0.1.7-alpha.2` (22 package manifests), the root `pnpm-workspace.yaml` exclusion ledger, the host payload pin in `desktop/runtime/host/package.json` plus its regenerated lock, the CI and release mount-smoke pins, `docs/publish-prep.md`, and the cohort-version source literals in `shared/web-platform.ts`, `shared/tests/web-platform.spec.ts` and `tests/e2e/mount.e2e.ts` move together. No partial bump is possible: `scripts/rollout-verify.test.mjs` pins the desktop host to the declared floor exactly and requires the root lock to resolve the family at that floor.
- **The independent support pins move with the same vendor release.** `@deepseek-ai/cordis` 4.0.3 → 4.0.4 and `@deepseek-ai/schemastery` 3.18.3 → 3.18.4 in the repository devDependencies; the root and host exclusion ledgers gain cordis 4.0.4, cosmokit 1.8.5, schemastery 3.18.4, cordis-plugin-include 1.0.9 and cordis-plugin-loader 1.0.5; the host `overrides:` block pins them.
- **The token contract is regenerated from both official surfaces.** `scripts/official-tokens-snapshot.mjs` reads `@deepseek-ai/dsh-client-ui-theme`'s `lib/` and `@deepseek-ai/dsh-web-frontend`'s `dist/assets/` and writes `contracts/official-tokens-v1.json` together with `src/core/css-safety/official-tokens.generated.ts`. `@deepseek-ai/dsh-web-frontend` becomes a root devDependency so the second source is reproducible rather than machine-local. **`contractVersion` stays 1**: the change is additive coverage with zero removals, so no consumer needs a migration branch, and the JSON and the generated registry ship as one pair (a test asserts they are equal).
- **The `--dsw-static-` palette stays excluded and the never-derived roles stay excluded.** A skin must not re-tint the static ramp, and state, shadow, mask, button, font, easing, duration and transition roles stay out of fallback derivation regardless of how many names the contract now carries — `--dsw-alias-state-idle-primary` and `--dsw-alias-label-error` are contract members that derivation deliberately skips.

## The official token surface

| Measure | alpha.1 | alpha.2 |
| --- | --- | --- |
| Shell bundle (`dsh-web-frontend` dist assets), non-static | 68 | 70 |
| Theme package (`dsh-client-ui-theme` lib) | 288 | 290 |
| Union (the contract universe) | 291 | 293 |
| Retired shell-only contract | 278 | — |

The 15 names the retired contract never covered are now contract members; 13 of them date from alpha.1 (`--dsw-alias-bg-document-preview`, `--dsw-alias-bg-layer-4`, `--dsw-alias-label-document-preview`, `--dsw-alias-label-error`, `--dsw-alias-link`, `--dsw-alias-state-idle-primary`, `--dsw-corner-shape`, five `--dsw-elevation-*`, `--dsw-menu-backdrop-filter`) and 2 are new in alpha.2. Fallback derivation is unchanged in shape: it still only emits anchors a skin left undefined, and `--dsw-alias-label-error` was measured as defined by none of the 42 shipped skins before it entered the contract, so the guard was extended for it first.

## Alternatives considered

**Stay on `0.1.7-alpha.1`.** Rejected: the host already serves alpha.2, and `scripts/rollout-verify.test.mjs` couples the declared floor to the desktop host pin and to the root lock resolution, so the repository cannot both declare the old cohort and run on the new one without the gate becoming a lie.

**Bump the plugin manifests only and leave the desktop host pin and lock.** Rejected for the same coupling plus the isolation rule: a partial cohort bump leaves the host runtime resolving alpha.1 while plugins declare alpha.2, which is exactly the skew this change removes.

**Regenerate the contract from the shell bundle only.** Rejected: it would rebuild the contract around ~70 names, delete derivable anchors from every skin, and entrench the packaging accident that moved definitions into the theme package.

**Hand-add just the two new tokens to the 278-name contract.** Rejected: it leaves 13 real gaps, keeps a `source` field that names only one of the two surfaces, and leaves no reproducible generator.

**Bump `contractVersion` to 2 for the surface change.** Rejected: no token was removed, so no consumer branch is needed, and the version exists to signal a breaking shape change rather than a wider list.

**Rebuild the whole `market/shell` + `market/dist` site in the worktree.** Rejected as unnecessary: `scripts/market-build` never enables `deriveFallbacks`, so no `market/dist` byte can depend on the contract change, and `pnpm market:check` re-emits the entire site with the rebuilt Skin Center `lib/` and compares it against the committed artifacts. The literal rebuild stays available if that check ever disagrees.

## Consequences

- `pnpm install` at the new cohort needed the installed tree removed first. pnpm verifies the *installed* `node_modules/.pnpm/lock.yaml` against the minimum-release-age policy, so a stale tree keeps failing `[ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION]` even when the root lockfile is already forward-dated and `minimumReleaseAge` is unset.
- The archive report's first-pass numbers were corrected in place (2 rather than 5 new tokens, 13 rather than 10 pre-existing gaps) and it now carries a follow-up section stating that this change supersedes its "not implemented" framing. The report is a one-off record in `docs/archive/`, not the authority for current behavior.
- Four packages commit `lib/`: the Skin Center `lib/` and `scripts/lib-artifact-fingerprints.json` are rebuilt and re-recorded here because the guard and registry changed; `packages/dsh-market/lib/index.js` is rebuilt only because its dependency comments changed.
- Residual, deliberately out of scope: twelve usage-only `--dsw-*` names that no official surface defines stay outside the contract (documented as a coverage gap rather than imported into it); the skin probe residue found by the scan (198 occurrences probing historically removed class names, 15 probing names alpha.2 genuinely removed, 6 probing renamed names) is not repaired here; `desktop/runtime/profile-web` still pins `@linxin666/dsh-web-all` 0.3.19 against this repository's 0.3.24.
- The running GUI's `lib/` output is live on the next page load, but anything that reaches a bundle row or `cordis.patch.yml` needs the operator to restart the DSH service; this change is verified in the worktree and in the shared checkout with that restart still pending.
