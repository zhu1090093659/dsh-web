# Agent Note: SDK cohort 0.1.7-alpha.2

Status: implemented

## Problem

集成线声明的是 `0.1.7-alpha.1`，但本机安装的宿主——以及正在提供这个 GUI 的 `dsh web` 进程——已经前进到 `0.1.7-alpha.2`（2026-09-22 发布，相对 alpha.1 有 162 个提交、300 个文件；永久 alpha 分支自身对 alpha.1 的适配记录在 [SDK cohort 0.1.7-alpha.1 on the permanent alpha branch](2026-09-22-sdk-cohort-0.1.7-alpha.1.md)）。仓库自身的 `node_modules` 解析到旧家族，于是所有本地门禁都在拿插件 cohort 去对照宿主已经不再提供的运行时。归档在 `docs/archive/sdk-compat-scan-0.1.7-alpha.2-2026-09-23.md` 的兼容性扫描显示差异集中在 UI 面：

- **官方壳不再内联发布大部分自定义属性。** 已退役的「仅壳」token 契约收录 278 个 `--dsw-*` 名字；alpha.2 的壳 bundle 只发布 70 个非 static 名字，因为定义搬进了 `@deepseek-ai/dsh-client-ui-theme`，其 `lib/client.js` 现在带 290 个。等效的官方面是两者的并集 293 个，且没有任何契约内 token 消失。
- **扫描第一轮量错了权威源。** 拿 alpha.2 对比退役的 278 名字壳契约会得出「alpha.2 新增 5 个」；按并集口径从 alpha.1、alpha.2 各自的已发布 tarball 重新测量得到 291 → 293：只有 `--dsw-alias-code-diff-added` 与 `--dsw-alias-code-diff-deleted` 是真正新增，另外 13 个名字是「仅壳」扫描一直漏收的既有缺口。
- **皮肤依赖的类名契约没有变。** alpha.2 的 CSS Modules 仍然哈希为 `_<local>_<hash>_<line>`，正是皮肤 patch 探针所匹配的形态；扫描在 1170 个手写文件里没有发现任何源码级硬性破坏。

放任这处错位，就等于发布一套按 278 个名字编写的 fallback 派生宇宙，外加过期的 mount-smoke 固定值、过期的桌面宿主固定值和低于实际宿主的 `engines.dsh` 下限。

## Decision

整个 cohort 一次性推进到 `0.1.7-alpha.2`，在隔离工作树（`sdk/0.1.7-alpha.2`，基于 `dev`）内完成，因此共享 checkout 与运行中的 GUI 在整合前不受影响：

- **一个家族、一个发行版。** 所有被消费的 `@deepseek-ai/dsh*` 说明符（25 份清单共 258 处）、声明的下限 `dsh.engines.dsh >=0.1.7-alpha.2`（22 份包清单）、根 `pnpm-workspace.yaml` 的排除清单、`desktop/runtime/host/package.json` 的宿主载荷固定值及其重新生成的 lockfile、CI 与 release 的 mount-smoke 固定值、`docs/publish-prep.md`，以及 `shared/web-platform.ts`、`shared/tests/web-platform.spec.ts`、`tests/e2e/mount.e2e.ts` 中的 cohort 版本字面量，全部一起移动。**不接受部分推进**：`scripts/rollout-verify.test.mjs` 要求桌面宿主与声明下限完全相等，并要求根 lockfile 恰好在该下限解析家族。
- **独立的支撑固定值随同一批 vendor 发行版移动。** 仓库 devDependencies 中 `@deepseek-ai/cordis` 4.0.3 → 4.0.4、`@deepseek-ai/schemastery` 3.18.3 → 3.18.4；根与宿主的排除清单增收 cordis 4.0.4、cosmokit 1.8.5、schemastery 3.18.4、cordis-plugin-include 1.0.9、cordis-plugin-loader 1.0.5；宿主 `overrides:` 块把它们钉住。
- **token 契约按两个官方面重新生成。** `scripts/official-tokens-snapshot.mjs` 同时读取 `@deepseek-ai/dsh-client-ui-theme` 的 `lib/` 与 `@deepseek-ai/dsh-web-frontend` 的 `dist/assets/`，写出 `contracts/official-tokens-v1.json` 与 `src/core/css-safety/official-tokens.generated.ts`。`@deepseek-ai/dsh-web-frontend` 成为根 devDependency，使第二个来源可复现而不是只存在于本机。**`contractVersion` 保持 1**：这是一次纯增量的收录扩张、零移除，没有任何消费方需要迁移分支，而且 JSON 与生成的注册表作为一个整体发布（有测试断言两者相等）。
- **`--dsw-static-` 调色板继续排除，永不适用的角色也继续排除。** 皮肤不得重染 static 阶梯；无论契约现在收录多少名字，state、shadow、mask、button、font、easing、duration、transition 这些角色都不进入 fallback 派生——`--dsw-alias-state-idle-primary` 与 `--dsw-alias-label-error` 是契约成员，但派生会刻意跳过它们。

## The official token surface

| 口径 | alpha.1 | alpha.2 |
| --- | --- | --- |
| 壳 bundle（`dsh-web-frontend` dist assets），非 static | 68 | 70 |
| 主题包（`dsh-client-ui-theme` lib） | 288 | 290 |
| 并集（即契约宇宙） | 291 | 293 |
| 已退役的「仅壳」契约 | 278 | — |

退役契约从未覆盖的 15 个名字现在都是契约成员；其中 13 个在 alpha.1 就已存在（`--dsw-alias-bg-document-preview`、`--dsw-alias-bg-layer-4`、`--dsw-alias-label-document-preview`、`--dsw-alias-label-error`、`--dsw-alias-link`、`--dsw-alias-state-idle-primary`、`--dsw-corner-shape`、五个 `--dsw-elevation-*`、`--dsw-menu-backdrop-filter`），2 个是 alpha.2 新增。fallback 派生的形态未变：它仍然只为皮肤留空未定义的锚点发牌，而 `--dsw-alias-label-error` 在进入契约之前已实测为 42 个随包皮肤无一为其赋值，因此先扩了守卫。

## Alternatives considered

**继续停留在 `0.1.7-alpha.1`。** 否决：宿主已经在提供 alpha.2，而 `scripts/rollout-verify.test.mjs` 把声明下限与桌面宿主固定值、根 lockfile 解析三者耦合，仓库不可能既声明旧 cohort 又跑在新 cohort 上而不让门禁变成谎言。

**只推进插件清单，留下桌面宿主固定值与 lockfile。** 否决：同样的耦合，外加隔离规则——部分推进会让宿主运行时解析 alpha.1 而插件声明 alpha.2，正是本次要消除的错位。

**只从壳 bundle 重新生成契约。** 否决：那会把契约缩到约 70 个名字，删掉每个皮肤的可派生锚点，并把「定义搬进主题包」这个打包现实固化成错误权威。

**在 278 名单契约上手工补两个新 token。** 否决：13 个既有缺口仍在，`source` 字段仍只指向两个来源中的一个，也没有可复现的生成器。

**为这次面变化把 `contractVersion` 升到 2。** 否决：没有任何 token 被移除，不需要消费方分支；该版本号用于标示破坏性的形态变化，而不是名单变宽。

**在工作树里把 `market/shell` 与 `market/dist` 整站重建。** 否决（不必要）：`scripts/market-build` 从不开启 `deriveFallbacks`，因此没有任何 `market/dist` 字节能依赖这次契约变化；`pnpm market:check` 会用重建后的 Skin Center `lib/` 重新生成整站并与已提交产物比对。若该检查出现分歧，字面重建仍然可选。

## Consequences

- 新 cohort 下的 `pnpm install` 必须先删掉已安装树。pnpm 校验的是**已安装**的 `node_modules/.pnpm/lock.yaml` 是否符合最小发布年龄策略，因此即使根 lockfile 已前移且 `minimumReleaseAge` 未设置，陈旧树仍会持续报 `[ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION]`。
- 归档报告的首轮数字已就地更正（新增 2 个而非 5 个，既有缺口 13 个而非 10 个），并追加了「后续进展」一节，声明本次变更取代其「本次未实施」的表述。该报告是 `docs/archive/` 里的一次性记录，不是当前行为的权威。
- 四个包提交 `lib/`：Skin Center 的 `lib/` 与 `scripts/lib-artifact-fingerprints.json` 因守卫与注册表变化在本变更内重建并重录；`packages/dsh-market/lib/index.js` 仅因其依赖注释变化而重建。
- 明确留在范围外的残留：十二个只被使用、没有任何官方面定义的 `--dsw-*` 名字仍留在契约之外（记录为覆盖缺口而非收进契约）；扫描发现的皮肤探针残留（198 处探向历史上被移除的类名、15 处探向 alpha.2 真正移除的名字、6 处探向改名后的名字）不在本次修复；`desktop/runtime/profile-web` 仍固定 `@linxin666/dsh-web-all` 0.3.19，而本仓库已是 0.3.24。
- 运行中 GUI 的 `lib/` 产物在下次页面加载即生效，但任何触及 bundle 行或 `cordis.patch.yml` 的改动都需要由用户重启 DSH 服务；本次验证在工作树与共享 checkout 内完成，该重启仍待用户执行。
