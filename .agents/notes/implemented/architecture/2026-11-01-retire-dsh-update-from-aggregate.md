# Agent Note: the family aggregate retires the self-update row

Status: implemented

## Problem

`packages/dsh-web-all/aggregate.yml` mounted `dsh-update` as the `web-ui-update` row and listed `@linxin666/dsh-update` among the aggregate's dependencies, so a bundle install delivered an in-GUI family self-update trigger to every profile. The package refuses to update a profile whose family is installed from a checkout — a `link:` spec cannot be moved by the registry, so it reports local development mode and stops — and that is exactly the profile `node scripts/link-profile.mjs` builds, the development flow this repository documents and the one its "install from a checkout" instructions produce. The bundle's own users were therefore the population whose update entry could never work. The per-row path is covered elsewhere: the plugin manager's list toolbar checks every installed plugin, applies the eligible third-party updates one by one, and offers the restart that makes them load. The aggregate was paying one runtime dependency and one sidebar seat for a coarser updater with a narrower working range. [The family self-update is its own plugin row](2026-09-25-self-update-own-plugin-row.md) owns the seat decision; this note retires the aggregate's share of it, and the package's behaviour is unchanged.

## Decision

- **The aggregate mounts no update row.** `../dsh-update` is no longer in `patchFrom` or in `deps` of [aggregate.yml](../../../../packages/dsh-web-all/aggregate.yml): `@linxin666/dsh-web-all` does not depend on the package, and installing the bundle no longer puts the row into a profile.
- **The package stays, and stays published.** `packages/dsh-update` keeps its sources, tests, `lib/`, cordis patch and README pair; [docs/publish-prep.md](../../../../docs/publish-prep.md) keeps its row and the package keeps releasing. `dsh plugin --profile <profile> add @linxin666/dsh-update` mounts the row in any profile that wants it, and the package's own manifest is already the fallback anchor when `@linxin666/dsh-web-all` is absent.
- **The subpath becomes a tombstone.** `update` stays in `tombstones:` and is registered in `retiredPlugins:` as `{"family":"update","plugin":"@linxin666/dsh-update"}`, with its `shellNotes:` row kept for the shell's own display metadata. A profile whose stored row name is `@linxin666/dsh-web-all/update` still resolves the export, and the shell reads the registry and mounts the row as a silent no-op instead of recording an import failure. The mechanism belongs to [Generate the aggregate's retired-plugin registry from its manifest](../bug-fix/2026-10-17-aggregate-retired-plugin-registry.md).
- **The Russian dictionary stays.** `packages/dsh-i18n/src/client/ru/update.ts` and that package's `update` namespace row keep serving the package for as long as it can be installed: retiring the aggregate's row is not removing the package. This deliberately differs from the `remote-web-ui` retirement, where the dictionary went away with the family's last consumer.
- **The documents state the retirement as current state.** [README.md](../../../../README.md) and [README.en.md](../../../../README.en.md) keep the plugin table row and the standalone install example, each saying the bundle does not include the package; the `dsh-update` row of [docs/architecture.md](../../../../docs/architecture.md) says the same, as do the package's README pair and the package's [AGENTS.md](../../../../packages/dsh-update/AGENTS.md).

## Alternatives considered

- **Delete the package together with the row.** Rejected: only the bundle's mount is being retired. A profile that installs the family from npm and wants one-click family updates in the UI has no other entry, the package's loopback run pipeline, tests and dictionary are in working order, and deletion would turn every existing standalone install into an unresolvable import. Removing a published npm package is also a deprecation decision of its own, not a side effect of an aggregate cleanup.
- **Keep the row and list it under `inactive:`.** Rejected: an inactive row still installs the package into every profile and still makes it a dependency, its README would describe a surface no default install has, and the per-row switch would remain the thing users are told to toggle for a plugin the bundle is trying to stop carrying. Retirement means the bundle no longer ships it, not that it ships it switched off.
- **Keep mounting the row and document the link-mode refusal harder.** Rejected: the refusal is correct — a `link:` spec must never be rewritten — so the only thing left to fix is that the bundle installs the package by default. A documented dead entry is a permanent "why does this button fail" in exactly the development profiles this repository tells people to build.
- **Excise the subpath export instead of tombstoning it.** Rejected: every profile that upgraded through the bundle has `@linxin666/dsh-web-all/update` written in its stored row name, and without the export that entry fails at import and is recorded as failed or degraded. A tombstone plus a `retiredPlugins` entry makes the same upgrade silent, and the aggregate already owns that mechanism.
- **Drop the ru dictionary, following the `remote-web-ui` retirement.** Rejected: that precedent dropped the dictionary because the family was removing the capability's last consumer. The package stays installable here, so its `update` namespace is still served to a Russian UI; deleting the dictionary would leave a standalone install in a Russian profile falling back to English.

## Consequences

- An aggregate profile shows no sidebar-footer update trigger. Updating is the plugin manager's per-row path, or a profile that installs `@linxin666/dsh-update` on its own when its family comes from npm.
- The aggregate carries one dependency and one mounted row fewer; `web-ui-update` appears in no generated patch, and `tombstones`, `retiredPlugins` and `shellNotes` hold the family's only remaining trace.
- A profile still carrying the old row name upgrades silently: the subpath resolves to the shell, the shell no-ops the row, and nothing lands in the degraded ledger.
- A standalone install keeps every documented behaviour, including the local-development-mode refusal and the `SELF_PACKAGE` fallback anchor.
- The retirement leaves the package's release line, its tests and its dictionary untouched.
