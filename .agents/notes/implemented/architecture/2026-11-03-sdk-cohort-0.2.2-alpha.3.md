# Agent Note: SDK cohort 0.2.2-alpha.3

Status: implemented

## Problem

The family and all four satellites declared 0.2.1-rc.3 while the operator's host and the current upstream release are 0.2.2-alpha.3. This release changes PTC execution, Session-projection registration, Cordis event typings and the Node floor. It also adds generic Russian localization, Host-level automation, third-party updates, change requests/worktrees and developer statistics, so a mechanical version bump would miss both runtime breakage and functionality that should now be shared with the Host.

## Decision

The published `dsh-v0.2.2-alpha.3` tag, not the moving upstream worktree, is the adaptation baseline. All consumed SDK ranges move to `^0.2.2-alpha.3`, Cordis to `4.0.6-alpha.2`, schemastery to `3.18.6-alpha.2`, and the Host peer and engine floors to `>=0.2.2-alpha.3`. CI and declared package engines use Node 24.9 or later. Main and satellite lockfiles, release-age ledgers, README badges and bilingual pairing records move together.

The overlap audit keeps one owner per capability:

- DSH owns the Russian language definition and official shell dictionaries. `dsh-i18n` keeps only family-owned Russian namespaces; it no longer calls `addLanguage`.
- The official Automation tasks page and the task board remain visible together. Generic reminders use the Host implementation; card execution, cron, subtasks and provider extensions stay with the board (the board's own goal acceptance was later removed in [2026-11-11](../simplification/2026-11-11-remove-task-board-goal-run-and-acceptance.md)). The DOM suppression helper is removed.
- Official change requests/worktrees do not replace the commit graph, branch switching, managed-worktree removal or automatic isolation, so Git Graph stays. Official developer statistics measure turns and steps, not provider balances, quotas or cost, so Usage stays. Official third-party `updateBundle` rejects bundles carrying plugin management and still changes layer order, so the family's guarded two-phase update and index restoration stay.
- The Agent Teams fork is rebased to tag commit `05b1cae8db6e674c5685101494d4eec24652424a` (agent-team tree `08322f8f03faad9b0ee04c7e72d1b119b0158977`, tool tree `e8af5edce18085dce4ad2e6ec3946e0da3422190`). Member pins and the squad-session tool gate remain local differences. `TeamService.create()` explicitly awaits the async projection registration that manual construction does not invoke, and `TeamJournal` consumes the retained handle. The baseline did not move after the 2026-11-03 upstream review either: upstream had meanwhile moved the team runtime out of `packages/experimental` into `packages/team`, renamed its packages to `@deepseek-ai/dsh-agent-team` / `@deepseek-ai/dsh-tool-agent-team` (both unpublished), and deleted `spawn_teammate` with the whole roster runtime, leaving Team a shared task board over the standard subagent tools. That makes the fork's reason to exist stronger, not weaker, so only the coexistence gate followed: it recognized either generation's bundle name and yielded the `agentTeams` service, with the evidence recorded in the provenance record this cohort carried. The fork and that record are gone: the runtime the deployment ships is the base now, and this package owns only the ledger, the panel, member runs and the squad orchestration ([owning note](2026-10-21-agents-sub-plugin-owns-member-definitions.md)).

LiangShen mounts the official PTC executor for `ptc` and disables it for `native`; the retired `modelSelectionSettings` key is removed. `local-lite` deliberately stays native and keeps only its outer-PTC restriction guard; roleplay presets need no tool-roster change. Shared settings helpers use erased event parameter types at their Cordis subscription seams. Windows dependency installation uses `pnpm.cmd` through the shell, Windows host-SDK candidates are discovered from `%APPDATA%`, and the mount lane passes a standard file URL to the CLI.

The official loader roster is refreshed to 192 ids, the frozen browser table remains at eleven modules, and the official token contract is refreshed to 335 tokens. Aggregate output, committed libraries, fingerprints, market inputs and `market/dist` are regenerated through their owning tools.

## Alternatives considered

**Track npm `latest` (0.2.1-rc.5) instead of the installed alpha host.** Rejected: it omits the PTC/PTC-SSH and projection changes this adaptation must cover and does not match the operator's requested upstream target.

**Remove every feature that has any upstream overlap.** Rejected: the new upstream capabilities are not complete substitutes for family dictionaries, board execution, Git history/isolation, provider accounting or squad pins. Only complete surfaces move to the Host.

**Use official `updateBundle` for the aggregate.** Rejected: the official updatability rule excludes the aggregate, and the operation still appends a reinstalled bundle to the layer list; replacing the guarded custom path would break both eligibility and ordering.

**Delete the Agent Teams fork.** Rejected: upstream alpha.3 still lacks member-definition pins and the squad-only tool gate. The smaller async-projection delta is replayed instead of losing those behaviors.

**Modify the upstream checkout or publish a release.** Rejected: the upstream checkout is read-only comparison evidence, and no release was requested. Package versions remain unchanged.

## Consequences

Future family artifacts require DSH 0.2.2-alpha.3 and Node 24.9 or later. Existing profiles need a Host restart to load rebuilt host rows and the new PTC executor; the running user service is never restarted by this work. Users who enabled the retired standalone `@deepseek-ai/dsh-experimental-tool-worktree` row must remove it from `dsh.profile.bundles` as the upstream upgrade guide requires.

A valid complete host SDK tree is still required for the local pin. The Windows global tree in this environment lacks core package markers and is correctly rejected, so registry packages provide the validation cohort instead of forcing a split pin. The standard `deps:install` and isolated mount paths work on Windows.

## Testing

- Full main typecheck, build and workspace tests pass. Focused suites pass for Agent Teams (262), i18n, LiangShen and Task Board (1381 plus one skipped native smoke). Runtime dependencies, aggregate, shared-copy, committed-library, docs, i18n, emoji and test-standard checks pass. `market:check` passes after regeneration.

- Satellite checks pass for presets (55 tests, 33 presets), community plugins (2 tests, 151 entries) and pet (full suite/build). Skins typecheck, build, catalog and hook checks pass; its suite has 807 passes and one Windows-only addon-mapping failure, where the expected `EPERM` on directory rename is not raised. That platform behavior is outside this cohort change.
- The real npm alpha.3 CLI installs the packed aggregate with every main-family tarball into an isolated home and starts the real GUI. Playwright finds the official frame, no page error and no plugin crash. The GUI shows Automation tasks and Task board together, the LiangShen preset is selectable, and official Russian chrome plus family Russian dictionaries render; the narrow viewport keeps both entries reachable. The composed Host configuration carries the PTC executor and no `modelSelectionSettings`. No running user service or shared home is touched, and every probe process is reaped.
