# Agent Note: SDK cohort 0.2.2-alpha.3

Status: implemented

## Problem

家族与四个卫星仓声明的是 0.2.1-rc.3，而操作者宿主与当前上游发布均为 0.2.2-alpha.3。该版本改变 PTC 执行、Session 投影注册、Cordis 事件类型与 Node 下限，同时加入通用俄语、宿主级自动化、第三方插件更新、变更请求/工作树与开发者统计。只做机械版本替换会同时漏掉运行时破坏和应当与宿主共享的功能。

## Decision

适配基线固定为已发布的 `dsh-v0.2.2-alpha.3` 标签，而不是持续移动的上游工作树。消费的 SDK range 全部迁到 `^0.2.2-alpha.3`，Cordis 迁到 `4.0.6-alpha.2`，schemastery 迁到 `3.18.6-alpha.2`，宿主 peer 与 engine 下限迁到 `>=0.2.2-alpha.3`。CI 与声明的包引擎使用 Node 24.9 或更高版本。主仓与卫星仓 lockfile、发布冷却账本、README 徽章与双语配对记录一起更新。

重叠审计让每个能力只有一个属主：

- DSH 负责俄语语言定义与官方 shell 字典。`dsh-i18n` 只保留家族自有俄语命名空间，不再调用 `addLanguage`。
- 官方「自动化任务」页与任务看板同时可见。通用提醒使用宿主实现；卡片执行、cron、子任务与提供方扩展继续由看板负责（看板自身的任务验收已于 [2026-11-11](../simplification/2026-11-11-remove-task-board-goal-run-and-acceptance.zh.md) 移除）。DOM 隐藏助手被移除。
- 官方变更请求/工作树不能替代提交图谱、分支切换、托管 worktree 删除或自动隔离，因此 Git Graph 保留。官方开发者统计衡量轮次与步骤，不提供余额、套餐或成本，因此 Usage 保留。官方第三方 `updateBundle` 拒绝携带插件管理能力的组合包且仍会改变层级顺序，因此家族的两阶段更新与索引恢复保留。
- Agent Teams fork 的基线迁到标签提交 `05b1cae8db6e674c5685101494d4eec24652424a`（agent-team 树 `08322f8f03faad9b0ee04c7e72d1b119b0158977`，tool 树 `e8af5edce18085dce4ad2e6ec3946e0da3422190`）。成员钉住与小队会话工具门禁仍是本地差异。`TeamService.create()` 显式等待手动构造不会触发的异步投影注册，`TeamJournal` 使用保留句柄。2026-11-03 复核上游之后基线同样没有移动：上游此时已把 team 运行期从 `packages/experimental` 迁到 `packages/team`，包名改为 `@deepseek-ai/dsh-agent-team` / `@deepseek-ai/dsh-tool-agent-team`（两者都未发布），并删掉了 `spawn_teammate` 与整套花名册运行期，Team 只剩原生子代理之上的一块共享任务板。这让这个 fork 存在的理由更强而不是更弱，因此只有共存闸门跟着动了：它认得两代任意一个 bundle 名，并照旧让出 `agentTeams` 服务，当时的证据记在这批改动自带的一份出处记录里。fork 与那份记录都已删除：如今运行期由部署提供、它就是基座，本包只持有账本、面板、成员运行与整队编排（[归属记录](2026-10-21-agents-sub-plugin-owns-member-definitions.zh.md)）。

梁神在 `ptc` 下挂载官方 PTC 执行器，在 `native` 下停用它；旧 `modelSelectionSettings` 键被移除。`local-lite` 刻意保持 native，只保留外层 PTC 的限制守卫；角色扮演预设无需工具清单迁移。共享设置助手在 Cordis 订阅缝使用擦除的事件参数类型。Windows 依赖安装经 shell 调用 `pnpm.cmd`，从 `%APPDATA%` 发现 Windows 宿主 SDK 候选，挂载流程向 CLI 传标准 file URL。

官方 loader 名册刷新为 192 个 id，浏览器冻结表保持 11 个模块，官方 token 契约刷新为 335 项。聚合产物、已提交 lib、指纹、市场输入与 `market/dist` 均由各自生成器重建。

## Alternatives considered

**跟随 npm `latest`（0.2.1-rc.5）而不是已安装的 alpha 宿主。** 否决：它缺少本次适配必须覆盖的 PTC/PTC-SSH 与投影变化，也不符合操作者要求的上游目标。

**删除所有与上游有重叠的功能。** 否决：上游新能力不能完整替代家族字典、看板执行、Git 历史/隔离、提供方账务或小队钉住。只有完整表面才交给宿主。

**聚合包改用官方 `updateBundle`。** 否决：官方可更新规则排除该聚合包，而且操作仍把重装组合包追加到层级列表；替换受保护的自定义路径会同时破坏可更新性与顺序。

**删除 Agent Teams fork。** 否决：上游 alpha.3 仍没有成员定义钉住与小队专用工具门禁。只重放更小的异步投影差异，避免丢失这些行为。

**修改上游检出或发布新版本。** 否决：上游检出只作只读对照，且没有收到发布请求。包版本保持不变。

## Consequences

后续家族产物要求 DSH 0.2.2-alpha.3 与 Node 24.9 或更高版本。既有 profile 需要重启宿主以加载重建的 host 行与新 PTC 执行器；本工作从不重启用户正在运行的服务。按上游升级指南，曾启用已退役独立 `@deepseek-ai/dsh-experimental-tool-worktree` 行的用户需从 `dsh.profile.bundles` 移除它。

本地 pin 仍要求完整有效的宿主 SDK 树。本环境的 Windows 全局树缺少核心包标记，因而被正确拒绝；验证改用 registry 包，而不是强行制造分裂 pin。标准 `deps:install` 与隔离挂载路径在 Windows 上可用。

## Testing

- 主仓全量 typecheck、build 与工作区测试通过。Agent Teams（262）、i18n、梁神与看板（1381，另有一项原生 smoke 跳过）焦点套件通过。运行时依赖、聚合、共享副本、已提交 lib、文档、i18n、emoji 与测试规范检查通过。重建后 `market:check` 通过。
- 脚本测试有 552 个通过项与一个既有 Windows 文件权限失败：deploy-market 探针期望 `600`，Windows 返回 `666`。未放宽这条无关断言。
- 卫星检查通过：presets（55 个测试、33 个预设）、community plugins（2 个测试、151 个条目）与 pet（完整套件/构建）。skins 的 typecheck、构建、目录与 hook 检查通过；其套件有 807 个通过项与一个 Windows 原生 addon 映射失败——目录重命名没有产生预期的 `EPERM`。该平台行为不属于本次 cohort 改动。
- 真实 npm alpha.3 CLI 把聚合包与全部主家族 tarball 装进隔离 home 并启动真实 GUI。Playwright 找到官方帧，未发现页面异常或插件崩溃。GUI 同时显示「自动化任务」与「任务看板」，梁神预设可选，官方俄语界面与家族俄语字典均渲染；窄屏下两个入口仍可达。Host 组合配置包含 PTC 执行器且不再有 `modelSelectionSettings`。未触碰运行中的用户服务或共享 home，所有探测进程均已回收。
