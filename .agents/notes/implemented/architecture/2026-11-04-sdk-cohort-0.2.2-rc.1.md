# Agent Note: SDK cohort 0.2.2-rc.1

Status: implemented

## Problem

The operator's local DSH host moved to `0.2.2-rc.1` while the main workspace and the four satellite submodules declared `0.2.2-alpha.3` (with alpha vendor packages `cordis@4.0.6-alpha.2` and `schemastery@3.18.6-alpha.2`). Advancing the cohort also surfaces two concrete drift points left behind by concurrent merges: `packages/dsh-remote-web-ui/src/client/plugin-card-seat.ts` (retired from `sync-shared.mjs`) still carried the pre-erasure `on(event: string, ...)` signature that fails under `cordis@4.1.0`, and `satellites/dsh-skins/src/core/custom-theme.ts` still emitted `--dsw-specific-sidebar-nav-item-hover`, which the 0.2.2 official shell removed.

## Decision

The published `dsh-v0.2.2-rc.1` tag (`66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`) is the adaptation baseline. Comparing `dsh-v0.2.2-alpha.3` against `dsh-v0.2.2-rc.1` shows zero non-manifest source differences: the official loader roster stays at 192 ids, the frozen browser platform table stays at eleven modules, the official CSS token set stays at 335 tokens, and the two `dsh-agents` forked upstream `src/` trees keep hashes `08322f8f03faad9b0ee04c7e72d1b119b0158977` and `e8af5edce18085dce4ad2e6ec3946e0da3422190`.

All consumed `@deepseek-ai/dsh*` ranges move to `0.2.2-rc.1` (preserving each manifest's `^`, `~`, `>=`, or exact operator), `@deepseek-ai/cordis` moves to `4.1.0`, `@deepseek-ai/schemastery` moves to `3.19.0`, and the host peer and engine floors move to `>=0.2.2-rc.1` across the root workspace, `shared`, `scripts/plugin-template`, all 23 family packages, and all four satellites (`dsh-community-plugins`, `dsh-pet`, `dsh-presets`, `dsh-skins`). Workspace `overrides`, the two `packageExtensions` entries (`dsh-client-store@0.2.2-rc.1` and `dsh-client-ui-primitives@0.2.2-rc.1`, which still omit runtime dependencies upstream), `pnpm-lock.yaml`, and `minimumReleaseAgeExclude` (pruning retired alpha.3/alpha.2 entries and recording `0.2.2-rc.1` plus stable vendor versions `1.1.0`/`1.2.0`/`1.9.0`) move together. CI and release mount pins (`DSH_CLI_VERSION`), README badges (including `dsh-liangshen`, which had lagged at `0.2.0--rc.2`), bilingual pairing hashes, `fork-provenance.md` banners, and [the host SDK pin note](../process/2026-11-01-host-sdk-pin-and-install-entry.md) are updated in lockstep.

Three compatibility fixes accompany the cohort bump:

- `packages/dsh-remote-web-ui/src/client/plugin-card-seat.ts` aligns `PluginCardContext.on` and its `slots/changed` subscription with `shared/client/settings/plugin-card-seat.ts` using erased `never` parameters, without re-adding the retired package to `scripts/sync-shared.mjs`.
- `satellites/dsh-skins/src/core/custom-theme.ts` drops the retired `--dsw-specific-sidebar-nav-item-hover` token (`--dsw-alias-interactive-bg-hover` already covers interactive hover), and `contracts/official-tokens-v1.json` refreshes its `source` provenance to `0.2.2-rc.1`.
- `packages/dsh-liangshen/presets/liangshen/tool-catalog.mjs` moves to the cohort's tool contract (issue [#2016](https://github.com/zhu1090093659/dsh-web/issues/2016)). `system-prompt/assemble` now transforms a `PromptPresentation` with no tool array — the harness collects the providers before the waterfall and merges its authoritative `tools` back after it — so a listener can neither observe nor rewrite the request's tools, and `ctx.tools.presentAs` is gone (the composition's `tool-executor-ptc` row is the presentation). The catalog therefore reads the step surface as `tools.schemas(agent, context.toolSet)`, derives the transport from the configured mode plus a mounted `ptcRuntime`, pages through `ctx.tools.restrict()` in both presentations (the only page left once the wire array stopped being filterable), and treats an unreadable projection as unreadable rather than as "this session has no tools": an empty state is never written, so a seeded child or a fork keeps a truthful catalog instead of a `No tools are currently available in this session.` assertion that contradicted the 47 tools on its own wire.

Committed `lib/` artifacts (`dsh-market`, `dsh-web-all`, `dsh-presets`, `dsh-skins`) and `scripts/lib-artifact-fingerprints.json` are rebuilt, and `node scripts/link-profile.mjs` relinks the aggregate's four satellite entries to the local satellite checkouts.

## Alternatives considered

**Leave manifests on `0.2.2-alpha.3` because `0.2.2-rc.1` satisfies `>=0.2.2-alpha.3`.** Rejected: tilde and exact vendor pins in workspace and satellite manifests prevent resolving `cordis@4.1.0` and `schemastery@3.19.0`, and `rollout-verify.sh` requires the root lockfile and scaffold floor to match the target release candidate.

**Put `dsh-remote-web-ui` back into `scripts/sync-shared.mjs`.** Rejected: `00aa61599` deliberately detached the deprecated package when retiring it from the aggregate; updating its local copy preserves that retirement boundary while keeping workspace typecheck and build green.

**Modify the upstream checkout, restart the running DSH service, or bump family package versions.** Rejected: the upstream checkout is read-only reference material, running user services must not be interrupted, and no release publication was requested.

## Consequences

Family packages and satellites now require DSH `>=0.2.2-rc.1`. Because the local global `@deepseek-ai/dsh` entry on this machine is a junction into an upstream source checkout rather than a flat global install, `scripts/host-sdk-link.mjs` exits `0` without pinning and the workspace validates cleanly against the unified npm registry `0.2.2-rc.1` cohort. Rebuilt host bundles and profile links are in place on disk; the user must restart their running DSH service for host-side rows to reload.
