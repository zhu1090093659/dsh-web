# Agent Note: SDK cohort 0.2.2-rc.1

Status: implemented

部分被 [0.2.2-rc.2 队列](2026-11-12-sdk-cohort-0.2.2-rc.2.zh.md) 取代：全部区间、floor 各面与 lockfile 条目都推进到 `0.2.2-rc.2`，并有三处契约需要适配。下述 fork 基线、兼容修复以及它们引入的双队列桥接，仍是那次改动的起点。

## Problem

操作者本机 DSH 宿主已升级至 `0.2.2-rc.1`，而主工作区与四个卫星子模块仍声明 `0.2.2-alpha.3`（配套预览版 vendor 包 `cordis@4.0.6-alpha.2` 与 `schemastery@3.18.6-alpha.2`）。推进 cohort 的同时还暴露出两处并行合入遗留的契约漂移：已脱离 `sync-shared.mjs` 的 `packages/dsh-remote-web-ui/src/client/plugin-card-seat.ts` 仍保留擦除前的 `on(event: string, ...)` 签名，在 `cordis@4.1.0` 下触发类型不兼容；`satellites/dsh-skins/src/core/custom-theme.ts` 仍在输出已被 0.2.2 官方 shell 移除的 `--dsw-specific-sidebar-nav-item-hover`。

## Decision

适配基线固定为已发布的 `dsh-v0.2.2-rc.1` 标签（`66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`）。对照 `dsh-v0.2.2-alpha.3` 与 `dsh-v0.2.2-rc.1` 可确认非清单源码差异为零：官方 loader 名册仍为 192 个 id，浏览器冻结平台表仍为 11 个模块，官方 CSS token 集合仍为 335 项，`dsh-agents` fork 的两棵上游 `src/` 树哈希保持 `08322f8f03faad9b0ee04c7e72d1b119b0158977` 与 `e8af5edce18085dce4ad2e6ec3946e0da3422190` 不变。

根工作区、`shared`、`scripts/plugin-template`、全部 23 个家族包与四个卫星仓（`dsh-community-plugins`、`dsh-pet`、`dsh-presets`、`dsh-skins`）消费的 `@deepseek-ai/dsh*` 版本全部迁至 `0.2.2-rc.1`（保留各清单原有的 `^`、`~`、`>=` 或精确前缀），`@deepseek-ai/cordis` 迁至 `4.1.0`，`@deepseek-ai/schemastery` 迁至 `3.19.0`，宿主 peer 与 engine 下限迁至 `>=0.2.2-rc.1`。工作区 `overrides`、两条 `packageExtensions`（上游仍漏声明运行时依赖的 `dsh-client-store@0.2.2-rc.1` 与 `dsh-client-ui-primitives@0.2.2-rc.1`）、`pnpm-lock.yaml` 与 `minimumReleaseAgeExclude`（清理旧 alpha.3/alpha.2 条目，登记 `0.2.2-rc.1` 与正式版 vendor `1.1.0`/`1.2.0`/`1.9.0`）一并更新。CI 与发布挂载 pin（`DSH_CLI_VERSION`）、README 徽章（含此前停留在 `0.2.0--rc.2` 的 `dsh-liangshen`）、双语配对哈希、`fork-provenance.md` 文件头标识及[宿主 SDK pin 记录](../process/2026-11-01-host-sdk-pin-and-install-entry.zh.md)同步对齐。

随本次 cohort 升级一并落地三项兼容性修复，以及在本机宿主检出升级至 `dsh-v0.2.2-rc.2`（`ddac96760b6`，npm registry 尚未发布 `0.2.2-rc.2`）时的跨队列运行期桥接：

- `packages/dsh-remote-web-ui/src/client/plugin-card-seat.ts` 将 `PluginCardContext.on` 及其 `slots/changed` 订阅与 `shared/client/settings/plugin-card-seat.ts` 对齐为 `never` 参数擦除签名，同时不将该已退役包重新加回 `scripts/sync-shared.mjs`。
- `satellites/dsh-skins/src/core/custom-theme.ts` 移除已退役的 `--dsw-specific-sidebar-nav-item-hover`（交互悬停背景已由 `--dsw-alias-interactive-bg-hover` 覆盖），并将 `contracts/official-tokens-v1.json` 的 `source` 来源刷新至 `0.2.2-rc.1`。
- `packages/dsh-liangshen/presets/liangshen/tool-catalog.mjs` 迁至本 cohort 的工具契约（issue [#2016](https://github.com/zhu1090093659/dsh-web/issues/2016)）。`system-prompt/assemble` 现在变换的是不含 tools 数组的 `PromptPresentation`——宿主在 waterfall 之前收集 provider、之后才把自己的权威 `tools` 合并回去——因此监听器既读不到也改不了本次请求的工具面，且 `ctx.tools.presentAs` 已被移除（呈现改由组合里的 `tool-executor-ptc` 行决定）。目录于是改为用 `tools.schemas(agent, context.toolSet)` 读本步准入面，由配置模式加挂载的 `ptcRuntime` 判定传输形态，并在两种呈现下都通过 `ctx.tools.restrict()` 分页（wire 数组不再可过滤后，注册表是唯一还留有分页的地方），同时把「读不到投影」与「本会话没有工具」彻底分开：读不到时不写状态，于是 seeded 子会话或 fork 保留真实目录，而不会注入与自身 wire 上 47 个工具相矛盾的 `No tools are currently available in this session.`
- `packages/dsh-agents` 移除对 `@deepseek-ai/dsh-subagent/internal` 的静态子路径导入（`0.2.2-rc.2` 已移除该导出），改为优先探测 `Symbol.for('dsh.subagent.deliverPrompt')` 并回退至 `subagents.sendMessage(caller, target.id, content, { signal })`；在 `subagents.startActivation` 中同时传入顶层字段与 `request` 嵌套字段；桥接 `drainChildren` / `drainDescendants` / `started.dispose()`；并在 `@deepseek-ai/dsh-base` 与 `subagents.rootOf` 同时在场时于 `profileMountsOfficialTeams` 中识别 `0.2.2-rc.2+` 内建的 `id: agent-team` 行并主动让位。
- `packages/dsh-liangshen/presets/liangshen/dispatch-guard.mjs` 在 `agents.roots()` 缺省（`0.2.2-rc.2+`）时回退探测 `subagents.rootOf(caller)`，并支持从存活 `Agent` 实例读取 `entry.running === true` 与 `entry.session.header.parentSession`；`packages/dsh-plugin-manager/tests/bundle-row-id.spec.ts` 将官方 bundle 行 ID 快照更新为 `0.2.2-rc.1` 与 `0.2.2-rc.2` 的并集（共 200 个 ID）。

重建已提交 `lib/` 产物（`dsh-market`、`dsh-web-all`、`dsh-presets`、`dsh-skins`）与 `scripts/lib-artifact-fingerprints.json`，并通过 `node scripts/link-profile.mjs` 将聚合包内四个卫星包重新链接到本地卫星工作树。

## Alternatives considered

**因为 `0.2.2-rc.1` 满足 `>=0.2.2-alpha.3` 而保持清单在 `0.2.2-alpha.3` 不动。** 否决：工作区与卫星清单中的波浪号及精确 vendor 版本会阻碍解析到 `cordis@4.1.0` 与 `schemastery@3.19.0`，且 `rollout-verify.sh` 要求根 lockfile 与脚手架下限与目标候选版本一致。

**将 `dsh-remote-web-ui` 重新加回 `scripts/sync-shared.mjs`。** 否决：`00aa61599` 在将其从聚合包退役时刻意解除了同步绑定；直接更新其本地副本可在保持退役边界的同时让工作区类型检查与构建全绿。

**修改上游检出、重启正在运行的 DSH 服务或递增家族包版本号。** 否决：上游检出仅供只读对照，运行中的用户服务不得中断，且本次未收到发布请求。

## Consequences

家族包与四个卫星仓现在要求 DSH `>=0.2.2-rc.1`。由于本机全局 `@deepseek-ai/dsh` 是指向上游源码检出的目录联接而非扁平全局安装，`scripts/host-sdk-link.mjs` 按预期返回 `0` 不建立软链，工作区基于统一的 npm registry `0.2.2-rc.1` cohort 完成验证。重建后的宿主 bundle 与本地 profile 链接均已就绪，用户需自行重启正在运行的 DSH 服务以加载新构建的宿主行。
