# Agent Note: SDK cohort 0.2.2-rc.2

Status: implemented

## Problem

The operator's DSH host moved to `0.2.2-rc.2` (published 2026-11-11 on the `next` dist-tag; `latest` still answers `0.2.2-rc.1`) while the workspace, `shared`, the plugin scaffold and the desktop-facing surfaces all declared `0.2.2-rc.1`. Because `node_modules/@deepseek-ai` is a symlink into the host installation, a workspace left on the older cohort silently resolves two copies of the same SDK package, and `0.2.2-rc.2` breaks three contracts this repository consumes:

- `HarnessError` left `@deepseek-ai/dsh-llm` for its own package, `@deepseek-ai/dsh-error`, which `dsh-llm` imports at module top level and declares as a required peer. Without it the base class degrades to `any` for every consumer and the import fails at runtime.
- The central prompt-context order table dropped `TEAM_IDENTITY` (rc.1 had it at 125). `getContextOrder('TEAM_IDENTITY')` now returns `undefined`, and the official `context()` rejects a non-finite order, so a copied-from-upstream registration throws.
- The SDK moved to zod 4.6.6 while `dsh-agents` pinned 4.4.3, splitting zod's type identity across two module instances for every projection schema.

## Decision

The published `dsh-v0.2.2-rc.2` tag is the adaptation baseline, and the host and the workspace move together: the operator upgraded the global CLI to `@deepseek-ai/dsh@0.2.2-rc.2` and the pin was restored afterwards (`host sdk: … (0.2.2-rc.2, 336 packages)`, `check: ok (root exposes 336 packages, 223/223 workspace entries pinned, 37 host-absent left to pnpm)`).

Every consumed `@deepseek-ai/dsh*` range moves to `0.2.2-rc.2` preserving its operator, `@deepseek-ai/cordis` and `@deepseek-ai/schemastery` stay at 4.1.0 and 3.19.0, and the cohort's host-floor surfaces move with it: `dsh.engines.dsh >=0.2.2-rc.2` plus the matching `@deepseek-ai/dsh` host peer in every family package and the scaffold, both root README badges, all 32 package README badges, and the CI/release `DSH_CLI_VERSION` pins. Workspace `overrides` (the three client-only packages the host never installs), the two `packageExtensions` keys, `minimumReleaseAgeExclude` and the lockfile move in the same change. This repository declares no desktop runtime pin, so that surface is absent here rather than moved.

Three compatibility changes ride along:

- `@deepseek-ai/dsh-error@0.2.2-rc.2` joins the root devDependencies as a host face, the same shape `dsh-sandbox` has: a required peer the SDK imports at module top level is carried by the workspace instead of a `packageExtensions` patch.
- `zod` is pinned to `4.6.6` in `dsh-agents` and `dsh-remote-web-ui`, so the workspace resolves one zod instance together with the SDK.
- `dsh-agents` supplies the Team identity prompt-context position itself (`TEAM_IDENTITY_CONTEXT_ORDER = 125`, the slot rc.1's table allocated to the name) for both the identity context and the squad roster context, and drops the `SquadContextRegistry.getContextOrder` optional face that can no longer answer.

Three consumed contracts were re-verified against rc.2 rather than assumed: the frozen browser platform table is byte-identical (all eleven specifiers, same order), the `dsh.client.inject` union is unchanged at sixteen names (rc.2 adds two official client rows, `ui-agent-team` and `ui-account-notifications`, which no package here injects), and `@deepseek-ai/dsh-client-locale`'s registration surface is unchanged (identical `lib/types` declarations; the same duplicate-`(ns, locale)` rejection and idempotent disposer).

## Native-first overlap inventory

rc.2 adds official capability that overlaps three plugin implementations. None is removed in this change: each needs the restarted rc.2 host to verify the native replacement in the real GUI, so each is a recorded exception with the follow-up direction stated, per the rule that de-duplication may never ship a capability regression.

- **AgentTeam runtime** (`packages/dsh-agents/src/team/*`, `src/tools/*`): a fork of rc.1's experimental agent-team. rc.2 folds teams into native subagents (`ROOT_AGENT_NAME`, `listDescendants`, `rootOf`, the `agent-team` and `tool-agent-team` roster rows) and our `profileMountsOfficialTeams` already yields to it. Decision: recorded exception. The fork carries capability the native face does not — the squad ledger pins preset, permission, model and reasoning effort four ways before the child session exists, plus ten `squads_*` tools, a `/state` route and a bounded run history. Removing the fork is now a contained change (delete the fork, re-express spawn on `subagents.startActivation` + `rootOf`), but it must be a separate change verified against a restarted host.
- **Team roster UI** (`packages/dsh-agents/src/client/*`): rc.2's `ui-agent-team` row covers browsing and coordination. Decision: recorded exception, migrate to a thin extension that keeps only member-definition editing and run history.
- **Language-keyed code-block rendering** (`packages/dsh-diagrams/src/client/blocks.ts`): rc.2 publishes two seams we do not use — the `conversation.chat.markdown.fence` language-keyed slot and `MarkdownDelegate.renderCode` — while the plugin claims blocks by a private DOM class and its own README records that a renderer rename stops diagrams. Decision: recorded exception for this cohort; the migration is a visible UI change and needs Before/After captures against the restarted host.
- No overlap: archived-session worktree cleanup (`dsh-session-archive` implements an archive ledger and physical deletion only), MCP server management, web-search provider, menu/overlay positioning (`useAnchoredPosition` was removed upstream and this repository never used it), Gemini provider, account notifications, LiveShare, Office tools and Computer Use.

Two risks are recorded rather than fixed. First, the team surface collides on the restarted host: rc.2 mounts `agent-team` and `tool-agent-team` in `dsh-base` and `ui-agent-team` in `dsh-web-app` with no `disabled` flag, so the bundled replacement is on by default; the official `agentTeam` projection is at `stateVersion: 7` and its wire view carries the selection and task board while current subagents ride `subagentCatalog`, whereas the fork registers `stateVersion: 4` under the same key with the roster folded into the view. Our runtime already yields when the official bundles are present, but the client reads the projection key alone (`agentTeam`), so after a restart it reads version 7 state it was not written for while the official `ui-agent-team` seats its own sidebar entry. Second, `dsh-plugin-manager`'s update toolbar and built-in plugin group anchor on official DOM that rc.2 extends with new row states. Both need the restarted host to verify and are the first items of the follow-up change.

The committed mount smoke (`pnpm test:mount`) mounts the packed aggregate into a scratch profile with the rc.2 CLI and renders it in headless Chromium, which is the available rc.2 evidence without touching the live host.

## Alternatives considered

Upgrading only the workspace manifests was rejected: the pins resolve the SDK through the host installation, so an rc.2 workspace under an rc.1 host splits module identity exactly the way a shadow copy does. Upgrading only the host was rejected for the mirror reason: the floor would trail the host the plugins run on. Dropping the workspace `overrides` now that rc.2 is on the registry was rejected: those three client packages are build-time inputs the host never installs, and the override is what keeps their resolution on the cohort. Shimming `getContextOrder('TEAM_IDENTITY')` back to 125 was rejected in favour of the plugin owning the number: the host no longer answers for the name, and a shim would keep a call alive that returns `undefined` on every rc.2 host.
