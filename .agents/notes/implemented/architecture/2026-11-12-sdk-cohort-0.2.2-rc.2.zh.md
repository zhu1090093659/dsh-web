# Agent Note: SDK cohort 0.2.2-rc.2

Status: implemented

## 问题

操作者的 DSH 宿主已升到 `0.2.2-rc.2`（2026-11-11 发布在 `next` 标签上，`latest` 仍指向 `0.2.2-rc.1`），而 workspace、`shared`、插件脚手架与面向桌面的各面仍声明 `0.2.2-rc.1`。由于 `node_modules/@deepseek-ai` 是指向宿主安装树的软链，留在旧队列的 workspace 会静默解析出同一个 SDK 包的两份副本；而 `0.2.2-rc.2` 打断了本仓在用的三个契约：

- `HarnessError` 从 `@deepseek-ai/dsh-llm` 迁到自有包 `@deepseek-ai/dsh-error`，`dsh-llm` 在模块顶层导入它并声明为必需 peer。缺这个包时基类对每个消费方退化成 `any`，运行时导入直接失败。
- 中央 prompt context 顺序表删掉了 `TEAM_IDENTITY`（rc.1 把它分配在 125）。`getContextOrder('TEAM_IDENTITY')` 现在返回 `undefined`，而官方 `context()` 拒绝非有限 order，照搬上游写法的注册会抛错。
- SDK 换到 zod 4.6.6，而 `dsh-agents` 钉在 4.4.3，导致每个 projection schema 的 zod 类型身份被拆到两个 module 实例上。

## 决策

发布的 `dsh-v0.2.2-rc.2` tag 是适配基线，宿主与 workspace 同步移动：操作者把全局 CLI 升到 `@deepseek-ai/dsh@0.2.2-rc.2`，随后恢复 pin（`host sdk: … (0.2.2-rc.2, 336 packages)`、`check: ok (root exposes 336 packages, 223/223 workspace entries pinned, 37 host-absent left to pnpm)`）。

所有消费的 `@deepseek-ai/dsh*` 区间保留各自操作符移到 `0.2.2-rc.2`，`@deepseek-ai/cordis` 与 `@deepseek-ai/schemastery` 保持 4.1.0 与 3.19.0；队列的宿主 floor 各面同步移动：每个家族包与脚手架的 `dsh.engines.dsh >=0.2.2-rc.2` 及同一字面量的 `@deepseek-ai/dsh` 宿主 peer、两个根 README badge、全部 32 个包 README badge、CI 与 release 的 `DSH_CLI_VERSION`。workspace `overrides`（宿主从不安装的三个纯客户端包）、两个 `packageExtensions` 键、`minimumReleaseAgeExclude` 与 lockfile 在同一改动里移动。本仓没有 desktop runtime pin 这一面，属缺失而非未移动。

三处兼容改动同行：

- `@deepseek-ai/dsh-error@0.2.2-rc.2` 作为宿主面进入根 devDependencies，形状与 `dsh-sandbox` 相同：SDK 在模块顶层导入的必需 peer 由 workspace 承载，而不是走 `packageExtensions` 补丁。
- `dsh-agents` 与 `dsh-remote-web-ui` 把 `zod` 钉到 `4.6.6`，使 workspace 与 SDK 解析出同一份 zod。
- `dsh-agents` 自己提供 Team identity 的 prompt context 位置（`TEAM_IDENTITY_CONTEXT_ORDER = 125`，即 rc.1 中央表分配给该名字的槽位），identity 与 squad roster 两个 context 共用它，并删掉已无法作答的可选面 `SquadContextRegistry.getContextOrder`。

三个在用的契约做了 rc.2 实测复核而非假设：冻结的浏览器平台表逐字节相同（11 个 specifier、顺序一致），`dsh.client.inject` 并集仍是 16 个名字（rc.2 新增 `ui-agent-team` 与 `ui-account-notifications` 两条官方客户端行，本仓无包注入它们），`@deepseek-ai/dsh-client-locale` 的注册面未变（`lib/types` 声明一致；同样的重复 `(ns, locale)` 拒绝与幂等 disposer）。

## 原生优先的重叠盘点

rc.2 新增的官方能力与三处插件实现重叠。本次全部列为已登记例外，没有删除任何一处：每一处都需要重启后的 rc.2 宿主在真实 GUI 里验证官方替代品，而"去重不得带来能力回退"的规则高于去重本身。

- **AgentTeam 运行期**（`packages/dsh-agents/src/team/*`、`src/tools/*`）：rc.1 实验性 agent-team 的 fork。rc.2 把团队收回原生子代理（`ROOT_AGENT_NAME`、`listDescendants`、`rootOf`、`agent-team` 与 `tool-agent-team` roster 行），本包的 `profileMountsOfficialTeams` 已经会让位。决策：已登记例外。fork 承载官方没有的能力——squad 账本在子会话建立前把 preset、permission、model、reasoning effort 四个维度钉死，另有 10 个 `squads_*` 工具、`/state` 路由与有上限的运行历史。删除 fork 现在已是受控改动（删 fork、把 spawn 重新表达在 `subagents.startActivation` + `rootOf` 上），但必须是针对重启后宿主验证的独立改动。
- **团队界面**（`packages/dsh-agents/src/client/*`）：rc.2 的 `ui-agent-team` 行覆盖浏览与协调。决策：已登记例外，方向是改成只保留成员定义编辑与运行历史的薄扩展。
- **按语言渲染代码块**（`packages/dsh-diagrams/src/client/blocks.ts`）：rc.2 提供了我们没用的两条正规接缝——语言键控的 `conversation.chat.markdown.fence` 槽与 `MarkdownDelegate.renderCode`——而插件靠私有 DOM class 认领块，README 自己记着"渲染器改名即停"。决策：本队列记为已登记例外；迁移属可见 UI 改动，需要针对重启后宿主的 Before/After 证据。
- 无重叠：归档会话清理工作树（`dsh-session-archive` 只有归档账本与物理删除）、MCP 服务管理、网页搜索 provider、菜单与浮层定位（上游删掉了 `useAnchoredPosition`，本仓从未使用）、Gemini provider、账号通知、LiveShare、Office 工具与 Computer Use。

两处风险选择记录而非就地修复。其一，重启后的宿主上团队面会相撞：rc.2 在 `dsh-base` 里挂 `agent-team` 与 `tool-agent-team`、在 `dsh-web-app` 里挂 `ui-agent-team`，且都没有 `disabled` 标记，随附的官方替代默认是开的；官方 `agentTeam` projection 为 `stateVersion: 7`，它的 wire view 只带选中状态与任务面板，当前子代理另外走 `subagentCatalog`，而 fork 在同一 key 上注册的是 `stateVersion: 4`、把 roster 折进 view。我们的运行期在官方 bundle 在场时已经让位，但客户端只按 `agentTeam` 这个 key 读，重启后读到的是它没有为之编写的版本 7 状态，同时官方 `ui-agent-team` 自己占一个侧栏入口。其二，`dsh-plugin-manager` 的更新工具条与内置插件分组锚在官方 DOM 上，而 rc.2 给插件行加了新状态。两条都需要重启后的宿主来验证，是后续改动的第一项。

## 验证

最终提交在钉好的 rc.2 宿主树上通过：`pnpm typecheck`、`pnpm build`、`pnpm test`、`pnpm test:scripts`、`pnpm libs:check`、`pnpm runtime-deps:check`、`pnpm aggregate:check`、`pnpm docs:check`、`pnpm i18n:check`、`pnpm emoji:check`、`pnpm sync-shared:check`。`pnpm lint`（1239 problems）与 `pnpm test:standards`（同样的违例分组）在基线提交 `3c4ef05db` 上以完全相同的方式失败，属继承失败而非本次引入。

队列的 GUI 验收等操作者重启宿主：本会话不得重启正在运行的服务。已提交的挂载冒烟（`pnpm test:mount`）用 rc.2 CLI 把打包后的聚合包挂进 scratch profile 并做无头 Chromium 渲染，是不触碰在跑宿主的前提下能拿到的 rc.2 证据。

## 被否决的替代方案

只升 workspace 清单被否决：pin 是经宿主安装树解析 SDK 的，rc.2 workspace 配 rc.1 宿主的 module 身份分裂与阴影副本是同一类故障。只升宿主被否决，镜像理由：floor 会落后于插件实际运行的宿主。rc.2 已在 registry 上就删掉 workspace `overrides` 被否决：那三个纯客户端包是宿主从不安装的构建输入，override 正是把它们锁在同一队列的东西。把 `getContextOrder('TEAM_IDENTITY')` 垫回 125 也被否决，选择让插件自持这个数字：宿主已不再为该名字作答，垫片只会让一个在每个 rc.2 宿主上都返回 `undefined` 的调用继续存在。
