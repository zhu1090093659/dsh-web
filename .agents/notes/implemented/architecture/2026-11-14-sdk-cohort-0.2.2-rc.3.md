# Agent Note: SDK cohort 0.2.2-rc.3

Status: implemented

Partially supersedes [2026-11-12 SDK cohort 0.2.2-rc.2](2026-11-12-sdk-cohort-0.2.2-rc.2.md) on the SDK baseline pin, the web authentication bridges, and the official bundle snapshot.

## Problem

The `@deepseek-ai/dsh*` packages on npm advanced to `0.2.2-rc.3` while local DeepSeek Harness checkouts (`C:\Users\A\Documents\deepseek-harness` at `master` `39163dd30f`) also landed breaking authentication and bundle updates (`#8266` and `#6858`) that are not yet published in the `0.2.2-rc.3` tarball:

- `dsh-client-connection@0.2.2-rc.3` still types `authenticatedUrl` and `requestRejection` without `admit`, whereas host `master` replaces those members with peer admission (`admit`) and emits `'webserver/entry-url'` on `webServer`.
- `dsh-host-webserver@0.2.2-rc.3` does not declare `auth` on `WebRoute`, whereas host `master` defaults routes to `auth: 'required'` unless self-fenced routes declare `auth: 'anonymous'`.
- `dsh-plugin-manager` bundle snapshots need to reflect `authentication-token` (from `0.2.2-rc.3`) and `ui-session-status` (`#6858`).

## Decision

Upgrade the repository SDK baseline across package manifests, workspace configuration, build/release workflows, tests, and documentation to `@deepseek-ai/dsh@0.2.2-rc.3` using the npm registry fallback, while keeping all package TypeScript builds decoupled from local DSH source checkouts. Add narrow dual-cohort runtime bridges so every affected plugin compiles against `0.2.2-rc.3` types and runs cleanly under both `0.2.2-rc.3` and post-`#8266` host checkouts.

## Dual-cohort authentication bridges

1. Startup authenticated URL resolution adds `resolveAuthenticatedUrl` in `packages/dsh-browser-view/src/index.ts` and `resolveLaunchTokenUrl` in `packages/dsh-remote-web-ui/src/index.ts`: both prefer `connection.authenticatedUrl?.(url)` when available and otherwise resolve `webServer` (`ctx.webServer ?? ctx.get('webServer')`) to emit `'webserver/entry-url'`, picking the first entry with `open === true` or falling back to the first non-empty `url`.
2. Inbound connection admission extends `HostConnectionService` in `packages/dsh-skill-explorer/src/access.ts` and `TaskBoardConnectionTrust` in `packages/dsh-task-board/src/host-routes.ts` / `packages/dsh-task-board/src/index.ts` with optional `admit?`, trying `admit` before falling back to `requestRejection`.
3. Self-fenced routes attach `auth: 'anonymous'` across `dsh-remote-bridge`, `dsh-remote-web-ui`, `dsh-task-board`, `dsh-skill-explorer`, `dsh-diagrams`, `dsh-usage`, and `packages/dsh-web-all/src/shell.ts` so they remain reachable when host `WebServer` enforces `auth: 'required'` by default.
4. Official bundle row ID coverage in `packages/dsh-plugin-manager/tests/bundle-row-id.spec.ts` adds `'authentication-token'` and `'ui-session-status'` in alphabetical order.

## Alternatives considered

- Point TypeScript or workspace dependencies directly at the local `deepseek-harness` checkout: rejected because repository rules forbid coupling `tsconfig` or packages to a local DSH checkout and the npm cohort remains `0.2.2-rc.3`.
- Drop support for `0.2.2-rc.3` `authenticatedUrl` and `requestRejection`: rejected because CI and clean installs resolve against `@deepseek-ai/dsh@0.2.2-rc.3` from npm.
- Add bridge abstractions outside plugins rather than local structural checks: rejected because structural optional members keep bundle sizes minimal and remain trivial to delete once `#8266` is published.

## Consequences

- Packages typecheck, build, and pass BDD unit tests against `0.2.2-rc.3` without touching host DSH source files or global user profiles.
- Committed build outputs in `packages/dsh-market/lib` and `packages/dsh-web-all/lib` and `scripts/lib-artifact-fingerprints.json` stay synchronized with the `0.2.2-rc.3` and dual-cohort bridge edits.
- Pre-existing unrelated issues observed during verification remain out of scope: three `no-unused-vars` lint errors in `packages/dsh-agents/src/host/run-gateway.ts`, Windows-specific script test cases (`scripts/deploy-market.test.mjs` and `scripts/git-pre-push-gitlinks.test.mjs`), and one pre-existing failing case in `packages/dsh-win-bash/tests/shell.spec.ts`.
