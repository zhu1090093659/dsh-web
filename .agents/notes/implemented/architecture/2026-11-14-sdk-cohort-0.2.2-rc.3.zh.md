# Agent Note: SDK cohort 0.2.2-rc.3

Status: implemented

本笔记在 SDK 基线锁定、Web 认证桥接与官方插件快照方面部分取代 [2026-11-12 SDK cohort 0.2.2-rc.2](2026-11-12-sdk-cohort-0.2.2-rc.2.zh.md)。

## 问题

npm 上的 `@deepseek-ai/dsh*` 套件已推进至 `0.2.2-rc.3`，而本机 DeepSeek Harness 源码检出（`C:\Users\A\Documents\deepseek-harness` 的 `master` 提交 `39163dd30f`）同时合入了尚未发布进 `0.2.2-rc.3` tarball 的认证与内置包变更（`#8266` 与 `#6858`）：

- `dsh-client-connection@0.2.2-rc.3` 仍只声明 `authenticatedUrl` 与 `requestRejection` 而未包含 `admit`，但宿主 `master` 已将这两个成员替换为基于 Peer 的准入检查（`admit`），并改由 `webServer` 触发 `'webserver/entry-url'`。
- `dsh-host-webserver@0.2.2-rc.3` 的 `WebRoute` 尚未声明 `auth` 字段，但宿主 `master` 默认要求路由具备 `auth: 'required'`，因此自带安全围栏的路由需要显式声明 `auth: 'anonymous'`。
- `dsh-plugin-manager` 的内置行快照测试需要同步纳管 `0.2.2-rc.3` 新增的 `authentication-token` 与 `#6858` 引入的 `ui-session-status`。

## 决策

将仓库各包清单、工作区配置、构建与发布工作流、测试夹具及文档中的 SDK 基线统一升级至 npm registry 的 `@deepseek-ai/dsh@0.2.2-rc.3`，保持 TypeScript 构建完全独立于本地 DSH 源码检出；同时在受影响插件内实现窄范围的双队列运行时桥接，使代码既能通过 `0.2.2-rc.3` 类型检查，又能在 `0.2.2-rc.3` 与合入 `#8266` 的本机宿主运行时下正常执行。

## 双队列认证桥接

1. 启动认证 URL 解析在 `packages/dsh-browser-view/src/index.ts` 中新增 `resolveAuthenticatedUrl`，并在 `packages/dsh-remote-web-ui/src/index.ts` 中新增 `resolveLaunchTokenUrl`：两者均优先调用 `connection.authenticatedUrl?.(url)`，缺席时通过 `ctx.webServer ?? ctx.get('webServer')` 触发 `'webserver/entry-url'`，优先选取 `open === true` 条目并回退至首个非空 `url`。
2. 入站连接准入判定扩展了 `packages/dsh-skill-explorer/src/access.ts` 中的 `HostConnectionService` 与 `packages/dsh-task-board/src/host-routes.ts` / `packages/dsh-task-board/src/index.ts` 中的 `TaskBoardConnectionTrust`，均增加可选 `admit?`，优先调用 `admit` 再回退至 `requestRejection`。由于 `admit` 会沿**调用方 fiber** 解析 `connection.authentication`，两个插件都在 `ctx.inject(['connection', 'connection.authentication'], …)` 作用域内捕获该服务，并保留裸 `ctx.get('connection')` 回退；桥接抛错一律按「无裁决」处理，交由原有的回环 / 已配对围栏决定，而不是让请求以宿主 400 逃逸（本队列首个版本未做注入，post-#8266 宿主上任务看板全部路由因此只回 400 空体）。
3. 自带访问控制的路由为 `dsh-remote-bridge`、`dsh-remote-web-ui`、`dsh-task-board`、`dsh-skill-explorer`、`dsh-diagrams`、`dsh-usage` 以及 `packages/dsh-web-all/src/shell.ts` 补齐 `auth: 'anonymous'`，确保宿主 `WebServer` 默认启用 `auth: 'required'` 时这些自围栏路由依然可达。
4. 官方内置包行 ID 测试 `packages/dsh-plugin-manager/tests/bundle-row-id.spec.ts` 按字母序新增 `'authentication-token'` 与 `'ui-session-status'`。

## 被否决的替代方案

- 让 TypeScript 或工作区依赖直接指向本地 `deepseek-harness` 检出：因违反仓库不耦合本地 DSH 源码检出的规则且 npm 发布的官方队列仍为 `0.2.2-rc.3` 而被否决。
- 直接移除对 `0.2.2-rc.3` `authenticatedUrl` 与 `requestRejection` 的支持：因 CI 与干净检出环境依赖 npm 上的 `@deepseek-ai/dsh@0.2.2-rc.3` 而被否决。
- 在插件外部另设集中兼容层而非采用局部结构化类型探测：因局部可选字段扩展体积最小，且待 `#8266` 正式发包后更易清理而被否决。

## 后果

- 全部工作区子项目可在 `0.2.2-rc.3` 下通过类型检查、构建与 BDD 单元测试，未触碰宿主 DSH 源码或用户全局 profile。
- `packages/dsh-market/lib`、`packages/dsh-web-all/lib` 以及 `scripts/lib-artifact-fingerprints.json` 已随 `0.2.2-rc.3` 升级与双队列桥接同步重建并锁定指纹。
- 验证过程中观察到的既有无关问题保持不动，超出本次变更范围：`packages/dsh-agents/src/host/run-gateway.ts` 中的三处预存 `no-unused-vars` lint 错误，`scripts/deploy-market.test.mjs`、`scripts/git-pre-push-gitlinks.test.mjs` 中依赖 POSIX 权限或句柄行为的 Windows 环境失败，以及 `packages/dsh-win-bash/tests/shell.spec.ts` 中的一处预存失败用例。
