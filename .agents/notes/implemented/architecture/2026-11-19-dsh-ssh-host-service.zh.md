# Agent Note: dsh-ssh 向同级插件发布宿主服务

Status: implemented

本笔记实现[任务看板 SSH 提供方方案](../../proposed/feature/2026-11-19-task-board-ssh-remote-execution.md)的 Seam 1。促成它的消费方——把看板卡片放到远端主机上执行的提供方——经该服务到达主机；看板那一侧是[任务看板外部提供方扩展契约](2026-09-30-task-board-extension-contract.md)。

## Problem

`dsh-ssh` 持有进程内全部 SSH 能力，却不向任何插件提供：`apply` 注入 `webServer`、`tools` 与 `systemPrompt`，自己什么都不 provide。另一个插件若想执行命令、搬运文件或读取用户的主机清单，只有三条坏路：import 本包内部实现（家族规则封死的跨包耦合）；自建第二个连接池并第二次读取 `~/.dsh/dsh-ssh.json`（一份清单两个事实源、内存里两套凭据，且一处编辑的主机在另一处保持陈旧）；或调起 `ssh(1)`，但那既不共享已存凭据，也不共享用户配置的跳板机与 ProxyCommand 链路。

方案恰好需要一个这样的消费方：在远端主机上启动智能体、把 git bundle 送过去、再把日志读回来的看板提供方。把服务面收窄到该消费方，等于把提供方词汇塞进 `dsh-ssh`；干脆不做，则每个后来的消费方都会重犯第二个连接池的错误。

## Decision

宿主半区发布一个 cordis 服务 `dshSsh`，版本常量 `DSH_SSH_API_VERSION = 1`。它是路由、Web 终端、`ssh_*` 工具与面板本来就共用的那一个 `SshEngine` 实例的薄转发。

1. **服务面**：`apiVersion`、`hosts.list()`、`hosts.find(alias)`、`exec(alias, command, { timeoutMs, signal })`、`upload(alias, localPath, remotePath)`、`download(alias, remotePath, localPath)`。`exec` 用一个 options 对象承载上限与取消（引擎自身是位置参数），其余成员逐个参数等价于引擎方法。任何成员都不带逻辑——无门禁、无缓存、无状态——因此拒绝消费方的正是拒绝 GUI 与工具的同一套东西，一次设置编辑同时到达它们全部。
2. **契约文件**：`packages/dsh-ssh/src/service.ts` 承载服务名、版本常量、全部类型与 `declare module` 增强，且不 import 任何东西。消费方包逐字同形重述它并在运行时按名字取值，于是两个包共享一种形状而不共享模块——与看板提供方契约的方向相反、做法相同。
3. **不交出机密的投影**：`hosts.*` 返回 `SshHostSummary` 已公开的字段，去掉 `proxyCommand`。该值是宿主进程以自身权限执行的 shell 命令（agent 工具出于同一理由把它投影成布尔），而密码、密钥口令、私钥路径与 agent 端点根本不进入该形状。
4. **没有流式成员**：促成它的消费方必须在本机离线之后回放日志，而这只可能来自它经 `exec` 按字节偏移读取的远端文件。流式 exec 为了回答同一个问题还得缓冲、落盘再重发同一批字节，因此服务面保持「轮询 + 偏移」。
5. **生命周期**：`ctx.provide` 在 `sync()` 里执行，与路由、工具、提示词段落同批；每次重新推导时它的 disposer 先于它们运行。因此服务恰好只在总开关打开期间存在：关掉开关或卸载插件都会 unprovide，而 cordis 会先把每个依赖方的 inject 作用域卸载，之后本实例才会注册别的东西。手工搭的、没有 cordis 注册表的上下文（设置面测试、降级挂载）照常服务自己的面，只是不 provide 该服务。
6. **所有消费方同一个面**：插件不认识任何提供方词汇，消费方也无法在其中注册特例。

## Context & Efficiency Impact

该服务面新增一个 import-free 类型模块、一个五行转发的工厂和一个 disposer 变量。没有消费方注入时它不产生任何成本：没有定时器、没有路由、没有工具、没有提示词文本。而消费方省掉的是每台主机第二个连接池与第二次凭据文件读取——正是它所替代的方案。

## Alternatives considered

**让消费方直接 import `SshEngine` 与 `HostStore`。** 否决：这是跨包边界上的值导入，家族规则本就封死；它会把引擎构造函数形状钉成对外契约；还会让消费方在用户关掉插件之后照样动作。

**发布原始 `SshHostSummary`，含 ProxyCommand。** 否决：该文本是宿主进程以其权限执行的 shell 命令，从不执行它的消费方没有任何用处。投影本身就是边界，因此公开类型里根本不出现 `proxyCommand` 成员，而不是写一个「仅供内部使用」的成员。

**无条件注册服务，与总开关解耦。** 否决：一个仍能 exec 的「已停用」插件让开关变成谎言——用户关掉 SSH，另一个插件照样在他的服务器上执行命令。服务就是该开关管辖的又一个面。

**按能力拆成更窄的多个服务（主机清单服务 + exec 服务）。** 否决：两个 provision 点要挂在同一条生命周期上，两个版本要维护，而同时需要两者的消费方得注入两次。一个五成员的面比两个面更小。

**顺带暴露终端、隧道、集群执行、目录浏览与传输进度。** 否决：促成它的消费方只需要命令、传输与清单，而每一个多出来的成员都会变成将来删不掉的契约。

## Consequences

- **同级插件现在可以在用户的主机上执行命令。** 信任边界是宿主进程：装载进去的任何插件都以与 `ssh_*` 工具相同的可达范围触达每台已配置主机，且没有按消费方分级。包 `AGENTS.md` 与中英 README 都写明了这一点。
- **总开关现在会卸载依赖方。** 关掉 SSH 会在会话中途释放消费方的 inject 作用域，因此消费方必须按「可加载、可卸载」来写，而不是在激活时一次性解析服务面；它必须把「没有服务」当作「我什么都不跑」。
- **契约是兼容面。** 同一版本下新增成员属增量；修改或删除成员需要新的 `DSH_SSH_API_VERSION` 与消费方侧的检查，因为消费方重述类型，本包的编辑不会在它的编译器上报错。
- **`upload` 只搬一个文件。** 递归目录遍历、进度流与暂存文件生命周期留在插件自己的路由与工具里；目录会被引擎拒绝，而不是被悄悄遍历。
- **覆盖**：`packages/dsh-ssh/tests/service.test.ts` 驱动真实的 cordis 注册表。以 `ctx.inject(['dshSsh'], ...)` 挂载的依赖方读取清单、在内嵌 ssh2 服务端上执行命令、在真实 sshd 上上传读取下载，并在两个方向上失去服务（总开关、卸载）。逐字段用例钉住投影：精确的公开键集、任何私有字段都不存在、序列化后的服务面里没有任何机密或 ProxyCommand 原文，而 store 自己的投影仍然带着那段文本。
