# Agent Note: SDK cohort 0.2.3-alpha.2

Status: implemented

本笔记在 SDK 基线队列锁定、Node.js 运行时下限、客户端样式生命周期、官方内置包快照、Markdown 围栏类名契约以及子代理路由策略读取方面部分取代 [2026-11-14 SDK cohort 0.2.2-rc.3](2026-11-14-sdk-cohort-0.2.2-rc.3.zh.md)。

## 问题

上游 `@deepseek-ai/dsh` 推进至 `0.2.3-alpha.2`，在将宿主 Node.js 下限抬升至 `^24.22.3 || >=26.13.1` 的同时，在五项仓库契约上带来了运行时、构建与内置行清单变化：

- 官方 UI 渲染器 `0.2.3-alpha.2` 将包体内直接写入 DOM `<style>` 替换为 `DocumentStyles`，通过 `window.__ModuleLoader__.load({ id, factory, meta })` 读取延迟声明的 `meta: () => ({ stylesheets })`（`@deepseek-ai/dsh-client-ui-renderer`）。
- 上游从 `dsh-web-app` 移除了 `ui-settings-plugins` 与 `ui-settings-plugin-inventory`；若在 `dsh-plugin-manager`（及聚合包 `dsh-web-all`）保留裸补丁行 `- id: ui-settings-plugins`（`disabled: true`），启动时会触发 `patch: entry "ui-settings-plugins" not found` 告警。
- 上游将 CSS Modules 生成模式改为无尾随下划线的 `[hash]_[local]`，导致 `dsh-diagrams` 的 `_infostring_` 与 `_language_` 子串匹配失效。
- 上游停止向会话日志写入 `subagent/model-selection-policy` 事件，改为暴露 `ctx.get('subagentModelSelection').allowedRoutes()` 实时服务，使 `dsh-liangshen` 的 `subagent-routes` 预设守卫在实时配置变更或清空时读不到最新策略。
- Node.js `v26.13.1` 在未传入 `--localstorage-file` 时暴露了返回 `undefined` 的可配置 `globalThis.localStorage` getter，使未接 `shared/vitest.setup.ts` 的 jsdom 测试套（`dsh-plugin-manager`）运行失败。

## 决策

全仓 SDK 基线、宿主版本下限（`>=0.2.3-alpha.2`）、Node.js 版本要求（`^24.22.3 || >=26.13.1`）、`@deepseek-ai/cordis`（`~4.2.0-alpha.1`）、`@deepseek-ai/schemastery`（`~3.20.0-alpha.1`）、CI 与发布钉版、工作区 overrides、README 徽章及根 lockfile 统一升级至 `@deepseek-ai/dsh@0.2.3-alpha.2`（`host-sdk:check` 将 216/216 个工作区依赖全部钉住至 349 包的宿主安装树）。家族 `@linxin666/*` 版本保持 `0.4.21` 不变，四个卫星仓库及其固定提交均不作改动。

## 兼容适配与官方契约采用

- **采用官方 `DocumentStyles` 样式表契约（`shared/tsdown.client.ts`）**：`dsh-css-modules-inline` 使用 `[hash]_[local]` 确定性编译每个 `.module.css` 文件并按仓库相对路径键入内存映射（`moduleSideEffects: 'no-treeshake'`），通过 `outputOptions.footer(chunk)` 发出 `meta: () => ({ stylesheets: { [fileId]: { text: () => css } } })`，不再在 `factory` 内手动插入 `<style data-plugin-css>` 标签。`packages/dsh-remote-web-ui/src/client/mobile-adapt.ts` 的运行时动态适配样式不经过 CSS Modules，保持原样。
- **移除已退役的 `ui-settings-plugins` 覆盖行（`packages/dsh-plugin-manager`、`packages/dsh-web-all`、`scripts/aggregate.mjs`）**：从 `packages/dsh-plugin-manager/cordis.patch.yml` 删除裸补丁行 `- id: ui-settings-plugins`，运行 `node scripts/aggregate.mjs` 刷新 `packages/dsh-web-all/cordis.patch.yml`。按 `0.2.3-alpha.2` 的 `dsh-base` 与 `dsh-web-app` 将 `packages/dsh-plugin-manager/tests/bundle-row-id.spec.ts` 中的 `OFFICIAL_ROW_IDS` 刷新为 211 个唯一行 id，更新 `scripts/aggregate.test.mjs` 以合成临时目录覆盖裸补丁行转发逻辑并断言 `ui-settings-plugins` 持续缺席，并在 `packages/dsh-plugin-manager/vitest.config.ts` 接入 `../../shared/vitest.setup.ts` 使 Node 26 jsdom 用例获得 `MemoryStorage`。
- **更新 CSS Modules 类名片段（`packages/dsh-diagrams`）**：将 `packages/dsh-diagrams/src/core/contract.ts` 中的 `INFOSTRING_CLASS_FRAGMENT` 与 `LANGUAGE_CLASS_FRAGMENT` 分别改为 `'_infostring'` 与 `'_language'`，同时兼容旧版 `_<local>_<hash>` 与 `0.2.3-alpha.2` `<hash>_<local>` 类名。
- **接入实时 `subagentModelSelection` 服务（`packages/dsh-liangshen`）**：`presets/liangshen/subagent-routes.mjs` 保持 `inject = ['tools']`，在每次被守卫的委派调用时实时读取 `ctx.get('subagentModelSelection')`。服务挂载时以其 `allowedRoutes()` 返回为准（返回 `undefined` 直接放行、不回退旧会话事件；抛错则 fail-open 以便宿主配置报错透出）；仅当服务未挂载时才回退扫描 `subagent/model-selection-policy` 事件。
- **工作区扩展与冷却豁免对账（`pnpm-workspace.yaml`）**：将 `overrides` 与 `packageExtensions` 键移至 `0.2.3-alpha.2`（为 `@deepseek-ai/dsh-client-ui-primitives` 补上 `@deepseek-ai/dsh-util-file-drag: 0.2.3-alpha.2` 及匹配 `0.2.3-alpha.2` 的传递依赖区间），并将 `minimumReleaseAgeExclude` 与 lockfile 实际解析出的 60 个 `@deepseek-ai/*` 条目逐一对账（保留未改版卫星包解析出的 `cosmokit@1.9.0` 与 `schemastery@3.19.0`，清理无效旧条目）。

## 原生优先的重叠盘点

- **将 `packages/dsh-remote-web-ui` 作为已登记例外保留**：官方 `dsh-client-remote-connection` 仅承担二维码/链接生成与设备配对，不包含监听地址控制、cloudflared 隧道以及局域网 HTTP/WebSocket 转发器，且 `dsh-remote-web-ui` 已不在 `dsh-web-all` 聚合范围内。若强行替换为 `remote-connection` 会直接丢失既有远程访问能力，因此 `dsh-remote-web-ui` 作为独立包保留，继续复用 `0.2.3-alpha.2` 原生准入与入口接缝（`admit`、`webserver/entry-url`、`WebRoute.auth`）。
- **移除插件自建的 CSS-module DOM 注入**：用官方 `DocumentStyles` 的 `meta().stylesheets` 管线取代 `shared/tsdown.client.ts` 中内联的 `<style data-plugin-css>` 注入代码，将样式去重、排序与卸载清理权交还官方渲染器。

## 被否决的替代方案

- 在 `shared/tsdown.client.ts` 中继续保留手工 `<style data-plugin-css>` 注入器而不迁移至 `meta().stylesheets`：因官方 `DocumentStyles` 已按 `[data-plugin][data-path]` 接管去重、排序与热卸载清理，继续保留手工注入等于在渲染器之外维持重复样式生命周期而被否决。
- 在 `packages/dsh-liangshen/presets/liangshen/subagent-routes.mjs` 将 `subagentModelSelection` 加入 `export const inject`：因对可选宿主服务做强注入会导致缺少 `subagent-model-selection-settings` 的精简宿主或测试组合无法挂载该预设行而被否决。
- 在本次变更内同步升版 `@linxin666/*` 或改动四个卫星仓库：按明确授权范围保持卫星仓库与当前发布版本号 `0.4.21` 不变，待后续统一发版周期处理。

## 后果

- 已提交产物（`packages/dsh-market/lib`、`packages/dsh-web-all/lib`）与 `scripts/lib-artifact-fingerprints.json` 已切换为 `0.2.3-alpha.2` 构建并输出 `meta().stylesheets`，且 `factory` 执行期间不再写入 `document.head`。
- 本机全局 `dsh --version` 与工作区 `node_modules/@deepseek-ai` 已统一在 Node.js `v26.13.1` 与 `@deepseek-ai/dsh@0.2.3-alpha.2` 上；既有在跑的 `dsh-web.service` 及其 `~/.dsh/profiles/web` 需在本次会话之外由操作者重启服务并重装刷新后生效。
- 操作者主检出中原有的 `M satellites/dsh-community-plugins` 与全部四个卫星仓库均保持原样未受干扰。
