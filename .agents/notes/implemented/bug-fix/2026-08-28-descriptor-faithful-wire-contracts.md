# Agent Note: descriptor-faithful 0.1.2 wire contracts after review

Status: implemented

## Problem

A findings-first review of the 0.1.2-alpha.1 migration (evidence archived in docs/archive/2026-09-remote-web-ui-sdk-0.1.2-review-notes.md) proved that several call sites encoded wire contracts the generated descriptor tables do not have, and that the test doubles shared the same wrong assumptions, so every gate was green over silently broken paths: session/list was invoked with args {request} although its single parameter wires as _request (task-board settlement loop dead, phone session list dead); directoryPicker/list was sent {request: body} although it declares one flat optional path (phone browsing dead); business error codes were read from error.code although TypertRemoteFailure carries them on error.failure (paired-model-catalog answered 502 instead of 409/422); CardForm.save() treated a resolved scope.mutate as success although the 0.1.2 scope resolves after a recovery reload on refusal (refused saves dropped user drafts); git-graph assumed ISessions.create navigates although only open() selects (worktree session created invisibly); and the phone's history paging repeated one page because beforeSeq never advanced.

## Decision

Every fixed call site now keys its gateway args off the descriptor wire layout, and the test fakes encode the same descriptor tables so drift fails the suite: dsh-task-board and dsh-remote-web-ui route invokes through an invokeWireArgs() helper (session/list -> { _request }, directoryPicker/list -> flat optional path, agentPresets/list and session/modelCatalog -> {}, everything else -> { request }), and the fakes (packages/dsh-remote-web-ui/tests/wire-gateway.ts, the task-board host-runner fakes) reject extra/missing keys exactly like the gateway's assertExactArguments. The remote-web-ui BFF extracts business failures from error.failure before falling back to error.code, and paired-model-catalog maps the real wire codes (settings-conflict -> 409, settings-rejected -> 422) instead of message regexes. CardForm.save() keeps the single atomic mutate but judges the outcome by reading the settled snapshot back per planned write (set: the user layer holds the value; unset: the field is gone; one miss fails the whole save and keeps the drafts), while still catching rejections from the bridge scope. git-graph opens the SessionId that create() resolves. The phone's sessionHistory pages backward by advancing beforeSeq to the oldest accumulated seq, dedupes by seq, answers in ascending order, and passes the opening projections baseline through; session.list rows carry projections again and session/models maps the catalog's default onto current.

## Alternatives considered

Keying invoke args off a locally vendored copy of the descriptor tables at runtime was rejected: the descriptors are generated artifacts of the SDK packages, and reading them at runtime would couple plugin boot to SDK internals the inject contract deliberately hides; a transcribed constant plus descriptor-faithful fakes catches drift at test time instead. A revision-bump heuristic for judging secret writes was rejected because dsh-settings only bumps the revision when the raw section changed, so re-typing an identical secret would misreport success as failure; secret sets are judged by settlement (documented in the code). Restoring per-field set/unset writes instead of read-back judgment was rejected because it abandons the atomic cross-field validation the 0.1.2 mutate contract provides.

## Consequences

Wire-contract drift is now a test-failing event in both gateway-consuming packages, and the new diagnostics in task-board log swallowed gateway throws instead of staying silent. A save batch consisting only of secret sets still cannot detect a Host refusal, because the Host strips role('secret') fields from every wire view layer and the snapshot exposes no secrets sidecar; fixing that needs an upstream SDK change. The phone-facing fixes take effect only after the rebuilt bundle is served (DSH restart). The full review evidence lives in docs/archive/2026-09-remote-web-ui-sdk-0.1.2-review-notes.md.
