# Agent Note: Desktop Launcher Automatic Browser Launch Reliability

Status: implemented

## Problem

When starting DSH via the Windows desktop shortcut generated by `dsh-desktop-launcher`, the browser failed to open automatically:
1. The shortcut launched PowerShell with `-WindowStyle Hidden`. Directly invoking `Start-Process $url` inside a hidden PowerShell process caused `ShellExecuteEx` to inherit `SW_HIDE`, silently launching the browser in hidden/background mode if it was not already running, or failing to bring it to the foreground due to Windows Foreground Lock Timeout restrictions. Immediately exiting PowerShell with `exit 0` also interrupted Shell IPC handoffs.
2. In Windows PowerShell 5.1, `Invoke-WebRequest` threw a `WebException` on non-2xx/3xx HTTP responses (e.g. 401/403 security fence gates), causing `Test-DshUrl` to return `$false` and spin until timing out after 60 seconds without triggering browser opening.
3. If DSH failed or exited early during startup, the launcher did not inspect the process status and waited 60 seconds before showing a generic timeout.

## Decision

1. In `packages/dsh-desktop-launcher/src/core/launcher.ts`:
   - Introduced `Open-DshUrl` in PowerShell launchers: uses `Start-Process -FilePath 'explorer.exe' -ArgumentList $url` to delegate URL launching to the top-level Windows Explorer shell, ensuring the default browser opens in a normal foreground window (`SW_SHOWNORMAL`). Falls back to `Start-Process -FilePath $url` on error.
   - Enhanced `Test-DshUrl` exception handling in PowerShell to inspect `$_.Exception.Response.StatusCode`, accepting any HTTP response in 200..499 as an active server signal.
   - Captured the background DSH process via `-PassThru` and checked `$dshProcess.HasExited` in the polling loop to promptly display process termination errors.
   - Added process liveness checking (`kill -0 "$DASH_PID"`) in POSIX launchers.
2. Updated unit test assertions in `packages/dsh-desktop-launcher/tests/launcher.spec.ts`.

## Consequences

- Desktop shortcuts now reliably open the default browser in a visible foreground window upon DSH readiness on Windows.
- Server readiness probing withstands HTTP 4xx response codes.
- Crashed or failed DSH launches fail fast with descriptive error popups rather than hanging for 60 seconds.
