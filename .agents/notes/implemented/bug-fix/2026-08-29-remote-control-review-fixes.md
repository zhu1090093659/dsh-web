# Review-driven hardening round for dsh-remote-web-ui 0.4.0

A findings-first review of the official-UI adaptation refactor (commits e39330b9d + 702051bfe) surfaced three high-severity gaps and a set of medium/low defects; all are fixed in this change and every fix carries a test.

**The remote channel now carries the process's own browser credential.** The review proved empirically that on the pinned 0.1.2-alpha.1 line the harness browser-auth cookie is authority-bound with no loopback exemption, so every proxied `/api` call through `/remote` answered 401 — a paired phone paired successfully and then loaded no data (the earlier QA round had verified only the chrome layer). The fix (`src/inner-auth.ts`) redeems the process's own launch token once — the same exchange a first browser visit performs — and attaches the resulting cookie to re-issued requests, invalidating and re-redeeming after an upstream 401. The credential is exercised only behind the pairing gate, so stop()/revoke() keep their teeth on the channel.

**The revocation story is now stated honestly.** Nothing in the 0.1.2-alpha.1 runtime emits the `api/gate` seam this plugin subscribes to, so direct `/api` from a LAN origin is governed solely by the harness fence (which auto-trusts LAN literals under a 0.0.0.0 bind) plus the harness browser-auth cookie — a browser credential a device has already redeemed survives stop() until its 30-day natural expiry. This is documented as a first-class paragraph in both README security models, backed by a boot-time console warning on a LAN-exposed bind. The listener stays wired for cohort lines that do carry the seam.

**Install-path and hygiene fixes**: the prepare build still bundled the deleted `src/mobile/index.tsx` (every git install failed; fixed by mirroring `tsdown.config.ts`); the firewall status probes were locale-trust bugs (netsh exits 0 on "no rules match", now matched against the echoed rule name in verbose output; the ufw regex is anchored so 1443/tcp cannot satisfy a 443 probe); `firewallSummary` is TTL-memoized (30 s) and the sync path re-applies the rule only when the toggle or port actually moved, instead of spawning delete+add on every settings save; the lan-bind `profile` value is schema-constrained and path-contained; the patch rewrite uses a unique temp name, preserves the original file mode, and truncates a hand-truncated unterminated block instead of stacking a second webserver row; `pendingRestart` now compares the effective desired host (CLI flags win) instead of the raw toggle; the accept rate limiter honors XFF only for loopback peers (a direct LAN client cannot mint buckets by header rotation) and splits the page and API buckets; the adaptation layer honors the plugin master switch, pauses its 600 ms tick on hidden pages, clamps a restored whale position into the viewport (a test also exposed that the stored position was never restored on the first show — the CSS-read guard could not fire on a fresh page load), and treats IME keyCode 229 as composition rather than a newline.
