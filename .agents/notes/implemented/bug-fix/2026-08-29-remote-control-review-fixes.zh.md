# dsh-remote-web-ui 0.4.0 的审查强化轮

对官方界面适配重构（e39330b9d + 702051bfe）的发现先行审查暴露了三个高危缺口与一批中低级缺陷；本次改动全部修复，且每个修复都带测试。

**远程通道现在携带进程自己的浏览器凭据。** 审查实证：在锚定的 0.1.2-alpha.1 线上，harness 浏览器认证 cookie 与 authority 绑定且无回环豁免，因此经 `/remote` 转发的每个 `/api` 调用都拿到 401——配对手机配对成功却加载不出任何数据（早前的 QA 只验证了外观层）。修复（`src/inner-auth.ts`）由进程自行兑换一次启动令牌——与浏览器首次访问执行的是同一次交换——并把所得 cookie 附到再发起请求上，上游 401 后作废并重新兑换。该凭据只在配对门之后被使用，所以停止/撤销在通道上的牙齿保留。

**撤销语义现在被如实陈述。** 0.1.2-alpha.1 运行时没有任何组件发出本插件订阅的 `api/gate` seam，因此局域网源头的直连 `/api` 仅由 harness 围栏（0.0.0.0 绑定下自动信任局域网字面量）加 harness 浏览器认证 cookie 约束——设备已兑换的浏览器凭据在停止后仍有效至 30 天自然过期。双语文档的安全模型都以一级段落写明这一点，并以局域网暴露绑定时启动阶段的 console 告警兜底。监听器保持挂载，供未来携带该 seam 的 cohort 免费获得直连 `/api` 的配对强制。

**安装路径与卫生类修复**：prepare 构建仍在打包已删除的 `src/mobile/index.tsx`（一切 git 安装失败；镜像 `tsdown.config.ts` 修复）；防火墙状态探测是本地化信任缺陷（netsh 对「无匹配规则」也退出 0，现在改为在 verbose 输出中匹配回显的规则名；ufw 正则锚定，1443/tcp 不再满足 443 的探测）；`firewallSummary` 做 30 秒 TTL 记忆化，sync 路径仅在开关或端口真正移动时才重建规则，不再每次设置保存都 delete+add；lan-bind 的 `profile` 值受 schema 约束并做路径包含检查；补丁重写改用唯一临时名、保留原文件权限，并把手工截断的未终止块从 BEGIN 处截断而不是堆叠第二个 webserver 行；`pendingRestart` 现在比较生效期望绑定（CLI 旗标优先）而非裸开关；accept 限流只对回环对端信任 XFF（直连局域网客户端无法靠轮换头部铸造新桶），并把页面桶与 API 桶分开计数；适配层尊重插件总开关、在页面隐藏时暂停 600ms tick、把恢复的鲸鱼位置夹取回视口内（测试还暴露出存储位置从未在首次显示时被恢复——CSS 读取型守卫在全新页面加载上不可能触发），并把 IME keyCode 229 视为组合输入而非换行。
