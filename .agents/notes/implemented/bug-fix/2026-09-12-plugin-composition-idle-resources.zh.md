# Agent Note: 插件组合的闲置资源

Status: implemented

## Problem

[共享观察器](2026-09-11-combined-plugin-mutation-cost.md)减少了原生观察器，但当前家族订阅者全部忽略收集的 mutation 记录。动画帧队列暂停时仍会保留每条记录及其移除的子树。最后一次退订只断开观察器，没有取消该帧。六个订阅者进行 1,000 次子树替换时，三轮基线均保留 1,001 条记录，清理后仍有一个待执行回调。

[共享面板挂载](../../implemented/simplification/2026-09-02-panel-mount-core-extraction.md)在 SSH 和任务看板尚未打开时就创建 React 根，导致 SSH 默认的主机页在页面启动期间查询数据。访问过的隧道页在面板关闭或页面隐藏后仍每五秒轮询，慢查询还可能重叠。聚合 shim 的回调已经由共享 hub 合并，却又安排第二个动画帧。

## Decision

- `subscribeBodyInvalidations` 用跨 bundle 的 symbol 标记包装回调。所有监听者均使用该 API 时，现有 hub 只安排一次重检查，不保留记录。`subscribeBodyMutations` 继续向需要记录的消费者交付完整记录，混合订阅保留此契约。生成副本仍兼容旧 hub；但旧 hub 会继续收集记录，直到重新加载采用新实现。
- 最后一个记录消费者退订时释放排队记录。最后一次退订同时取消 hub 的待处理帧并断开观察器。同一次 flush 中被较早回调移除的监听者不会执行。
- 面板挂载立即创建轻量容器，首次打开时才创建 React 根。访问过的根在关闭与重开期间保持挂载，保留草稿、选中页签和终端会话。关闭状态下脱离文档的树会释放，替代树等待打开后创建。任务看板 controller 与 Host 同步保持现有生命周期。
- SSH 将 controller 的打开状态传给隧道页。自动查询仅在面板和文档都可见时运行，恢复可见时立即刷新，并且同一时刻最多一个自动请求。如果关闭重开时仍有请求未完成，只在其结束后补一次刷新；反复切换会替换待刷新操作，不堆积请求。清理会使迟到响应失效，不停止 Host 隧道、用户发起的操作或终端会话。
- 聚合 shim 直接在 hub 回调中执行幂等检查，去掉第二帧及其在清理后的残留工作。整帧语义查询保持原样；其增量改写已在前一 note 中评估并放弃。

## Alternatives considered

从现有 API 中丢弃记录会静默破坏记录消费者。单独的失效通知 API 保留其行为，也允许独立打包的副本共享现有 hub。

文档隐藏时断开 body 观察器，需要额外的可见性监听及全量刷新信号才能避免漏掉 shell 替换。不保存记录的失效通知保留一个待执行检查，继续正常观察，同时不保留脱离文档的子树。

每次关闭都卸载面板可以释放更多内存，但会丢失本地草稿并中断终端组件。首次打开才渲染可省掉未使用插件的工作，同时保留已访问面板的现有状态生命周期。

整体调慢隧道轮询会牺牲可见状态的新鲜度。按可见性控制可保留五秒间隔，以及恢复时立即刷新。

## Consequences

首次打开才渲染会将初始工作移动到第一次点击，并不消除用户实际使用面板时的工作。访问过的关闭面板有意保留 React 状态和订阅。任务看板 Host 调度与同步、SSH 连接及端口转发均保持原样。

hub 每次 mutation 回调会检查监听者标记，新增一次对少量订阅者的扫描。记录消费者仍会保留其所需记录到下一帧。如果旧 bundle 先创建 hub，失效通知消费者仍能工作，但需要加载新 hub 才能获得减少记录保留的效果。

聚合客户端由 2,926,084 增至 2,931,248 字节；gzip 由 822,867 增至 824,072 字节，增加 1,205 字节。不根据资源计数基准宣称 FPS 或进程内存百分比改善。

源码改动需要重新构建受影响客户端包和内联子包源码的聚合包。bundle 行、默认值、依赖版本、profile 设置与 DSH 源码文件均未改变。

## Testing

回归覆盖混合订阅的记录交付、独立执行的 bundle、旧 hub 兼容、取消帧、回调中退订、缺少动画帧支持、首次打开挂载、草稿保留、兄弟面板互斥、shell 延迟到达、脱离文档后的恢复、隐藏时暂停查询、恢复时立即刷新、慢请求、迟到响应及反复关闭重开时有界的刷新操作。

仓库类型检查、包测试、全部 274 项脚本测试、文档、i18n、共享副本一致性、聚合一致性和运行时依赖检查均通过。四个受影响客户端包（含聚合包）构建成功。

一次并行包测试运行在 `dsh-remote-web-ui/tests/loopback-proxy.spec.ts:108` 的既有中止时序断言上失败。本任务没有修改该包和共享代理源码。定向重跑的三项代理用例全部通过，随后使用 `pnpm --workspace-concurrency=1 -r test` 完整运行全部测试并通过；代理代码及测试预期均未改变。

在 `http://127.0.0.1:3080/` 的真实 GUI 上以 1600 × 1000 和 390 × 844 验证，独立浏览器仅将聚合客户端响应替换为新构建，不改动服务、profile 或运行中的进程。桌面首次打开、关闭重开、筛选文字保留与输入框节点身份检查均通过；未打开的看板没有子节点。基线和修改版均没有页面脚本错误或脚本、样式加载失败。

窄屏验收仍受运行组合中原有的布局问题限制：两个版本的返回按钮均位于 y=854，超出 844 px 的视口，侧栏收起后也一样。基线与修改版截图确认同一故障，因此不将移动端导航报告为通过。SSH 轮询通过实际组件和 controller 测试验证，在线 profile 未执行远程 SSH 会话。GUI 验证采用响应替换，不代表现有浏览器已经加载交付的构建产物。
