# Agent Note: Issue batch 1587-1600 — session reuse, packaged-CLI discovery, plugin-card seats, console decoding, and z.ai plans

Status: implemented

Superseded in part by [family plugin cards resolve their seat from the loaded settings group](2026-09-17-family-plugin-card-seat-follows-the-loaded-group.md): its #1589 rule chose the seat by asking whether the official keyed seat is declared, which is true on every harness web build and therefore sent every family card to the official Plugins tab, leaving the family group's own section empty. Seat selection now keys on the settings group being loaded. The other five fixes in this note are unaffected.

The #1592 sidebar surface this batch shipped was removed by [usage sidebar surface removed](../simplification/2026-09-18-usage-sidebar-surface-removed.md): the entry row, its collapsible panel, and the entry-core trailing-actions API are gone, leaving the settings section as the only usage surface. What still stands from #1592 is the host side — the loopback-plus-paired-device trust fence and its routes.

## Problem

Six open issues reported defects and gaps that shared three underlying mistakes — a rule evaluated at the wrong moment, a seat/launch path that only existed in one deployment shape, and a byte/encoding assumption made once and copied:

1. **#1587 — task-board session reuse never fired.** `reusableSessionId` read the newest execution of `task.executions`, but the launch path calls it after `startExecution` appended this run's own open record, so the array tail was always an unsettled row and reuse always bailed out.
2. **#1588 — `dsh CLI not found on PATH` in the packaged desktop app.** `findDshBinary` searched PATH and `node_modules/.bin` shims; the desktop runtime stages the CLI at `resources/runtime/host/node_modules/@deepseek-ai/dsh/lib/bin.js` and deliberately deletes every `.bin` directory (symlinked shims cannot survive an installer), so no candidate existed at all.
3. **#1589 — the remote-access settings card was missing without the family group.** Five family plugins registered their card into `web-ui.plugin.item`, the list seat declared by `dsh-web-settings`; a profile carrying a family plugin without that group declares only the official keyed `settings.plugin.item` seat, and every plugin swallowed the resulting registration error, so the card silently never rendered.
4. **#1600 — plugin-manager CLI output was decoded per chunk as UTF-8.** `capture()` called `chunk.toString()` and truncated by characters, so a Windows OEM code page (CP936/GBK) became replacement characters, a character split across two `data` reads produced two replacement characters, and the budget was counted in characters for byte-bounded data.
5. **#1597 — z.ai (GLM) coding plans were not detected.** The GLM adapter served only `zai-coding` / `zai-coding-cn`, while the pi-ai catalog registers the international coding plan as `zai`; the parser also keyed windows by row position, rendered `TIME_LIMIT` (the MCP request cap) as a quota window, and had no exact credit ratio for credits-based plans.
6. **#1592 — no sidebar usage surface.** Usage data was reachable only inside the settings section, and its host routes were loopback-only, so a paired LAN browser could not read the same overview.

## Decision

1. `core/session-reuse.ts` now walks the execution list backwards to the newest **settled** execution that carries a session id, and keeps every other guard (opt-in, known roster, present and idle) unchanged.
2. `findDshBinary` additionally probes `lib/bin.js` beside the running host's entry script (`dirname(argv[1])/../lib/bin.js`), and `dshSpawnCommand` runs a resolved `bin.js` through the host's own interpreter (`process.execPath`, with the existing `ELECTRON_RUN_AS_NODE` branch covering an Electron host) because a script path has no Windows launcher.
3. A shared `shared/client/settings/plugin-card-seat.ts` owns the seat decision: it probes `ctx.slots.spec('settings.plugin.item')` and registers into the official keyed seat (keyed by the settings namespace) when the host declares it, otherwise into the family list seat. A refused registration logs one `console.warn` instead of being swallowed. All five family plugins (remote-web-ui, task-board, doctor, tool-describe-image, liangshen) register through it.
4. A shared `shared/host/console-output.ts` owns child-output capture: raw bytes accumulate under a byte budget and are decoded once at read time (`decodeConsoleBytes`), preferring strict UTF-8 and otherwise the candidate that loses the fewest characters (GBK, then lenient UTF-8). The budget trims from the front, never starting on a UTF-8 continuation byte, and drops one leading replacement character introduced by the seam. `dsh-plugin-manager` (gateway + routes probe) and `dsh-remote-web-ui` (`runUpdate`) both consume it.
5. The GLM adapter serves `zai` alongside `zai-coding` / `zai-coding-cn`, keys windows by the provider `unit` code (3 = 5-hour, 5 = month, 6 = week), reads the exact `currentValue` / `usage` ratio for `CREDIT_LIMIT` rows before falling back to `percentage`, and skips `TIME_LIMIT` and unknown units entirely.
6. `dsh-usage` gained a sidebar surface: an entry row injected through the shared sidebar-entry core (family position `after`, so it lands behind the task-board / SSH / skill-center rows and before the workspace browser) and a panel below it rendering the same overview document. The entry row seats the panel's refresh and collapse controls; the mount owns the single open state, persisted in `localStorage` (`dsh-usage.sidebar.collapsed`); collapsed renders a one-line strip with the current provider's today usage (see [the pet-decoupling note](../simplification/2026-09-17-usage-pet-decoupling-collapsed-summary.md)), polling runs at 10 s expanded, 30 s collapsed, and pauses while the page is hidden, and the host routes now use the shared pairing fence (`shared/host/pair-access.ts`): loopback always passes, a live paired-device cookie passes when `dsh-remote-web-ui` is loaded, unpaired LAN requests keep their 403.

## Alternatives considered

- **#1587**: keeping the array-tail rule and having the caller pass the previous task snapshot. Rejected: the rule is the only arbiter of reuse and must be correct for whatever task record it is handed; a caller-side snapshot would silently break the next call site.
- **#1588**: staging a `.cmd` shim in the desktop payload. Rejected: the runtime builder removes `.bin` directories precisely because symlinked shims do not survive installers, and re-introducing one would trade a clear "not found" for a broken shim on user machines.
- **#1589**: probing the official seat from each plugin separately, or declaring the family seat in every plugin (the previous design). Rejected: the seat is a deployment property, and duplicating the probe per plugin would let the five copies drift; one shared helper keeps the decision in one place. Also rejected: registering into both seats unconditionally — the second registration always throws because a slot has exactly one declaring parent.
- **#1600**: fixing only `gateway.ts` (the issue's headline site). Rejected: the issue explicitly asks for one handling at every call site of the defect class, and `dsh-remote-web-ui` carried the same per-chunk decoding bug even after its #1430 fix.
- **#1600**: making the budget a character window after decoding. Rejected: it would decode the whole (unbounded) stream first, which is exactly the quadratic cost the issue calls out.
- **#1597**: also accepting `TIME_LIMIT` as a window. Rejected: it is a per-minute MCP request cap, not a plan quota; rendering it would show a quota that does not exist.
- **#1592**: rendering the panel through a slot instead of DOM injection. Rejected: the official sidebar declares no list seat an external plugin may use (the known-fragility item in the semantic-attributes contract); the family precedent is DOM injection with the shared self-healing core.
- **#1592**: keeping the usage routes loopback-only and shipping a separate paired route. Rejected: duplicating the fence is how fences drift; the family already has one shared pairing predicate.

## Consequences

- Reuse now happens for tasks that opted in, which is the behavior the docs always described; an opted-in task whose previous session is gone, running, or on an unknown roster still mints a fresh conversation.
- The packaged desktop resolves its own bundled CLI, so installs and updates work without a PATH entry; a PATH entry still wins when present.
- Family plugin cards render on deployments with or without `dsh-web-settings`, and a refused seat is now diagnosable from the browser console instead of being invisible.
- CLI child output is decoded once, so GBK error text and split multi-byte characters render correctly; the retained tail is bounded in bytes, which lowers the effective character window for CJK output.
- The plans tab covers the z.ai route the catalog actually ships, with unit-keyed windows and credit-ratio percents; unknown units and the MCP cap produce no window, and a plan with nothing renderable reports no plan data.
- The sidebar usage panel reads host data on a paired LAN browser; the settings section and the sidebar share one overview document and one fence.
- No host/client boundary moved: the new shared modules are host-side (`console-output`) and client-side (`plugin-card-seat`), both carrying generated copies per the sync manifest. The sidebar-entry core was unchanged by this batch; a later change added its opt-in trailing-actions API (see the controls note above), which leaves action-less rows byte-identical.
