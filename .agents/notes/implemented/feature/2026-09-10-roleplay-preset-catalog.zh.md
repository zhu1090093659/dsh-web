# Agent Note: 角色扮演预设目录及其内容边界

Status: implemented

## Problem

社区预设目录一直是空的，创意工坊的「预设」标签页无内容可列，[Community agent presets distributed through the Workshop](2026-09-09-community-agent-presets.md) 描述的发布链路也从未承载过真实内容。可用于首批导入的素材是外部提示词收集库（`dongshuyan/Awesome-Prompts`，`角色扮演/多角色人设`）中的 46 个角色扮演提示词。它们全部按 NSFW 伴侣人设撰写：同一模板先写角色档案，再加「性态度」字段、分级的露骨话语库，以及一段声明读者性癖好的「用户身份」块。其中 3 个文件写明角色 17 岁，另有多位角色在其原著中就是儿童。

目录是 dsh-market.com 的发布源：写入目录的条目会被商店的每个用户下载到本机，并在创意工坊里一键变成可运行的 agent。因此这批素材既不能原样拷入，也不能只删掉露骨句子——对未满 18 岁的条目而言，问题在于「恋人」这一框架本身，而不在于用词。

## Decision

32 个成年角色作为首批社区预设发布，每个角色一个目录：`packages/dsh-preset-center/presets/roleplay-<拼音>/`，并在 `catalog.json` 中以 1.0.0 版本署名上游收集库（`author: dongshuyan`、`repo: https://github.com/dongshuyan/Awesome-Prompts`），且把每个条目归类为 `roleplay`（词表与筛选界面记录在 [市场界面上的预设分类](2026-09-10-preset-category-filtering.zh.md)）。

每个预设只有一个组合行：persona 行把整份角色设定作为完整系统提示（`complete: true`、`includeRuntimeContext: false`），不挂载其它内容。组合不引用任何工具、相对模块或内联 `!!js` 表达式，因此由它组成的会话只能对话：没有文件系统、没有 shell、没有网络。全年龄边界写在人设文本自身，约束随预设走，而不是只存在于评审清单里。

## Content boundary

两条规则决定入选名单，并已由 `packages/dsh-preset-center/presets/README.md` 写成本资产类别面向贡献者的内容要求：

- **不收录未满 18 岁的角色。** 设定年龄低于 18 岁即排除：江晚星（17）、林小枝（17）、周小雨（17）、晓美焰（14）、秋月爱莉（16）、雪之下雪乃（17）、雷姆（17）、露易丝（约 16）、顾星落（17）。
- **不收录原著中的儿童角色，也不收录年龄未定的条目。** 据此排除木之本樱（原著开场 13 岁）、灰原哀（原著为儿童体型）、菲伦（文件给出 15 或 19）、樱岛麻衣（17～18），以及那个泛化的「你创作的小说中的她」（年龄交给用户、建议 20 岁及以下）。

46 个文件中有 14 个按此排除。其余每个预设只从角色档案重建：删去「性态度」字段、露骨话语库、「用户身份」块与逐句的亲密描写，伴侣框架仅保留为普通的成年恋爱关系，绝不作为性框架。

## Derivation

这批内容由一次性转换脚本产出，而非直接编辑源文件：脚本在第一个交互协议标记处整体截断（一次性去掉话语库与用户身份块），丢弃「性态度」字段及建立其上的行为段落，对剩余行按分句匹配露骨与软性亲密词表（括号词组作为整体处理），并把框架改写为角色扮演头部加全年龄条款。该脚本不进入本仓库；交付物是预设本身，后续修改直接改预设文件。

## Alternatives considered

**原样拷入源文件。** 否决：等于通过公开商店发布露骨性内容，且其中 3 个文件性化了 17 岁角色。

**只删露骨文本，角色（含未成年）全部保留。** 否决：对未成年条目而言，人设本身就是「对一个孩子角色忠贞不渝的恋人」，问题在关系框架，词级过滤去不掉。

**只发布一个空的角色扮演模板预设，不发布具体角色。** 否决：本批次的目的就是让创意工坊的「预设」标签页有真实可安装的内容，模板不是；模板已存在于 `presets/_template/`。

**把每个角色做成独立 npm 插件包。** 按创意工坊预设 note 中已记录的理由否决：需要 profile patch 与重启，且 roster 没有逐项启用/禁用界面。

**沿用上游的显示文案与描述。** 否决：上游文件名与标语本身带有露骨框架（「NSFW 提示词」与伴侣式标语），而它们会成为商店与 DSH roster 的显示文本。

## Consequences

- 创意工坊的「预设」标签页首次有内容：32 个条目，rank 排序使整批位于内置预设之后，每个都可装入惰性库——安装本身即经显式确认的声明。
- 所有预设只做对话。想要读写文件或执行命令的用户应选择其它预设；这是角色扮演人设换来的取舍。
- 本批次是第三方收集库的衍生作品，而该库没有 `LICENSE`。目录中记录了署名与来源链接，但再分发授权未获上游作者确认。因此发布生成的 `market/dist` 属于维护者决策；若上游作者反对，应撤下该批次。
- 内容评审仍是人工流程。排除与过滤规则记录于此以便下一批次可审计，但 `scripts/market-build` 不做机械强制。
- `scripts/market-build-clean.test.mjs` 现在把 `packages/dsh-preset-center/presets` 复制进干净检出用例。此前该目录被遗漏，在目录为空时看不出来。

## Testing

- 32 个 `agent.cordis.yml` 均通过 YAML 解析并断言交付形态：恰好一行组合、`@deepseek-ai/dsh-persona`、`prefix` 非空、`complete: true`、`includeRuntimeContext: false`、无 `!!js`、每目录两个文件、`preset.yml` 各项单行。
- 对生成文本做残留扫描（露骨词表与 `身体`、`白丝`、`黑丝`、`开放`、`亲密`、`欲望`、`抱` 等），仅剩「好亲近」「亲近的人」这类良性命中；另有审计确认过滤没有丢掉含有效信息的源文本行。
- 所有生成预设的 `【年龄】` 字段均为 18 岁及以上。
- `node scripts/market-build` 输出 32 个预设（2485 个文件），`pnpm market:check` 报告已提交的 `market/dist` 为最新；`pnpm typecheck`、`pnpm test`、`pnpm docs:check`、`pnpm i18n:check`、`pnpm test:scripts`（272 项）全部通过。
