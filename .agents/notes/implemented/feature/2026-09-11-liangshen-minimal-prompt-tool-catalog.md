# Agent Note: LiangShen mode as a minimal persona plus an injected standard tool catalog

Status: implemented

Partially superseded by [a shell-only anchor and PTC promotion](2026-09-12-liangshen-shell-anchor-and-ptc-handoff.md) on the tool-surface half: the anchor is `bash` alone and the promoted turn presents the session's tools as PTC, so the catalog now lists argument signatures read from the registry instead of names and summaries read from the wire. Partially superseded by [lifting the AGENTS.md instructions into the system prompt](2026-09-12-liangshen-agents-md-in-system-prompt.md) on the instruction half: the agent-instructions hint is no longer the default. The minimal persona, the injected-catalog mechanism, and the message-source decision all still hold. Partially superseded on catalog scope by [the request-surface tool catalog and evaluation tooling](2026-09-13-liangshen-request-surface-catalog-and-eval-tooling.md): the entries describe exactly the surface the current request opens, so the rendered text is no longer stable across the presentation boundary. Partially superseded by [the V4.1 Flash native rebuild](2026-09-16-liangshen-v41-flash-native-rebuild.md) on the persona text and the staged wire: the working discipline is replaced with action-triggered rules, and the anchor turn plus the second-turn PTC promotion are retired; the minimal-persona mechanism, the injected catalog, and the message-source decision still hold.

## Problem

The LiangShen preset shipped as a two-phase anchored-standard composition: the first model request exposed only the builtin Minimal preset's two tools with empty runtime contexts and a whitelisted set of message sources, promotion waited for a minimal-like first reasoning block with a four-step fallback, and the wire then switched to PTC Mode (a single `run_code` tool). Every part of that machinery — the anchor gate, the bootstrap output-token cap, the deferred injections, the post-compaction reset to a controlled phase — existed to manage the transition rather than to serve the task, and the first turn paid for it with two tools.

A live defect made the cost concrete. The phase-1 prompt filter matched the section names `deployment:persona` and `persona`, while the installed SDK registers the persona section as `deployment:persona-prefix` (`PERSONA_PREFIX_SECTION`, `@deepseek-ai/dsh-system-prompt` 0.1.5-rc.1). Nothing matched, so phase 1 sent an empty system prompt: the anchor the whole design was built around was absent, silently. No test caught it because the fixtures spelled the same stale name as the filter.

## Decision

The preset keeps the builtin Minimal preset's one-line persona — extended with the mode's standing working discipline and one workspace-directory orientation line — as the whole system prompt, and delivers its tool surface as a context injection from the first turn while the wire is staged: the anchor turn (the session's first) carries the builtin Minimal surface natively and from the second turn the same plugin presents the session's tools as PTC ([a shell-only anchor and PTC promotion](2026-09-12-liangshen-shell-anchor-and-ptc-handoff.md)). The model's capability facts arrive as a message at the prompt tail instead of as system-prompt prose.

- `presets/liangshen/minimal-prompt.mjs` filters every assembled prompt down to the persona section, matching `deployment:persona-prefix` plus the legacy `deployment:persona` / `persona` spellings. The persona prefix carries the one-line persona, the standing working discipline (exit thinking loops immediately, design-first reasoning over pre-rehearsed code, YAGNI and PDCA, no code comments), and the plugin appends the session's workspace directory as one orientation line (`Your working directory is <cwd>.`, read from the session header). Plan mode's `plan:policy` is kept by default, because that section is the only enforcement behind the mode: the exit tool stays registered in every mode and no tool restriction backs it. An assembly whose sections match none of the accepted names degrades to the unfiltered prompt with a one-time warning, so the empty-system-prompt failure cannot recur silently. The workspace instructions are handled by [their own decision](2026-09-12-liangshen-agents-md-in-system-prompt.md).
- `presets/liangshen/tool-catalog.mjs` observes the `system-prompt/assemble` waterfall value and appends a durable user message listing each tool's argument signature and a one-line summary after the user's own message, the way `dsh-tool-skill` injects the skill catalog. Publishing starts at the first step and indexes the full registered PTC surface — the entries come from the registry, not from whatever wire the current request carries — so the rendered text is stable across the presentation boundary. The rendering is one stable pure function of the entry list and the presentation plan, and the published copy is read back from the durable log, so a step republishes only when the rendered text differs from the last catalog message still on the visible surface (a changed tool set, or a copy a compaction shadowed). Nothing is held in memory, so resume and reload reconstruct the same decision.
- The injected message source is exactly `{ kind: 'plugin', plugin }`, the same shape the instruction hint uses. `plugin` is the only injected kind the v2->v3 migration whitelist and the v3 `MessageSourceMap` both classify ([preset assets follow the current persona schema and durable message sources](../../bug-fix/2026-09-10-preset-schema-and-message-source.md), issue #1455), and the durable validator's `plugin` field set is `kind`, `plugin`, `form`, `sections`, `summary` — an extra field such as a stored `digest` is rejected as an unexpected member.
- Runtime contexts, workspace instructions, and the skill catalog flow as in Standard mode. `presets/liangshen/tool-bootstrap.mjs` is deleted along with the anchor gate, promotion, PTC presentation, message-source whitelist, deferred injections, bootstrap token cap, and compaction reset ([the PTC transition instruction](../../bug-fix/2026-08-25-workshop-and-runtime-fixes.md) loses its subject with it). The trajectory classifier moved into `tools/analyze-session.mjs`, where it stays a measurement instead of a gate.

## Testing

- `tests/minimal-prompt.test.ts` covers the section filter, the workspace line (append, legacy persona name, no duplication, absent cwd), the plan-policy switch, the persona-less degradation, the instruction hint under `instructionSource: 'hint'` including its post-compaction reset, and the workspace-instructions prompt section with its discovery, budget, and degradation paths.
- `tests/tool-catalog.test.ts` covers the registry-surface read and its fallback, the argument-signature renderer, the injection position and message shape, first publication versus update, dedupe against the durable log, the republish after a compaction shadows the copy, the legacy `events` session shape, the empty-surface cases, the anchor-turn staging (boundary read, shell-only wire narrowing, stable text across the boundary), the PTC declaration and its degradations, and the renderer's malformed-input handling.
- `tests/preset-composition.test.ts` validates the shipped `agent.cordis.yml` against the repo's preset schema and pins `PERSONA_SECTION_NAMES` against the installed SDK's `PERSONA_PREFIX_SECTION`, which is the regression guard for the defect above.
- The installed harness was run against the shipped preset directory outside a session: `scanRoot` reported the preset healthy with no broken row, `fileComposition` parsed the composition with the loader's own dialect and evaluated every `!!js` gate, and the persona row config was accepted by the installed `@deepseek-ai/dsh-persona` schema as `{ prefix, suffix: '', complete: false, includeRuntimeContext: true }`.
- The injected source shape was run through the installed durable payload validator (`assertReleasedPayloadSemantics(event, 3)`, the call the V3 `system/message` path already makes for a plugin-sourced message): `{ kind: 'plugin', plugin }` passes, and the earlier candidate carrying `digest` / `count` fails with `source has unexpected member "digest"`. That check is why the shipped plugin stores no digest.

## Alternatives considered

- Keep the two-phase transition and only correct the persona section name. Rejected: the empty-prompt defect was the visible symptom, but the transition itself is the cost — a crippled first turn, a second catalog change that breaks the prefix cache, and five interacting controls whose failure modes (goal rounds deadlocking in phase 1, presentation resets after compaction) each needed their own fix. Correcting one name would have left all of it in place.
- Keep the two-tool first request and inject the catalog instead of switching the wire. Rejected for the full roster: a list naming tools the wire does not carry is a capability claim the model cannot act on, and the anchor would then depend on the injected text being ignored. The narrow form of it is what [the staging note](2026-09-11-liangshen-anchor-turn-staging.md) ships: the anchor turn's own schemas are the whole wire and take no catalog.
- Make the persona row `complete: true` instead of filtering sections. Rejected: the registry restores a complete section after the assemble waterfall, so plan mode's `plan:policy` could never reach the model and the mode would keep its tool while losing the only text that enforces it.
- Deliver the catalog as a prompt section or a runtime context instead of a pre-step message. Rejected: both land in the prefix this mode exists to keep minimal, and the request was explicitly the skill-catalog shape at the prompt tail.
- Publish the catalog every step. Rejected: the message is durable, so each step would append another copy to the journal and to the model's history.
- Record the catalog digest on the message source so the republish decision reads one field. Rejected: the durable validator's `plugin` field set does not admit it (see Testing), and comparing the rendered text the plugin already writes needs no extra field at all.
- Keep the classifier as a gate on a smaller transition (for example, withholding only the filesystem tools until the anchor holds). Rejected: any gate reintroduces the state machine, and the mode's premise is that the system prompt, not the catalog, carries the anchor.

## Consequences

- The anchor turn is deliberately narrow: only the `anchorTools` schemas are on the wire for the session's first request, and the wire's schema set changes exactly once at the turn boundary — from the shell to the collapsed PTC surface — so no catalog-driven prefix-cache break happens within a turn or after the second request; the catalog text itself does not change at the boundary.
- The system prompt is byte-stable for the session — the persona line, plus plan mode's policy while plan mode is on — and nothing is appended after a tool call.
- The catalog message is one durable user message per session plus one replacement when the tool set changes or a compaction shadows it, so the journal and the history carry a bounded, cache-friendly addition instead of a per-step repetition.
- Plan mode keeps working through its policy section; `keepPlanPolicy: false` is available for a strict one-line surface but leaves the mode with no policy text.
- The anchored trajectory is now a hypothesis to measure rather than a mechanism to enforce: `tools/analyze-session.mjs` still reports the `we` / `let me` markers per step, and the mode no longer corrects drift on its own.
- The preset's tool roster keeps the two-phase version's shape, so the persistent shell still replaces the Standard ephemeral shell for the whole session and the editor still inherits the host file sandbox; the `workflow` tool is no longer published, matching the builtin PTC preset, while its engine stays mounted for `ralph`.
