# Agent Note: A shell-only anchor and PTC promotion for LiangShen mode

Status: implemented

Partially superseded by [restoring foundational anchor tools and refining PTC semantics](2026-09-12-liangshen-anchor-tools-and-ptc-refinement.md): default `anchorTools` is restored to `[bash, str_replace_editor, exit_plan_mode, skill]` while preserving bash-only as a configuration experiment, the anchor turn covers the entire first user turn, PTC is claimed active only upon actual success, and overcommitments (exact Minimal match, benchmark score claims, cache equals behavior) are retracted.

Supersedes in part [staging the Standard catalog behind the anchor turn](2026-09-11-liangshen-anchor-turn-staging.md) and the tool-surface half of [minimal persona plus an injected standard tool catalog](2026-09-11-liangshen-minimal-prompt-tool-catalog.md): the shipped anchor was previously `bash` alone and the promoted surface presents tools as PTC. The durable turn boundary, the flat anchor narrowing, and the injected-catalog mechanism stay in force.

## Problem

The mode kept the builtin Minimal persona as its whole system prompt but put the builtin Standard roster natively on the wire, staged behind a four-schema anchor turn (`bash`, `str_replace_editor`, `exit_plan_mode`, `skill`). Two costs followed. The anchor turn paid for capabilities it could reach by name anyway — execution resolves against the session registry (`dsh-tools` `resolveExecution`), not against the request's declared schemas — while those three extra schemas held the first request's tool surface away from the single-tool builtin Minimal shape the mode exists to reproduce. And from the second turn the model's only description of its tools was the injected catalog: a list of names with one-line summaries, no argument shapes at all, on top of a large native roster — the surface the community eval that motivates the mode scores below Minimal. PTC's payoff is the opposite shape: one program per intent, with independent read-only calls overlapping under `Promise.all` (the registry's cap defaults to 10). A promoted session whose catalog listed names and signatures but never that contract still produced one call per program, so the payoff did not materialize.

## Decision

The anchor turn presents natively and carries `bash` alone, and from the session's second turn this session's tools are presented in PTC mode.

- `presets/liangshen/agent.cordis.yml` sets `anchorTools: [bash]` and `ptcPresentation: true`, and disables the `tool-workflow` row while keeping the workflow engine row for `ralph` — the builtin `ptc` preset's one roster difference, because the model-authored composition surface is `run_code` itself.
- `presets/liangshen/tool-catalog.mjs` owns the whole staged surface. It still narrows the anchor turn's wire to `anchorTools`, and it now also declares PTC presentation for that agent alone (`agent.ctx.tools.presentAs('ptc')`). The declaration is triggered by the turn-boundary session events — the anchor turn's `turn/end` and the second turn's `turn/start` — not by the assembly waterfall, because the harness collects the tool providers BEFORE it runs `system-prompt/assemble`: a declaration made inside that waterfall can only affect the next assembly, which would put the collapsed surface one step into the promoted turn instead of on its first request. The assembly listener re-asserts the declaration for a session whose boundary was crossed while the plugin was not observing events (a host restart mid-turn); there the collapse lands one assembly later and stays. The declaration is latched per agent, is skipped when the context exposes no code runtime (`ctx.get('codeRuntime')`), and a declined declaration leaves the wire native with a one-time warning, so a broken optional path degrades instead of failing every request of a session.
- The catalog entries are the registry's PTC surface (`ctx.tools.sdkSchemas(agent)`, which excludes the reserved `run_code`), sorted by name, each rendered as a compact TypeScript-ish argument signature plus the capped one-line summary, e.g. `` - `bash({ command: string, timeoutMs?: number })`: Run commands in a bash shell``. The renderer covers scalars, `const`/`enum` literals, `oneOf`/`anyOf` unions, arrays, and inline object literals, degrades everything else to `JsonValue`, and stops expanding nested objects past a fixed depth so one tool stays one line. When the registry publishes no SDK projection, or the projection throws, the entries fall back to the assembled wire schemas with a one-time warning.
- The catalog rendering is a pure function of the entry list and the presentation plan, and the entries do not depend on which surface the current request carries. The anchor turn and the promoted turn therefore render byte-identical text, so the first publication stands across the presentation switch and no republish follows it.
- The catalog's closing block carries the program contract and the collapse rule that `minimal-prompt` filters out of the prompt together with the harness's own `tools:sdk` and `tools:ptc-only` sections: `run_code` takes `code` — the body of an async TypeScript function, erasable syntax only — and `description`; compose one program per intent instead of one call per step; reach a tool as `await tools.<name>({ ... })` and overlap independent read-only calls under `Promise.all` (safe calls run concurrently, mutating calls run alone in submission order); a failed call rejects with `ToolCallError`; only what the program returns or logs becomes output, so results must be curated; and only `run_code` is directly callable once it is on the wire, while the session's first turn carries the shell alone. The block restates the harness's own usage instructions in this mode's wording, so the injected text is identical on both sides of the presentation boundary, and it is omitted — along with the PTC declaration — without a code runtime or with `ptcPresentation: false`.

## Testing

- `tests/tool-catalog.test.ts` covers the signature renderer (scalars, literals, unions, arrays, inline objects, the nesting cap, malformed input), entry sorting and nameless skipping, the registry-surface entry source, the shell-only anchor turn (wire narrowed to `bash`, no PTC declaration), the promoted turn declaring PTC before `next()` reads the wire and keeping the wire untouched, one declaration per agent, byte-identical catalog text across the boundary, the empty-surface cases, the dedupe and republish rules against the durable log, and every degradation path (no code runtime, `ptcPresentation: false`, no SDK projection, a throwing projection, a session with no scoped tools view) with its single warning, plus the program contract's presence under PTC and its absence without a code runtime or with `ptcPresentation: false`.
- `tests/preset-composition.test.ts` pins the shipped `anchorTools: [bash]` and `ptcPresentation: true` rows and the disabled `tool-workflow` row against the repo's preset schema.

## Alternatives considered

- Keep the four-schema native anchor and change only the injected catalog text. Rejected: the anchor's tool surface would stay four tools where the builtin Minimal shape is one, and a catalog describing `run_code` while the wire presents native schemas describes an invocation contract the session does not have.
- Present PTC statically for the whole session, as the builtin `ptc` preset does. Rejected: the first request would then carry `run_code` instead of `bash`, which is exactly the surface the anchor exists to fix.
- Deliver the harness's generated SDK section verbatim — `renderToolsSdk` is exported by `@deepseek-ai/dsh-tools` — instead of a compact signature list. Rejected for this mode: the injected message is tail context, and the full declaration also carries fixed usage prose, complete output shapes, and nested object types, several times the size of the signature list; argument names and types plus the harness's structured tool errors cover the same ground.
- Inject the harness's rendered `tools:sdk` section verbatim instead of restating the contract. Rejected: it exists only once PTC is on the wire, so the injected text would change at the boundary and force a republish; it couples the mode to a harness section name whose disappearance degrades silently; and it carries the full declarations the compact signatures already cover.
- Keep the native names-and-summaries catalog while letting the wire collapse to `run_code`. Rejected: a list of names without argument shapes is not actionable inside a TypeScript program.
- Read the entries from the assembled wire, as the pre-PTC catalog did. Rejected: the anchor turn's wire is narrowed to `bash` and the promoted turn's wire is `run_code` alone, so the first publication would name one tool and the boundary would republish the whole list.
- Declare the presentation from inside the assembly waterfall, before `await next()`. Rejected after a live harness probe: the providers that build `assembly.tools` run before the waterfall, so the declaration only takes effect from the next assembly, and the promoted turn's first request would carry the native roster while its catalog claimed the `run_code` contract. This is also why the anchor narrowing, which transforms an already-built assembly, is unaffected by the constraint.
- Emit the PTC declaration from a pre-step decision. Rejected for the same timing: a pre-step decision runs after its own assembly, so the collapse would land one step late.
- Reset the session to native presentation after a compaction, as the retired `tool-bootstrap` did. Rejected: this mode's boundary is "the session's second turn", read from the durable log, so a compaction does not create a second first request that needs re-anchoring.

## Consequences

- The session's first request reproduces the builtin Minimal surface exactly: the persona block plus one tool schema (`bash`), with the injected catalog already naming the promoted surface.
- The wire changes exactly once per session, at the anchor-turn boundary, and that change is now a presentation collapse to `run_code` rather than a roster swap. The catalog text does not change with it, so the durable message is still written once per session plus one replacement after a compaction.
- The model's knowledge of the promoted surface comes entirely from the injected message: argument signatures and the collapse rule, without the harness's generated declarations (no output shapes, no nested expansion past the depth cap). Wrong arguments surface as the harness's structured tool errors and are self-corrected, at the cost of one failed call.
- The PTC prompt itself — the program contract — lives in the same injected message rather than in the system prompt, so the stable prefix stays the one-line persona; the mode's batched-call capability therefore rests on that durable message staying on the visible surface (a compaction republishes it) and on it being the model's only statement of the contract.
- `workflow` is no longer part of the mode's surface, matching the builtin PTC preset; `ralph` keeps working because only the tool row is disabled, not the engine.
- A deployment without a code runtime, or with `ptcPresentation: false`, keeps the previous native behavior — the assembled roster on the wire from the second turn, a catalog without the `run_code` contract — with a one-time warning.
- The mode no longer claims the model can call any registered tool directly after the anchor: under PTC presentation only `run_code` may be named, which is the rule the injected message states and the reason the mode reads its entries from the registry rather than from the request.
- The promotion needs one observed boundary event: a session resumed mid-turn after a host restart, where the plugin never sees that turn's `turn/end` or `turn/start`, carries the native roster for one assembly before the assembly-time re-assertion collapses it. Nothing else in the mode depends on the presentation having landed first — the catalog text is identical either way.
- Agent Notes and READMEs describing the four-schema anchor, the Standard roster on the wire, and the absent PTC switch are updated in the same change; the earlier records stay as the rationale for the machinery that still ships.
