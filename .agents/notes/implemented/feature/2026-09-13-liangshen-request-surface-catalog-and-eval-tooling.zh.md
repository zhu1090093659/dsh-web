# Agent Note: 请求面工具目录与梁神模式 V4.1 Flash 评测工具

Status: implemented

部分取代[极简 persona 加注入式工具目录](../../implemented/feature/2026-09-11-liangshen-minimal-prompt-tool-catalog.md)：目录改为索引当前请求实际开放的工具面，而不是完整注册表，因此其文本不再跨呈现边界保持稳定。延伸[四工具锚定与 PTC 语义修正](../../implemented/feature/2026-09-12-liangshen-anchor-tools-and-ptc-refinement.md)。落实[梁神模式针对 DeepSeek V4.1 Flash 的改进计划](../../proposed/feature/2026-09-13-liangshen-v41-flash-improvement-plan.md)的第 1–4 阶段，该计划的默认值选择阶段仍未完成。部分被[V4.1 Flash 原生重构](2026-09-16-liangshen-v41-flash-native-rebuild.zh.md)取代：目录跟踪的呈现边界不复存在——wire 在整个会话中保持单一呈现，被分页扣留的命名空间在激活前以摘要出现；「恰好宣告请求开放的面」原则与评测工具继续有效。

## Problem

锚定回合中，注入的工具目录列出了注册表里的每一个工具，而该次请求的 wire 只开放 `anchorTools`。模型被声明了它无法调用的能力。同一份契约文本还声称会话首轮"只带 shell"，而出厂默认锚定集改为四工具后这一说法已不成立。另一方面，仓库里没有任何手段能区分任务成功率的变化来自 persona、锚定回合还是 PTC 呈现，也没有用于这类对照的有界预算机制。

## Decision

`presets/liangshen/tool-catalog.mjs` 改为宣告该次请求实际开放的工具面，包内同时补齐计划要求的有限评测工具。

- 原生呈现的条目取自该次请求自己的 wire：锚定回合取收窄后的锚定集，PTC 被拒绝或关闭后取组装出的原生清单。`mergeProjectedSchemas` 按名字把注册表投影中更完整的 schema 覆盖到这些条目上，因此 wire 定义更薄时也不会丢掉完整参数语义。
- PTC 呈现的条目取自注册表投影（即经 SDK 可达的工具面），程序契约明确只有 `run_code` 可直接调用，列出的每个工具都要在程序内部触达。过时的"首轮只有 shell"表述已删除。
- `catalogStateFor` 在 pre-step 从当前呈现状态解析目录，因此晋升回合第一步描述的就已经是晋升面，而不是锚定回合组装时留存的状态。
- 回退、撤销、压缩恢复、会话恢复与去重的行为保持不变。
- `tools/benchmark-live-run.mjs` 在隔离的 preset 副本中运行候选矩阵：`B`（出厂 persona 与两阶段策略）、`P`（候选 persona）、`T`（候选 persona，首轮即用 PTC）、`N`（候选 persona，全程原生工具）、`M`（内置包官方 Minimal preset，外部参照）。它记录基线（仓库提交、出厂 preset hash、变体 preset hash、DSH 版本、固定 route、任务版本与上限），为任务写入初始工作区，用 Node 验收检查判分，把语言风格指标排除在结果之外，并在达到会话数或费用上限时停止而不自动扩样。矩阵按任务交错运行各组，因此被上限截断时每个组仍有会话；无法计价的预算会直接拒绝运行，而不是让预算门永不触发。
- `tools/benchmark-report.mjs` 把运行记录汇总为按组的成功率与 Wilson 区间、按任务配对差值与置信区间、token 与费用合计，并单独列出基础设施失败。超时计入任务失败并在单独的列里报告，只有"没有任何 request"或"未被判分"才算基础设施失败。报告只读取本次 suite 清单内的记录，并拒绝基线不一致的目录。`tools/tasks/liangshen-v41-flash.json` 是覆盖代码修复、首轮专用工具、多轮修改、失败恢复与工作区指令遵循的种子任务集。
- 出厂默认仍是四工具锚定加 PTC。尚未运行任何真实对照，而计划规定的规则是：在证据无法排除退化时落地契约修复并保留当前策略。

## Testing

- `tests/tool-catalog.test.ts` 钉住请求面契约：锚定回合在首轮每一步都恰好列出锚定 wire，晋升回合第一步在其自身组装之前就已描述晋升面，PTC 契约声明 `run_code` 是唯一可直接调用的工具且不再声称首轮只有 shell，会话恢复与恶意投影都会回退且不宣告 PTC。
- `tests/benchmark-live-run.test.ts` 钉住各变体重写（出厂默认、候选 persona、空锚定、关闭 PTC、官方 Minimal），用仓库自有的 preset schema 校验每个派生组合，验证 persona 块标量的改写在下一个组合行前停止，读取持久会话形状，合计 usage 且不重复计数，并确认每个种子任务在初始工作区上都不通过，从而没有任何任务可以不做事就通过，还拒绝费率缺失或不可用的预算表，并把任务超时排除在基础设施桶之外。
- `tests/benchmark-report.test.ts` 钉住汇总：Wilson 边界、按任务配对的均值差值与区间、超时计入失败而基础设施失败不进入分母、suite 清单排除复用目录中的旧记录、基线不符被拒绝、单个配对任务不产生区间，以及报告必须携带的处理说明。

## Alternatives considered

在锚定回合列出注册表工具并让目录文本跨边界保持不变：否决。它宣告了请求并不开放的工具面，而早先的"跨边界稳定"只有在列表不描述 wire 时才站得住。

只从 wire 派生原生条目、不做投影覆盖：否决。当某次组装的工具对象携带更薄的参数定义时，目录会静默丢掉它本应交付的完整参数语义。

为每个实验组注册一个公开预设：否决。用现有 `anchorTools` 与 `ptcPresentation` 字段配合隔离的 preset 副本即可表达矩阵，无需新增用户可见预设或注册表改动。

在本次改动中运行真实 A/B：延后而非否决。计划要求在付费会话之前先由 smoke 估算确定费用预算，而该预算尚未获得授权。

现在就把默认值改为首轮即用 PTC 或全程原生：否决。证据无法排除退化，而计划规定的规则在这种情况下保留当前策略。

## Consequences

- 目录与请求不再可能对"有哪些工具"给出不同说法；晋升边界现在会重发一次目录，这是有意的上下文变化，此前设计是为避免它而付出了虚假声明的代价。
- 候选矩阵、基线记录与汇总工具已就绪，且没有花掉任何付费会话：默认值不变，计划在拿到证据前保持 proposed。
- `packages/dsh-liangshen` 的插件源码已变化，运行中的 DSH 宿主需重启后新的目录行为才生效；preset 组合本身的结构与配置键保持不变。
