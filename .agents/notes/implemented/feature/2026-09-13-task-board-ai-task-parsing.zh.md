# Agent Note: 把粘贴文本用 AI 解析进新建任务表单

Status: implemented

## Problem

issue #1540 希望看板能把粘贴进来的文本（例如从聊天软件复制的一段对话）变成任务：提炼并归类内容，在新建任务时预填标题、描述和执行 Prompt。先前的方案卡在一个问题上：解析花的是哪个模型的额度。报告者给出了答案——用当前部署已配置提供商的模型，让用户自己选，默认任意一个即可。

## Decision

新建任务表单带了粘贴框、模型下拉和一个动作按钮。下拉用的是任务自身「模型」下拉那份 `executionOptions.models` 列表，默认选中第一项。`POST {TASK_BOARD_API_PREFIX}/parse` 挂在看板既有的回环与同源围栏之后，接收 `{ text, model }`，返回 `{ ok: true, draft }` 或带类型的失败；失败码对应状态码：`no-model` 503，`parse-failed` 与 `model-error` 502，`timeout` 504。客户端把每个码翻成当前语言，表单里不会出现状态码。

宿主在每次请求时按需取 `llm` 服务，并且刻意不把它写进插件的 `inject`：没有模型的部署也必须能挂载整个看板，此时路由回 `no-model`，而不是插件加载失败。解析用一次 `llm.stream` 调用，路由取自限定的 `provider/model`，system 提示要求只回一个 JSON 对象，预算 45 秒，并接入「客户端断开即中止」。提取会去掉代码围栏、读取第一个 JSON 对象；回复不可用时标题与 Prompt 回退到用户粘贴的原文，用户写的东西不会丢。

解析结果只填标题、描述和执行 Prompt 三个字段。在用户提交之前不会有任何内容进入账本，因此模型无法自行创建或执行任务。

## Alternatives considered

从第一个已注册 provider 猜一条路由：否决。报告者要的是用户可见的选择，静默猜测会花掉任意一个模型的额度。

把 `llm` 写进插件的 `inject`：否决。cordis 对缺失注入服务的插件会拒绝加载，一个没有模型服务的部署会把整个看板一起拖下水。

把 `@deepseek-ai/dsh-llm` 声明进本包自己的 devDependencies 是首选做法，但在这里做不到：当前检出连不上本工作区 SDK 包所用的注册表，无法把版本写进 lockfile。类型图改由根 devDependencies 满足；运行时导入仍然合法，因为 runtime-deps 门禁把 `@deepseek-ai/*` 视为宿主提供。

用 schema 库校验模型回复：否决。草稿只有三个字符串，表单本身就是复核环节，手写提取加回退提供了同样的保证、面积更小。

由模型回复直接创建任务：否决。粘贴内容可能带注入指令，用户必须在字段变成任务之前看到它们。

## Consequences

每次解析都会消耗部署自己的模型额度；动作是显式的、可取消的，并受超时约束。回来的只有三个字段，标签、计划与执行钉住仍需手动设置。模型调用本身没有在本仓库的环境中跑过——这里没有模型通道——所以交付的证据是一个假的 `llm` 服务，加上路由、传输层与表单的测试。

## Testing

`tests/host-ai.spec.ts` 覆盖路由拆分、回复提取、回退、中止与超时、空粘贴；`tests/host-routes.spec.ts` 覆盖围栏、每种失败状态与输入上限；`tests/host-api.spec.ts` 覆盖浏览器侧分类；`tests/ai-parse.spec.tsx` 覆盖区块可见性、回填与失败文案。
