# Agent Note: LiangShen mode native rebuild for DeepSeek V4.1 Flash

Status: implemented

Partially supersedes [minimal persona plus an injected standard tool catalog](2026-09-11-liangshen-minimal-prompt-tool-catalog.md) on the persona text and the staged wire: the working discipline is replaced with action-triggered rules, and the anchor turn plus the second-turn PTC promotion are retired, while the minimal-persona mechanism, the injected-catalog mechanism, and the message-source decision still hold. Partially supersedes [four-tool anchoring and PTC contract refinement](2026-09-12-liangshen-anchor-tools-and-ptc-refinement.md): `anchorTools` first-turn narrowing is removed and `ptcPresentation` is replaced by the three-value `presentation` key, while the honest activation semantics, the request-surface catalog contract, and the three-tier validation standard still hold. Partially supersedes [the request-surface tool catalog and evaluation tooling](2026-09-13-liangshen-request-surface-catalog-and-eval-tooling.md) on the presentation boundary the catalog tracked — the wire no longer changes at a turn boundary — while its declare-exactly-what-the-request-opens principle and the evaluation tooling still hold. Partially superseded by [remove liangshen dynamic reasoning effort](../simplification/2026-09-17-remove-liangshen-dynamic-reasoning-effort.md) on the phase-aware reasoning effort mechanism and its settings fields. Resolves the default-selection stage of [the LiangShen V4.1 Flash improvement plan](../../proposed/feature/2026-09-13-liangshen-v41-flash-improvement-plan.md) on published official evidence instead of a local paid matrix. The full design rationale lives in `docs/liangshen-v41-flash-optimization.md`.

## Problem

The two-stage design — a natively presented anchor turn followed by a second-turn PTC promotion — was built on pre-release community assumptions about DeepSeek V4 behavior, not on official evidence. The DeepSeek-V4.1-Flash technical report's own scaffold comparison places the native minimal surface ahead of the PTC surface on code-agent benchmarks (DeepSWE v1.1: 72.6% vs 67.6%; Terminal-Bench 2.1: 90.6% vs 85.8%), and the promotion boundary forced every tool besides `run_code` through generated-SDK programs, adding syntax and runtime failure modes the native DSML surface does not have.

At the same time the mode could not retreat to a closed four-tool surface: real engineering sessions depend on MCP servers and plugins, while a flat roster carrying every external schema crowds the model's sparse-attention budget (CSA2 retrieves a bounded Top-K of compressed blocks per query, so a large static schema surface displaces conversation content). The persona's abstract loop-avoidance line also proved too weak against the RL self-correction bias that drives closed-loop reasoning when a tool result contradicts the model's expectation.

## Decision

The preset keeps one wire presentation for the entire session and moves external-tool discovery onto a gentle paging mechanism.

- `tool-catalog` gains a `presentation` key with three values: `native` (the assembled native roster), `ptc` (the wire collapses to `run_code`, other tools reached through the generated SDK; **the shipped default**), and `both` (the full native roster with a co-resident `run_code` as an ordinary atomic tool). Choosing `ptc` as the default is an **unmeasured trade**: it takes the native roster's schema payload out of every request, the cheapest static context of the three, while the official published scaffold comparison ranks that presentation below the native surface (DeepSWE v1.1: 67.6 against 72.6; Terminal-Bench 2.1: 85.8 against 90.6). This repository has not run the bundled benchmark matrix that would settle it; `presentation: 'native'` is the one-line opt-out. `both` and `ptc` need a mounted code runtime and degrade to `native` with a one-time warning when it is missing. There is no turn-boundary transition anymore: the chosen presentation applies from the first request to the last. The legacy `ptcPresentation` key maps onto `'ptc'`/`'native'` with a deprecation warning; `anchorTools` first-turn anchoring is retired, and setting it warns without narrowing the wire.
- Gentle tool paging: `pagedToolPatterns` (default `['mcp__*']`) holds matching tools off the executed surface — a scoped `tools.restrict` removes them from the scope's visible set, so they leave both the assembled wire and the generated-SDK declarations — until the model activates their namespace through `tool_activate({ namespace })`. Held-back namespaces appear in the injected catalog as one-line summaries, at most three paged namespaces stay active at once (activating a fourth evicts the least recently used one back to its summary), and activation state is rebuilt from the durable session event stream, so compactions and resumes restore the same surface.
- The persona's working discipline is replaced with action-triggered rules: a repeated hypothesis is closed after two reasoning passes in favor of an inspection tool call, thinking determines the next concrete operation instead of pre-rehearsing code, and verification runs against actual tool output. The `tool-result-pruner` tightens to 4096/1500/500 characters (threshold/head/tail). The preset-local win32 Git Bash shell this decision shipped has since been retired in favor of the upstream persistent pwsh twin of the shell stack, which also removed that platform-only persona line; see [the shell and paging decision](2026-09-17-liangshen-shell-and-paging-ptc-surface.md). A minimal working-context line (plan-mode state, active paged namespaces, in-progress todos) is injected at the tail of the latest message only when its sources are readable.
- The static schema surface itself is watched by a diagnostic guard: `maxResidentTokens` (default 6000) estimates the always-on-wire surface from the serialized schemas at roughly four characters per token, and warns once per session when it is crossed, naming the heaviest tools and `pagedToolPatterns` as the remedy. The default is deliberately calibrated above this preset's own shipped roster: gentle paging keeps every non-`mcp__*` tool resident, that roster already measures in the low thousands of estimated tokens, and a ceiling below the factory baseline would fire on every ordinary session and train the reader to ignore it. The guard warns and never truncates — silently dropping a tool the session needs would trade a measurable context cost for an unmeasurable capability loss. The tools of an activated paged family are listed under their namespace heading in the catalog while every non-paged tool keeps its flat entry, and the persona gains a `Bounded Output` rule (filter at the source with grep/head/tail/wc instead of pouring a large command output into the conversation), because long-range attention is a bounded budget the session's own constraints must not be evicted from.
- The plugin's web settings surface carries the preset-shaping fields (`presentation` and the guard switches). The settings surface edits the plugin's own Config while the values that shape a session live in the preset's rows; the two meet at declaration, where the plugin rebuilds the rows from its shipped `agent.cordis.yml`, merges the committed values into the rows they address, and re-declares the preset, so the operator's choice is what sessions actually run. A row the composition does not carry is never invented: the overlay narrows the shipped configuration, and no file is rewritten.
- Phase detection recognizes three cases: an explicit plan mode, a failure-driven review stretch (opened by a failed dispatch and closed by the next successful one), and execution. The review level defaults to the planning level because diagnosing a failure is the same kind of work as forming a plan. Pairing failure with the next success is what keeps a fix-it loop deep from the breakage to the working fix, instead of switching on every tool call.
- Phase switching is gated by an `autoEffortByPhase` switch that ships OFF: while off the plugin registers no request listener, so a request is byte-for-byte what the deployment would have sent anyway; turning it on takes over the reasoning level from the next phase boundary. It defaults off because a session's reasoning level is a visible, explicit choice in the model picker, and silently overriding it would make that choice look broken — while opting in also keeps a feature most deployments never need off the hot path.
- A `reasoning-effort` plugin joins the host's `agent/request` waterfall (the API catalog documents that event as a waterfall whose summary is "Replace the frozen call configuration", dispatched agent-scoped) and swaps the request's `reasoningEffort` from the planning level (default `'high'`) to the execution level (default `'low'`) at a plan-mode boundary. It switches only at that boundary because the field is part of the request-header snapshot that governs cache reuse — flipping it every turn would pay a cache miss per turn to save reasoning tokens. Levels are validated against `'off' | 'low' | 'high' | 'max'`; the switch is skipped when the routed model's offered set is readable and excludes the wanted level, and a throwing projection is treated as "cannot confirm" and skipped rather than risking a level the route may reject.
- `tool_activate` declares `isConcurrencySafe: () => true`. The host dispatcher already classifies calls through that self-report (`executionMode()`: only an exact `true` joins a parallel group, everything else is exclusive and forms a barrier, with results committed in submission order), while this preset declared it nowhere and so degraded every tool of its own to exclusive. The handler only reads the event stream and returns a report — the activation itself is the durable `tool/call` event the runtime appends for this call — so it is concurrency-safe.
- One capability is genuinely left to the DSH core rather than implemented in this repository, and is documented in `docs/liangshen-v41-flash-optimization.md` section 8: the `namespace::function` tool mapping (the `dsh-tools` registry and wire serialization), plan-mode-driven `reasoning_effort` (the `dsh-llm` request assembly hook), and a read-parallel/write-serial barrier in the tool dispatch engine.

## Testing

- The tool-catalog suite pins the three presentation modes, the co-resident `run_code` under `both`, the one-time degradation warning when no code runtime is mounted, the legacy-key mapping warnings, and the `anchorTools` retirement warning.
- The paging behavior is pinned at the pattern match, the wire exclusion of held-back tools, the namespace summaries in the catalog, `tool_activate` mounting from the next request, LRU eviction at three active namespaces, and activation rebuild from the durable event stream across compaction and resume.
- The minimal-prompt suite pins the replacement discipline text, the win32 ephemeral-shell line, and the working-context projection gating; the preset-composition suite validates the shipped `agent.cordis.yml` with the new keys.
- The resident-budget guard and the catalog grouping are each covered: the estimator against an empty surface, an unserializable malformed schema, and the four-characters-per-token conversion; the over-budget warning firing once per session, staying silent when the surface fits, going silent when the ceiling is raised, and rejecting a non-positive ceiling through config validation. Grouping covers an activated family appearing under its namespace heading with each tool named exactly once, and no namespace field appearing when no paging pattern is configured.
- The stable-prefix invariant has a regression test: editing a workspace-instruction file leaves the persona and plan-policy sections byte-identical and moves only the appended section's variable value — the precondition for the encoder's prefix KV cache to be reused.
- The `reasoning-effort` suite pins the phase decision (a `plan/mode` event wins; with none, a first turn counts as planning), the per-phase level resolution, the skip when the offered set excludes the wanted level, identity preservation when the frozen config already carries that level (an unchanged request must not be replaced, or the header snapshot churns), that identity across a long execution stretch, the conservative skip on a throwing projection, config validation, and that a missing agent or a throwing session fold never fails the request.
- The repository gates for this change are `pnpm i18n:check` and `pnpm docs:check`. No paid A/B run is part of this change: the default follows the official published scaffold comparison, and the benchmark matrix remains the instrument for any future statistical claim.

## Alternatives considered

- Keep the anchor turn with second-turn PTC promotion. Rejected: the official scaffold comparison places PTC behind the native minimal surface on code-agent benchmarks, the turn-boundary transition invalidates the prefix cache exactly once per session, and every tool besides `run_code` pays the generated-SDK syntax and runtime tax after the boundary.
- Retreat to a closed four-tool minimal surface. Rejected: MCP servers and plugin tools become physically unreachable, which is unacceptable for real engineering sessions even though it maximizes closed-set benchmark scores.
- Carry the full flat native roster, external schemas included. Rejected: the static schema surface crowds the bounded sparse-attention index and degrades tool-selection precision as the roster grows; paging exists precisely to keep the static surface small.
- Page every non-core tool, not just the external patterns. Rejected: everyday built-ins would pay an activation round-trip on routine work; the shipped default pages only `mcp__*`-style external tools, which are both the schema-heavy and the less-frequently-used kind.
- Implement the namespace mapping, the dynamic reasoning effort, and the dispatch barrier inside the preset. Rejected: all three belong to host-owned seams (tool registry and wire serialization, request assembly, dispatch scheduling); a preset-local fork would duplicate host semantics and conflict with other presets.

## Consequences

- The wire no longer changes at a turn boundary: the persona prefix and the presentation stay stable for the whole session, and the injected catalog republishes only on a real surface change (a paged activation, a presentation change, or a compaction shadowing).
- External MCP tools stay reachable without a flat schema explosion: they are announced as one-line namespace summaries and mounted on demand, with at most three paged namespaces active at once.
- `run_code` remains available for computation-heavy work as an ordinary tool instead of displacing native interaction as the session's sole transport.
- The declaration is rebuilt from the shipped `agent.cordis.yml` at activation and after every committed settings write, so sessions created after an upgrade compose the new wire behavior; nothing is written into the harness home, and histories persisted by earlier revisions keep their injected catalog messages (the `plugin` source kind is unchanged).
- The verification hierarchy is unchanged: a real inference probe is not a mode-integration pass, and neither is a statistical improvement; any future performance claim goes through the benchmark matrix with recorded baselines.
