# Agent Note: LiangShen mode can append the dispatcher rule set

Status: implemented

Extends [the V4.1 Flash native rebuild](2026-09-16-liangshen-v41-flash-native-rebuild.md) on the persona content and [bounded inspection and convergence](2026-09-18-liangshen-bounded-inspection-convergence.md) on the working discipline: both keep their decisions, and the appended block composes with them rather than replacing either.

## Problem

The LiangShen persona is deliberately minimal: one line of identity plus a standing working discipline of a few rules. That shape pays off for a session that does its own work, and it is the wrong shape for a session whose job is to run other sessions. A dispatcher has to decide how large a task is before working on it, decide whether its peers are teammates or sub-agents before dispatching, hand off a task book with boundaries and acceptance criteria, verify a report against evidence instead of a self-report, and know where its own authority stops. None of that is inferable from a discipline that never mentions delegation, and a session left to improvise it invents a different process every time.

That process already exists, reviewed and written down, in the separate dispatch preset of the subscription repository's data plane: a `[Role Identification]` paragraph that tells a sub-agent which rules do not reach it, a `[Coordinator Identity]` paragraph, R0 through R8 with R-W, and a closing anti-pattern list. Re-deriving a shorter version locally would produce a second, divergent process for the same job.

The carried set is one-sided, and its one-sidedness is the part that did not survive contact with real sessions. Its anti-patterns punish asking too little — planning or editing before the requirement is clear — and nothing in it punishes asking too much. A dispatcher therefore holds an unbounded licence to interview: no question budget, no exit for a user who does not want an interview, no rule for folding new evidence in without reopening settled decisions, no statement of what "understanding is aligned" asks the user to confirm or where that conclusion lands, no requirement that a recommendation carry its reason, and no form at all for the one or two questions R0 already grants an L1 task. Each missing rule is a way for a session to spend the user's attention instead of its own.

## Decision

A new boolean `dispatcher` on the LiangShen Config (schema default `true`, `volatile()` like every other preset-shaping field) writes the `dispatcher` key into the declared preset's `minimal-prompt` row through `applyPresetOverrides`, exactly as `presentation` writes into `tool-catalog`. On, `minimal-prompt.mjs` appends the dispatcher rule block to the persona section after the workspace line; off, the assembly returns to the bare persona byte for byte.

The shipped default is ON: the mode's dispatch capability is what an operator gets from a fresh installation rather than something they must discover and enable, and the settings switch is what returns a session to the persona-only surface. The plugin's own fallback in `minimal-prompt.mjs` agrees with the factory row, so a row that loses the key and an activation with no config resolve to the same value.

- The rule text lives in a new pure-text module, `presets/liangshen/dispatcher-rules.mjs`, exported as `DISPATCHER_RULES`. It carries the upstream text from the role-recognition paragraph through the closing anti-pattern list: the `[Role Identification]` paragraph, the `[Coordinator Identity]` paragraph, R0, R0.5, R-G, R1 through R5, R6, R-W, R7, R8, and the twenty anti-patterns. (Re-extracted 2026-10-18; the corrections folded in place are recorded in [the maintenance note](../../architecture/2026-10-18-liangshen-dispatcher-rules-maintained-in-place.md).) Relative to the block this decision originally carried, the text also brings the `[Execution Pipeline]` line under the identity paragraph, the R-W turn-boundary section, and the anti-patterns 13 through 16 that enforce it. A session that turns the switch on runs the upstream reference block, not a local summary of it, and the block carries no R-T: this mode dispatches sub-agents and refuses Agent Teams rather than degrading into it, so R0.5 is where a teammate-class tool surface stops the session and hands the user the exit choice.
- Later changes to the rules are APPENDED, never folded in. **Superseded for corrections** (2026-10-18): additions still go into the appendix, while a sentence the upstream lineage has corrected is rewritten where it stands — an appended correction leaves the model holding two rules for one decision, and the stricter reading wins without anyone checking. See [the maintenance note](../../architecture/2026-10-18-liangshen-dispatcher-rules-maintained-in-place.md). `DISPATCHER_RULES` holds the upstream text and `DISPATCHER_RULES_APPENDIX` carries the local additions; `DISPATCHER_RULES_WITH_APPENDIX` composes them and is what the prompt appends. The appendix is English, holds the local interview entries G7 through G14 with two locally added violations, and adds G15 — the one rule upstream has no counterpart for, keeping the task board a tracking surface rather than a dispatch path. The appendix opens by declaring itself a local supplement that wins where it conflicts with G1 through G6, so one fact still has one home. `withDispatcherRules` checks the two halves separately: a persona that already carries the reference text still gains the additions, and neither half is ever appended twice.
- What the appendix adds: G7 budgets the asking — at most four questions per round, three rounds, ordered by blast radius, and no question whose two answers would not change the path, the acceptance criteria, or the cost; G8 gives the assumption exit (list the assumptions you will proceed on, never skip silently); G9 folds new evidence into the affected branch only; G10 names the confirmable object — a four-line interview record whose settled decisions and hard constraints are registered as facts — and reads "either is fine" as delegation, with no second asking of a settled decision; G11 requires a recommendation to carry its reason and its refutation condition, and separates observation from attribution; G12 records the question path a collapsed wire uses and the degradation when the tool is unavailable; G13 gives L1 the minimal form of G3; G14 exempts read-only fact-check dispatches from R5's precondition, which R5 already scoped to implementation; and G15 — the one rule here with no upstream counterpart — states the task-board consequence: a card is not a substitute for an R5 dispatch, and the task list itself stays in `todo_write`, pinned by the reference text's own R-W section.
- OWNERSHIP. The text came from the `dispatch` preset of `@eddyskywalker/dsh-chatgpt-subscription` (github.com/Aa728848/dsh-chatgpt-subscription), a third-party package that ships from npm and has no writable checkout on this machine or in this repository. The block started as that upstream text at version 0.24.6 — its persona prefix in the original English — and is maintained in this repository from the 2026-10-18 re-extraction on: `DISPATCHER_RULES_PROVENANCE` names the origin, the inherited version, the re-extraction date, and every correction folded in place, while `tools/check-dispatcher-rules.mjs` reports drift against an installed copy. Parity with upstream is not a guarantee this repository holds: the rule set is owned here and evolves here, the frozen constant is replaced whenever upstream's text is adopted, and every local addition lives in the appendix beside it.
- The upstream text arrives whole, with no locally adapted sentence. Its model-routing paragraph describes the runtime route guard by what it does — a sub-agent model authorization guard enabled in DSH's own sub-agent settings, on by default — and names no repository and no configuration key. The single removal is the template line upstream opens the block with.
- The identity line above the `[Role Identification]` paragraph (`You are powered by {{model}}. Your working directory is {{cwd}}.`) is not carried. Its placeholders belong to that preset's own renderer; LiangShen binds no such variables, and a stray `{{...}}` in a section whose text the harness interpolates would throw on every request. LiangShen already appends its own workspace line to the persona.
- `minimal-prompt.mjs` imports the constant and appends it from `withWorkspaceLine`, so ORDER is fixed by construction: the persona, its discipline, the workspace line, then the appended rules. The two are separated by a two-line heading (`## Dispatcher rules (a mode-level append)`) that names the block and states the discipline above it stays in force, so the rules read as an announced addition rather than as one more persona bullet. The append is idempotent: a section that already carries the block is left alone.
- `dispatcher` and `presentation` are orthogonal. The switch changes the PROMPT only; the tool surface is whatever `presentation` selects. No tool, no row, and no repository plugin changes because of it.
- The factory `agent.cordis.yml` carries `dispatcher: true` on the `minimal-prompt` row, and the row's comment states the semantics. The key is present rather than absent so the overlay writes a value onto a key the row already declares, which is the same shape the `guard` and `tool-catalog` rows ship.

## Testing

- `packages/dsh-liangshen/tests/minimal-prompt.test.ts` pins the byte-identical off state (the persona section equals the persona plus the workspace line, the section list is unchanged, and no dispatcher prose appears anywhere in the assembled sections), the on state (the appended text is exactly the heading plus `DISPATCHER_RULES_WITH_APPENDIX`, the persona discipline stays ahead of it, and the section list is unchanged), the full rule coverage (identity, R0 through R8 including R-W, and the anti-pattern list all present), the absence of the subscription repository's name and of unbound `{{...}}` placeholders, rendering through the harness renderer, the no-cwd case, idempotency, and that the appended block never lands in the `workspace-instructions` section.
- `packages/dsh-liangshen/src/composition.test.ts` pins the factory row (`dispatcher: true` present in the shipped `agent.cordis.yml`), that an unset `dispatcher` writes no key at all, that a committed `true` writes the key and leaves the row's other keys untouched, and that the `tool-catalog` and `guard` rows do not move.
- `packages/dsh-liangshen/src/index.test.ts` pins the schema default and the volatile reference, and that every `presentation` / `dispatcher` combination resolves independently.
- `packages/dsh-liangshen/tests/preset-composition.test.ts` pins the factory row's `dispatcher: true` alongside its existing config keys.
- `packages/dsh-liangshen/tests/minimal-prompt.test.ts` also pins the appendix boundary: the reference constant still ends at the last upstream anti-pattern and carries no `G7`, the appendix carries none of the reference headings, the composed constant is exactly the reference plus the appendix, every addition appears exactly once and after the last anti-pattern, and a persona that already carries the reference block gains the additions exactly once. The local task-board rule is pinned like the rest: it sits in the appendix rather than in the reference constant. The three exact-text assertions compose `DISPATCHER_RULES_WITH_APPENDIX`.
- The question path is probed live rather than assumed. A question dispatched from inside a `run_code` program through `tools.ask_user_question` rendered its card and returned its answers, which is what G12 tells the model to rely on under a collapsed wire. The paged-namespace restriction cannot withhold this tool: paging matches `mcp__*` names only, and the collapsed `ptc` wire differs from `both` in what the model may call directly, not in which tool a program can reach.

## Alternatives considered

- **Carry only a condensed dispatcher rule set.** Rejected. LiangShen's minimal-persona philosophy is in real tension with a roughly ninety-line append, and a short version would have been the cheaper answer for the context budget. It loses on a different axis: the rules are not a style guide but a process with interlocking parts. R2's routing decision is what R5's task book relies on, R6's two-strike rule is what makes R8's fallback bounded, and the anti-pattern list is what makes the whole thing enforceable rather than advisory. Trimming it means choosing which guarantees to drop, and the resulting set is neither the reviewed one nor a coherent shorter one — it is a third process nobody reviewed, which is exactly the divergence this decision exists to avoid. The dispatch mode is also a self-referential risk: a dispatcher that invents its own dispatch process is the failure the rules describe. The full set is carried, and the cost is paid where it belongs: the switch is one key an operator can turn off, and a session on the bare persona is byte-for-byte what it was before the switch existed.
- **Rewrite G1 through G6 in place instead of appending the missing rules.** Rejected. Those sentences are the artifact another reviewer signed off, and editing them would leave this note's verbatim claim, the module's origin comment, and the reviewer's text all describing something that no longer exists — with no marker of where the reviewed part ends. Appending keeps the reference readable as what it was, and a single precedence line settles the only question two homes raise: which text wins.
- **Keep byte-level parity with the third-party preset, by hand or by contributing the additions upstream.** Rejected as a constraint on this repository. The upstream ships from npm, has no checkout here, and has itself moved past this block, so parity is unmaintainable and would freeze LiangShen's interview discipline to a schedule it does not control. The appendix states what this repository stands behind; a deployment that also runs that preset will see two generations of the same process, which is a visible difference rather than a silent one.
- **A separate `dispatcher` agent preset beside LiangShen.** Rejected. The mode is a discipline, not a tool surface: a second preset would duplicate the composition, the guard, the paging, and the settings card so that one boolean could differ. The switch keeps one composition and one settings surface, and the operator picks per session by toggling one field.
- **Fold the rules into the persona `prefix` in `agent.cordis.yml`.** Rejected. The prefix is a block scalar the composition reader parses; a ninety-line addition would make the factory persona and the appended rules indistinguishable in the one file a maintainer reads to see what the mode says, and it would give the operator no switch. The switch also keeps the off state byte-identical, which a prefix edit could not.
- **Rewrite the rules in English to match the rest of the preset's prose.** Rejected. The reference text is the reviewed artifact; translating it re-opens wording that was settled, and the surrounding persona already mixes languages by design.
- **Bind `{{model}}` and `{{cwd}}` so the identity line can ride along.** Rejected. `minimal-prompt` does not own the assembly's variable map, and `{{cwd}}` would duplicate the workspace line the plugin already appends from the session header — the same fact in two places, drifting the moment one of them changes.

## Consequences

- A session created with the switch on is a dispatch agent: its deliverable is the plan, the task book, the review verdict, and the hand-off, and the delegation rules apply from the first request. A session with the switch off is unchanged.
- The appended block travels inside the persona section, so it is prompt text on the stable prefix. Turning the switch on changes that prefix once, at session creation, and the prefix cache is reused from there; toggling it mid-session re-declares the preset and the next session composes the new prompt.
- The dispatch rules assume capabilities the session may not have (no sub-agent tool, no model-selection switch). R2 is written to detect those cases, which is why the rule carries its own availability detection rather than relying on the deployment to guarantee it. The mode once also carried an R0.5 compatibility gate for a teammate-class tool surface; that gate was removed in the 2026-11-13 re-sync because the harness generation which could present such a surface no longer exists, and the task-board contract that outlived it is now the standing [Agent Teams Board] paragraph.
- LiangShen carries no sub-agent model authorization guard of its own; a deployment that wants R2's [available] branch enforced supplies one outside this package. Without it the [unavailable] branch is what a session observes.
- The switch is orthogonal to `presentation`, so the two can be combined freely; the settings surface exposes them as independent fields.
- The block and the third-party `dispatch` preset it came from are two copies of one text, and that preset is installed on some machines beside LiangShen. The two hold still only while upstream holds still: the block tracks any later revision of that preset, while the local additions are the part this repository owns, and a session reading the block sees the upstream text and then a supplement that says it wins. A deployment that never reads the appendix runs the upstream rules unchanged.
- G7's budget is a prompt-level cap, not a mechanism: nothing in the runtime counts questions, so the number holds as long as the model honors it. The measurement that would show whether it does — questions per task and interventions per task — is already emitted by `tools/benchmark-live-run.mjs`'s `summarizeSession`, but no task in `tools/tasks/liangshen-v41-flash.json` exercises an interview, so the additions ship unpinned by any scenario. Adding one ambiguous-requirement task and one clearly-specified control task is the next step that would make the budget falsifiable.
- The local task-board rule closes a path rather than adding a capability: a dispatcher that reaches for a board card in place of the R5 dispatches has replaced a delegation with a note about one. Like the interview additions it is prompt-level — nothing in the runtime routes a delegation — so it holds as long as the model honors it, and it governs only sessions that run this block.
