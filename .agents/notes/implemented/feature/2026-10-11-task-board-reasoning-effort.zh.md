# Agent Note: 任务看板思考强度

Status: implemented

## Problem

任务可以钉住执行模型，却无法指定该模型使用的思考强度。官方模型目录已经声明适配器拥有的思考档位，但看板在构建模型选择项时丢弃了这些数据。

## Decision

任务新建与详情在模型选择器旁提供思考强度选择器。候选项来自该模型的官方 `session/modelCatalog` 元数据，而不是通用列表。留空沿用模型/宿主默认值。切换到不支持已存档位的已知模型会清空选择；未知或已移除的路由不被静默改写。

`reasoningEffort` 是可选的任务执行字段，经现有严格的创建/更新动作与账本传递，runner 在选择执行模型时将它带入官方 `session/selectModel` 请求。复用已有会话的启动路径采用同一选模逻辑。清空在线上传递空字符串，因为 JSON 会省略值为 `undefined` 的属性。此增量字段不改变账本 schema 版本。子任务自行钉住模型而留空档位时，使用该模型默认值，不借用祖先档位。未钉住模型时可继承祖先的模型/档位组合，子任务自己的档位仍优先。导入同时保留两个字段。携带显式且已声明档位的选模请求被拒绝时，此次执行在 Prompt 入队前失败。

该字段控制任务执行模型。[子任务决策](2026-09-24-task-board-subtasks.md) 拥有父子关系与 Team 执行，本记录不重新定义 teammate 路由。

## Alternatives considered

**为所有模型提供统一的 low/medium/high 列表。** 未采用：适配器拥有各自支持的 id，不支持的 id 会产生原生选模错误。

**只添加下拉框而不增加执行字段。** 未采用：表单会展示 Host 从未应用的偏好。

**为可选字段升级账本 schema。** 未采用：现有可选执行目标已使用增量归一化，升版带来不必要的兼容风险。

## Consequences

未声明思考档位的模型没有可选档位控件。能力发现是权威来源，看板不按模型名字猜测支持情况。显式选择随卡片保存，留空保留原生默认行为。必要验证覆盖目录映射、创建/更新/清空与持久化、模型切换、任务详情，以及新建与复用会话的选模请求。
