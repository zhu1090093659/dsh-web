# Agent Note: 任务看板卡片界面收敛到同一份呈现契约

Status: implemented

## Problem

看板的每个界面都在回答同一个问题——这张卡是什么、跑起来会怎样——但各自用了一套尺度。详情面板把九个同重量的按钮、四个字号（15/13/12/11px）和一份完整验收报告塞进每一行执行记录，于是一张有三十四次执行的卡片把同一句机器说明重复了三十四遍，扫读层里没有任何信号。看板列与卡片用第二套尺度（11px 与 10px 的元信息行），对话框用第三套（12.5px 的区域头），面板里的 Markdown 渲染器用第四套（16/15/14/13/12.5/12/11px，h2 与 h3 只差 1px）。仓库里没有任何机制让这些预算可被检查，所以每块界面自己漂移。

## Decision

一份呈现契约由 `packages/dsh-task-board/src/client/board.module.css`、`task-markdown.module.css` 与看板的三语字串表声明，并由 `tests/responsive-css.spec.ts` 机械校验，约束面板、看板列与卡片、对话框以及 Markdown 渲染器。

### 字号尺度

一个界面最多渲染三档字号，其余层级由字重与颜色承担。面板为 15（标题）、13（正文）、12（元信息）；对话框为 16、13、12；Markdown 渲染器 h1 与 h2 用 16、h3 至 h6 与正文用 13、代码与图片占位符用 12，层级由字重（700/600/600/600/500/500）与颜色（`label-primary`、`label-secondary`、`label-tertiary`）承担。任何界面都不再声明 11px 或 12.5px。

### 结果槽位

状态与结果徽标按结果读取同一个填充槽位：warn 是静止态，success 与 error 读取各自的 `-secondary` 底色配 `-primary` 文字，cancelled 读取中性的 `interactive-bg-hover`。任何徽标家族都不再保留透明填充，因此同一种徽标不会用两种颜色到达同一状态。六色标签调色板是声明的例外：它标识标签身份，不标识状态。

### 折叠

折叠是一种行为、一份契约。区域行拥有 `aria-expanded`、`aria-controls` 指向的 id、`data-open`、chevron、描述收起区域内容的一行摘要、成对的进入与退出动效（`dshTbRowsIn` / `dshTbRowsOut`，同一组缓动与时长；reduced-motion 下只留 opacity）、退出腿跑完才卸载，以及「持有焦点的区域体关闭时把焦点交回区域行」。面板折叠、对话框分区与执行记录都骑这一对动效（原验收报告在 [2026-11-11 移除](../simplification/2026-11-11-remove-task-board-goal-run-and-acceptance.zh.md)前同属此列）；全文件只声明一对 `@keyframes`。

### 阅读顺序与节奏

视口宽于等于 1024px 时面板是两条轨——左栏放内容，右栏放这次执行会怎么跑——窄于此按同一顺序退回单栏。工作区、预设、权限、模型与思考档位常驻可见；会话复用开关折叠进一行「运行方式」（`detail.settings.run`，在 [2026-11-11](../simplification/2026-11-11-remove-task-board-goal-run-and-acceptance.zh.md) 移除原 `/goal` 与跳过验收开关时由最初的「高级设置」统一为此标题），其收起摘要回显是否已开启。定时运行与执行记录各占一行折叠，摘要说明状态，执行记录默认列出五次、展开才看全部。状态移动收为一个菜单，页脚保留一个主行动、一个次要行动与一个危险行动，创建戳位于主行动与危险行动之间。

相邻折叠构成一个分组（`.detailFolds`，8px），不参与 16px 的大节节奏，因此折叠行是 30px、两折叠之间的节距是 38px，改动前是 58px。

## Testing

`tests/responsive-css.spec.ts` 解析声明并逐项断言预算：详情区的字号集合等于 {12px, 13px, 15px}，对话框区等于 {12px, 13px, 16px}，Markdown 渲染器等于 {12px, 13px, 16px}，折叠行盒不超过 30px、组间距不超过 12px、折叠节距不超过 44px，每条徽标规则只有一个填充底色，改动行里没有字面色，面板与对话框两条腿共用一对 keyframes。`tests/task-detail-panel.spec.tsx` 断言阅读结构：展开前只列五次执行、收起折叠的摘要回显会话复用是否开启、页脚三个动作按顺序排列。

## Alternatives considered

只折叠长说明而不压缩它们是最初的提案，但它放过了根因：文案本身就是缺陷，因为四段 60 到 90 字的说明各自在重述该行已经写明的开关。决定改为每个开关一行、长说明降级为行上的悬浮提示。

纯视觉打磨——只调间距、颜色与字重，不动文案与结构——被否决，因为最响的两条问题都是结构性的：重复的验收句存在于数据的呈现方式里，九个同重量按钮是顺序缺陷而不是间距缺陷。

把权限确认门与状态徽标也折进该开关折叠行（历史设计时称「高级设置」，[2026-11-11](../simplification/2026-11-11-remove-task-board-goal-run-and-acceptance.zh.md) 起统一为「运行方式」）被否决。阻塞性确认与卡片当前所在列都是需要人行动的决定，任何折叠放在它们前面都会把可见的义务变成隐藏的义务。

重录 `test-standards` 基线来替代改写这次改造引入的断言被否决。门禁的 `基线 -> 当前` 计数显示十条只断言存在性的断言、一个不含角色的标题、六段没有写明前置条件的正文，全部由本次工作引入；重录会把这份债冻结，并藏在一次绿色的运行后面。

把面板的作用域覆盖共享给对话框的基座规则被否决：对话框保留自己的节奏（8px 区域间距、8px 10px 10px 区域体内距），只有它的区域头加入契约，于是两块界面在行为、字号与槽位上一致，而互不规定对方的间距。

为面板另写第三套折叠组件被否决：两套实现会在一个发布周期内让键盘与动效行为发生分叉。

## Consequences

面板折叠不再裁剪，44px 命中区才装得进 30px 的行盒：`.detailBody .formSection` 是 `overflow: visible`，内圆角改由区域头自己承担。在 8px 的间隙里两个 44px 目标重叠 6px，所以间隙的下半部分归下一行。行本身是 30px，高于 WCAG 2.5.8 的 24px 下限，而收紧节奏是明确的要求，因此接受重叠，而不是用 44px 的节距来偿付。

`.cardTag` 同时服务卡片与面板的标签行，所以它的 12px 会作用到两块界面；这是有意为之，不是泄漏。卡片自己的尺度——列、卡片、密度——由同一份 spec 在它自己的区段切片里断言。

两块界面有意留在这份契约之外：看板设置卡（`settings-card.module.css`，属于设置界面而非卡片界面）与六色标签调色板。

所有关于渲染几何的断言——真实 1024px 视口下的两条轨、三行摘要共享的右缘、圆角从节移到区域头后的悬浮填色、触屏上的 44px 目标——都只由声明与 DOM 结构证明。jsdom 没有布局，本次会话也没有重载运行中的 GUI，因此截图复核仍然是这些结论的证据。
