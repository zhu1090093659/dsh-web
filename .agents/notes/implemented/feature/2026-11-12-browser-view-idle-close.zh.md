# Agent Note: 浏览器视图的闲置自动关闭

Status: implemented

## Problem

浏览器视图打开的页面会一直开着，直到有东西把它关掉。隔离模式下它活在只有这个插件会说话的浏览器里，一个被遗忘的页面就一直占着一个渲染进程和它的内存，直到插件卸载。真实浏览器模式下这些页面就在用户自己的窗口里，一个没人认领的 agent 标签页正是干完活之后留下的那堆杂物。关闭契约刻意保持显式——隐式关闭可能毁掉未保存的工作——但"显式"让 DSH 自己创建的页面失去了主人：打开它的那个会话，等到这件事要紧的时候通常早就结束了。

## Decision

标签页带上闲置时钟，由宿主扫描。`TabRecord.lastActiveAt` 在接入 target 时落一次，之后只由 `TabManager.touch` 刷新；`BrowserViewService.tabFor` 解析出标签页之后才调它，因此任何作用到某个页面的 `browser_*` 调用都会重置那个页面的计时，而在面板里看它、选中它的 chip、以及投屏帧都不算。`TabManager.idleCandidates(maxAgeMs)` 返回时钟早于窗口、且 `origin` 为 `created` 的标签页。

`BrowserViewService.sweepIdle` 每十分钟跑一次，定时器 unref、dispose 时清除；窗口每次扫描现读，每个候选都走既有的 `closeTab` 路径关闭，于是指向该页面的会话绑定被丢弃、钉在它上面的面板回退到剩下的标签页、面板状态被广播。没有浏览器在跑时既不扫描也不拉起。

窗口是 volatile 设置 `idleCloseDays`：默认 3 天、最小 0、0 关闭该能力。它每次扫描现读，所以改设置在下一次扫描就生效，既不用重挂插件也不用重连浏览器。时钟只在内存里：宿主重启后，每个页面的窗口在接入时从头开始。

接管的真实页面永远不是候选。[真实浏览器 CDP 模式](2026-10-29-browser-view-real-cdp-mode.zh.md)那条决策否决了对接管标签页的隐式清理，理由是可能毁掉未保存的工作；把扫描限定在 `origin === 'created'` 上保持了这个边界，接管的页面仍然只有调用点名它的 id 才会关。

## Runtime and client contract

`idleCloseDays` 与 `realBrowserEnabled`、`cdpEndpoint` 一起进入 volatile schema，设置表单由宿主按它们生成。Web 扩展那张卡用共享的 `ValueField` 渲染它，字段规格是 `numberField('idleCloseDays', { integer: true, min: 0 })`；插件行配置把它写成数字。线上协议不动：扫描在宿主侧，面板收到的只是 `closeTab` 本来就在广播的状态事件。

## Testing

包测试覆盖闲置边界（正好落在窗口上的页面是候选，差一毫秒就不是）、touch 让计时重新开始、关闭与工具调用竞态之后的未知 id、以接管页面为对照的 created-only 范围、以及零窗口什么都不选。服务测试覆盖只关闭没被碰过的那个页面、关闭后会话绑定被丢弃使下一次调用开出新标签页、窗口关闭时既不关闭也不拉起浏览器、以及没有配置策略的服务让一个月前的页面继续开着。客户端测试覆盖卡片把 `0` 写下去、把负数草稿判为无效，以及行配置提交整数。仓库门禁 `typecheck`、包测试与 `i18n:check` 通过。新字段尚无真实 GUI 观察：运行中的 DSH 服务未被重启，卡片要等用户重启宿主并刷新 GUI 之后才会渲染出它。

## Alternatives considered

**把接管的真实页面也一起关。** 否决：这推翻了真实浏览器决策里那条显式关闭边界，等于让一个没人看着的定时器去销毁用户自己浏览器里未保存的工作。

**只在隔离模式生效。** 否决：真实浏览器模式恰恰是那些被遗忘的 agent 标签页堆在用户真正使用的窗口里的地方。

**把面板观看也算作活跃。** 否决：一个开在某页上的观看面板会让那页永远活着，这正好是闲置规则要避免的。

**把时钟落盘。** 暂时否决：这会把页面身份写进插件自有目录，包级规则不允许，而且对一个以天为单位的窗口还要额外承担迁移与陈旧条目策略。代价是宿主重启后窗口重新开始。

**固定三天的常量。** 否决：有用的窗口取决于浏览器怎么被使用，而一个已发布的常量不换版本就放不宽。

**只在启动时扫一次，不用定时器。** 否决：宿主一跑就是几天，而这正是第一天打开的页面到第五天还开着的场景。

## Consequences

宿主现在会关闭它自己创建、且没有任何工具调用的页面。只在面板里被人看着、没有 agent 工作的页面也会在窗口到期时关闭，面板回退到剩下的标签页。窗口之后才回来的会话拿到的是新标签页而不是那个旧页面，所以 DSH 打开的页面里没保存的状态不会活过这个窗口。

扫描是这个服务里唯一的后台定时器。它必须保持 unref 且在 dispose 时清除，否则宿主进程就退不掉；将来任何新的标签页来源都必须老实上报 `origin`：`created` 才是让一个标签页有资格被清理的那个取值。
