# Agent Note: SSH 本机受管密钥引用（Issue #2069）

Status: implemented

## Problem

多台主机共用一把私钥时，用户必须在每个主机表单重复输入同一个本机路径。集中凭据库会引入另一套信任边界，因此本扩展只管理本机密钥引用，同时保持既有主机认证与存储兼容性。

## Decision

- `$DSH_HOME/dsh-ssh.json` 的可选 `keys` 集合保存 `{ id, name, path, passphrase?, note?, createdAt, updatedAt }`；旧文件在首次创建密钥之前不含该字段。路径允许以 `~` 开头，展开后必须是绝对路径；存在性只读取文件元数据，绝不读取或复制密钥字节。
- `/api/dsh-ssh/keys` 在与主机相同的宿主 connection 或 loopback 围栏后提供 CRUD。响应只有 hasPassphrase、存在性与引用主机别名，不含口令明文。主机 create/update 接受瞬态 managedKeyId，Host 在校验与持久化之前解析并剥离为既有 `auth.keyPath` / `passphrase` 形状。
- 面板专用主机投影携带 keyPath 供匹配；agent 与 `dshSsh` 服务投影继续省略它。旧手填路径会自动在界面匹配受管密钥，但保存无关字段不会重新应用受管凭据；只有显式选择才发送 managedKeyId。
- 密钥页签显示文件存在性与引用数。编辑或删除被引用记录时，确认框列出全部主机别名。这些操作只改变受管记录：主机认证与私钥文件保持不动，不再匹配的主机保留为自定义路径。

## Testing

- Store 测试覆盖旧文件形状、校验、存在性 / 引用元数据、无泄密投影、口令保留 / 清除、瞬态 id 解析以及删除不改写主机。
- 真实 HTTP 路由测试覆盖创建受管密钥、Host 侧分配与移除后主机保持完整。
- React 测试覆盖六页签外壳、自动与未匹配路径、显式受管选择、CRUD 载荷、文件缺失 / 引用展示与确认告警。

## Alternatives considered

- 把受管口令返回浏览器：否决。Host 侧瞬态 id 解析保持浏览器既有无密钥投影。
- 主机只存 key id 并修改连接认证：否决，因为 issue 要求既有 `auth.keyPath` 主机与连接逻辑继续兼容。
- 把密钥编辑或删除传播到引用主机：否决。受管记录只是复用选择辅助，无权改写或删除用户凭据与文件。

## Consequences

- 共用密钥可直接下拉选择，无需重复输入路径，既有自定义路径与主机记录继续有效。
- 口令仍按包安全模型以明文保存在 owner-only 0600 配置文件中。
- 修改受管路径不会自动迁移旧主机；用户须在每台意图变更的主机中显式选择更新后的密钥。
