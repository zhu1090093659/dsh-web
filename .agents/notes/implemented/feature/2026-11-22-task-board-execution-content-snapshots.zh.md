# Agent Note: Task board execution content snapshots

Status: implemented

本决策部分替代 [Task board execution summaries](2026-10-18-task-board-execution-summary.zh.md) 中「内容永久冻结」的前提。执行摘要以及「不把运行产出写回描述」的决定保持不变。

## Problem

卡片一旦有了执行历史，标题、描述与 Prompt 就无法修改。调整一条需要反复执行的指令因此只能复制卡片，再重接计划与工作区，并失去与原执行历史的连续性。冻结存在的原因，是卡片当前文本同时也是「当时发给 agent 什么」的唯一记录。

## Decision

- `startExecution` 在它开启的执行记录上捕获 `promptSnapshot` 与 `titleSnapshot`。这两个字段可选，不增加账本 schema 版本，经账本加载与导入保留，且绝不为缺少字段的旧记录合成。
- `canEditTaskContent` 只允许未归档且没有未结算执行的卡片编辑标题、描述与 Prompt。`canEditTaskAttachments` 是独立且更严格的门禁：附件在首次执行后冻结，因为执行记录没有逐次附件快照。
- Host 的 update 动作分别应用这两道门。已结算卡片的编辑弹窗只禁用附件区，详情 footer 保持三键布局；标签快捷入口与复制动作留在头部菜单。
- 开跑时的 Prompt 与标题由执行记录自持，而不是读卡片当前文本。描述是卡片级工作文本，不是逐次运行的审计凭证。

## Alternatives considered

**让已执行卡片永久只读。** 否决：逐次快照既保留审计性质，也不必让每次 Prompt 调整都换一个新的任务身份。

**附件随文本一起解锁。** 否决：执行记录没有捕获附件字节，也没有独立的附件快照，跑后替换会破坏既有审计边界。

**用卡片当前文本给旧记录回填快照。** 否决：那会为开跑内容未知的运行伪造证据。字段缺席才是诚实的兼容表达。

## Consequences

已结算卡片可以编辑而不丢失身份、计划或历史。运行中与归档卡片仍只读，附件变更仍需复制卡片。账本为每条保留的执行增加开跑 Prompt 与标题，体积受既有执行记录保留上限约束。

## Testing

任务看板测试固定开跑快照、后续编辑不影响旧快照、账本与导入往返、旧记录无快照且不回填、畸形快照拒绝、已结算与运行中卡片的编辑边界、独立附件门禁，以及 footer/header 动作布局。包级类型检查、完整测试与 i18n 一致性检查覆盖交付行为；本次交付未完成剩余的真实 GUI 检查。
