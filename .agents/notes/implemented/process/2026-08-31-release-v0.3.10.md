# Agent Note: Release v0.3.10

Status: implemented

## Problem

The family needed its next unified release including everything merged to `dev` after the v0.3.9 tag (2026-08-30): the dsh-better-sidebar re-add at 0.18.0-alpha.0, the new `@linxin666/dsh-i18n` ru language pack, the cross-package i18n locale-dictionary migration, the dsh-archived-chats community registration, the e2e token-URL fix and the repo hardening commits. The release gate requires an auto-upgrade compatibility audit for the whole `v0.3.9..dev` range before any version bump, tag or npm publish.

## Decision

Release v0.3.10 (next patch after 0.3.9) by the standard unified-version flow on an isolated worktree (shared checkout kept untouched for the parallel sessions). The audit closed the range as safe for automatic upgrade:

- No package identity, contract, persistence or wire-protocol identifiers changed for existing packages: the eight i18n-migrated packages only move UI strings into their locale dictionaries (settings section ids, API paths, storage keys all frozen).
- The aggregate additions are strictly additive: two new insert rows (`web-ui-i18n` from the new bundle, `web-ui-better-sidebar` restored at the external plugin version the alpha.2 cohort supports) plus one new dependency. No stale disabling state exists for either row on old profiles, because the 2026-08-30 exclusion removed them by omission, not by `disabled:` overrides.
- `@linxin666/dsh-i18n` joins the family as a pure browser plugin (type-only `@deepseek-ai/*` imports, no settings section, `inject = ['locale']`), declares `engines.dsh >= 0.1.2-alpha.1` at or below every sibling's floor, below the release-validation pin `@deepseek-ai/dsh@0.1.2-alpha.2`.
- The legacy aggregate dual-publish window stays closed: `LEGACY_DUAL_PUBLISH_WINDOW_OPEN = false` and `@linxin666/dsh-web-ui-all` is already deprecated, so the pipeline step is a no-op for 0.3.10.

Validation evidence: fresh-install mount smoke (real alpha.2 host, keyless `dsh web`, Playwright: frame + better-sidebar mounted, archive-manager absent, no crash strips) and a 0.3.9-to-0.3.10 upgrade-path simulation on a scratch profile (real 0.3.9 registry install, `dsh plugin add file:<0.3.10 tarball>` with the full family rewritten to local tarballs, `--dump-config` preflight, row/dep/version assertions, home-data marker survival, and the same Playwright boot lane on the upgraded home).

## Alternatives considered

- Releasing with only the CI gates and no upgrade-path simulation: rejected — the hard gate explicitly disallows a fresh-install-only pass when the range adds new bundle rows and deps; the simulation is cheap and proves the real update flow.
- Publishing a legacy `@linxin666/dsh-web-ui-all@0.3.10`: rejected — the transition window is hard-closed and the deprecated package must stay at its window-end version.

## Consequences

- npm `@linxin666/*` family moves to 0.3.10 (`latest`); `@linxin666/dsh-i18n` publishes for the first time at 0.3.10.
- The aggregate profile gains the better-sidebar right panel and the ru language pack on the next install; both are additive and require no migration, so plugin-manager updates and Doctor prestart keep working unchanged.
- Release notes are the committed bilingual `docs/release-notes/v0.3.10.md` (Chinese default view, English fold); `dsh-web-ui-all` stays deprecated at 0.3.6.

Follow-up (2026-08-31): the CI verify-release mount smoke failed twice with `ERR_PNPM_FETCH_404` resolving `@linxin666/dsh-i18n@0.3.10` — the package's FIRST publication: the e2e-mount-rewrite probe saw the packument (200) but the install right after hit a stale edge (404). Registry-side consistency heals in minutes; the remediation was `gh run rerun --failed` (no tag change, publish job untouched). The next release that introduces a brand-new family package should harden `scripts/e2e-mount-rewrite` or retry the smoke install instead of relying on a lucky rerun.
