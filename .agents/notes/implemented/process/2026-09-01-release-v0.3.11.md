# Agent Note: Release v0.3.11

Status: implemented

## Problem

The family needed its next unified release including everything merged to `dev` after the v0.3.10 tag: the new built-in `dsh-session-archive` plugin (a brand-new family package, first publish), the doctor boot self-heal (failing-row attribution and quarantine), the aggregate fault-isolation shell with its two hardening fixes, the official SDK cohort bump to 0.1.2-alpha.3 plus the family host floor pins, five new skins (four from #1316 plus tokyo-night), three community plugin registrations, better-sidebar peer fixes, and two open-issue fix batches. The release gate requires an auto-upgrade compatibility audit for the whole `v0.3.10..dev` range before any version bump, tag or npm publish.

## Decision

Release v0.3.11 (next patch after 0.3.10) by the standard unified-version flow, with the version bump and release notes committed on `dev` and the tag cut from `main` after a fast-forward. The audit closed the range as safe for automatic upgrade:

- `dsh-session-archive` is purely additive: all its identifiers (npm name, `/api/dsh-session-archive/*` routes, settings section) are new, so there is no legacy state to migrate. It declares `engines.dsh >= 0.1.2-alpha.3`, matching the CI host pin, and is wired into the aggregate manifest as one new patch row plus one new dependency.
- The dsh-web-all shell changes are backward-compatible hardening of the existing profile contract: a config-less self row now mounts as a no-op, bare-row overrides of shell rows mount silently, and per-plugin boot failures degrade to the ledger instead of aborting the transactional loader group. Existing profile patch rows keep their shape; real-host boot is covered by `shell-isolation.spec.ts`.
- The doctor self-heal writes are gated behind `autoRepair` and only append `disabled: true` quarantine rows after repeated failures.
- No `@deepseek-ai/*` package appears in any published dependency field (they are devDependencies; runtime comes from host injection), and every declared name has 0.1.2-alpha.3 published on the registry (under the `alpha` dist-tag), so CI installs resolve without the cohort store.
- The legacy aggregate dual-publish window stays closed: `LEGACY_DUAL_PUBLISH_WINDOW_OPEN = false` and `@linxin666/dsh-web-ui-all` is already deprecated, so the pipeline step is a no-op for 0.3.11.

Validation evidence: full local gate set green (`sync-shared`, `typecheck`, `test` including the real-host shell-isolation specs, `test:scripts`, `docs:check`, `i18n:check`, `aggregate:check`, `runtime-deps:check`, `skin-center:check`), market assets rebuilt from the same build and committed together (376-file tryon hash churn from the vendored shell rebuild), and the committed bilingual release notes verified byte-identical to the `scripts/release-notes.mjs` English view before the tag push.

Process incident and repair: the first `git push origin dev` was rejected because `origin/dev` had advanced (e4448dfee, a doctor self-heal test settling fix) after the initial fetch. Rebasing the release commit on top rewrote history after local `main` had already fast-forwarded to the pre-rebase release commit 78f52afbc; the subsequent push chain then pushed the stale `main` even though the fast-forward had failed. The pushed tag was already re-created at the amended commit 18c3b0ab2, so the release content was correct. Repair: merged `dev` into `main`, resolved the add/add conflict on the release notes in favor of `dev` (the 15-fix version), verified `git diff dev main` is empty, and pushed the merge 36bedf8d8. Lesson: after any rebase that moves a release commit, re-verify every ref staged for the push sequence (`dev`, `main`, tag) — a failed fast-forward inside a `&&` chain does not stop the later pushes.

## Alternatives considered

- Excluding e4448dfee from the release by rebasing the bump below it or releasing without it: rejected — it fixes the settling race in the doctor self-heal tests for code already in the release range.
- Force-pushing `main` back to the amended release commit to keep a linear history: rejected — rewriting protected `main` history to drop one superseded commit is disproportionate; a merge commit with dev-identical content is honest and safe.
- Re-running the market build from a pinned older toolchain to shrink the 376-file tryon churn: rejected — `market:check` is a committed-completeness gate against the current build, and the skill requires committing the dist produced by the same build.

## Consequences

- npm `@linxin666/*` family moves to 0.3.11 (`latest`); `@linxin666/dsh-session-archive` publishes for the first time at 0.3.11, and the mount smoke resolved it on the first attempt (the first-publish 404 edge race from the v0.3.10 follow-up did not recur).
- `dsh-web-ui-all` stays deprecated at 0.3.6.
- `main` now carries the superseded bump commit 78f52afbc plus merge 36bedf8d8 whose tree equals `dev`; `dev` was intentionally not merged back from `main` (it already contains the amended release commit, and absorbing the merge would drag the superseded commit into `dev` history).
- Release notes are the committed bilingual `docs/release-notes/v0.3.11.md` (Chinese default view, English fold); the pipeline used the committed file.
