# Agent Note: Release v0.3.11

Status: implemented

## Problem

家族需要发布下一个统一版本，包含 v0.3.10 tag 之后合入 `dev` 的全部内容：新增内置 `dsh-session-archive` 插件（全新家族包、首次发布）、doctor 启动自愈（失败行归因与隔离）、聚合故障隔离 shell 及其两个加固修复、官方 SDK cohort 升至 0.1.2-alpha.3 与家族宿主下限钉点、五款新皮肤（#1316 的四款加 tokyo-night）、三个社区插件注册、better-sidebar peer 修复，以及两批开放 issue 修复。发布门禁要求在版本 bump / tag / npm 发布之前对 `v0.3.10..dev` 全范围做自动升级兼容性审计。

## Decision

按标准全仓统一版本流程发布 v0.3.11（0.3.10 的下一个补丁版本）：版本 bump 与双语 release notes 提交在 `dev` 上，`main` 快进后从 `main` 打 tag。审计将该范围判定为可安全自动升级：

- `dsh-session-archive` 纯增量：其全部标识符（npm 名、`/api/dsh-session-archive/*` 路由、settings section）都是新建，不存在需要迁移的旧状态。它声明 `engines.dsh >= 0.1.2-alpha.3`，与 CI 宿主钉点一致，并作为一条新 patch 行加一个新依赖接入聚合清单。
- dsh-web-all shell 的改动是对既有 profile 契约的向后兼容加固：无配置 self 行按 no-op 挂载、覆盖 shell 行的用户裸行静默挂载、单插件启动失败降级进台账而不是中止事务性 loader 组。既有 profile patch 行形状不变；真实宿主启动由 `shell-isolation.spec.ts` 覆盖。
- doctor 自愈写行为门控在 `autoRepair` 之后，且只在重复失败后追加 `disabled: true` 隔离行。
- 任何发布依赖字段（dependencies / peerDependencies）都不含 `@deepseek-ai/*`（它们是 devDependencies，运行时来自宿主注入），且全部声明的包名在 registry 上都有 0.1.2-alpha.3（`alpha` dist-tag 之下），CI 安装无需 cohort store 即可解析。
- legacy 聚合包双发窗口保持关闭：`LEGACY_DUAL_PUBLISH_WINDOW_OPEN = false` 且 `@linxin666/dsh-web-ui-all` 已 deprecate，管线步骤对 0.3.11 是 no-op。

验证证据：本地全部门禁绿灯（`sync-shared`、`typecheck`、`test` 含真实宿主 shell-isolation 规格、`test:scripts`、`docs:check`、`i18n:check`、`aggregate:check`、`runtime-deps:check`、`skin-center:check`），market 资产与同一次构建一起重建并提交（vendored shell 重建带来 376 个 tryon 哈希变动），双语 release notes 在打 tag 前与 `scripts/release-notes.mjs` 的 English 视图逐字节比对一致。

流程事故与修复：首次 `git push origin dev` 被拒——初次 fetch 之后 `origin/dev` 前进了（e4448dfee，doctor 自愈测试收敛竞态修复）。把发版提交 rebase 到其上重写了历史，而本地 `main` 此前已快进到 rebase 前的发版提交 78f52afbc；随后的推送链把过期的 `main` 也推了上去，尽管快进已经失败。已推送的 tag 在 amend 后的提交 18c3b0ab2 上重建，因此发布内容本身正确。修复：把 `dev` merge 进 `main`，release notes 的 add/add 冲突取 `dev` 侧（15 项修复版本），验证 `git diff dev main` 为空后推送 merge 36bedf8d8。教训：rebase 移动发版提交之后，必须重新核验推送序列里的每一个 ref（`dev`、`main`、tag）——`&&` 链中一次失败的快进不会阻止后续推送。

## Alternatives considered

- 通过把 bump rebase 到 e4448dfee 之下或绕开它来把该提交排除在发布外：拒绝——它修复的是发布范围内既有代码的 doctor 自愈测试收敛竞态。
- 强推 `main` 回 amend 后的发版提交以保持线性历史：拒绝——为丢弃一个被取代的提交而重写受保护的 `main` 历史不成比例；树内容与 dev 一致的 merge 提交诚实且安全。
- 钉住更旧的工具链重跑 market 构建以缩小 376 个 tryon 变动：拒绝——`market:check` 是针对当前构建的提交完整性门禁，技能要求提交同一次构建产出的 dist。

## Consequences

- npm `@linxin666/*` 全家族发布到 0.3.11（`latest`）；`@linxin666/dsh-session-archive` 以 0.3.11 首次发布，且挂载冒烟一次通过（v0.3.10 后续记录的首次发布 404 边界竞态没有复现）。
- `dsh-web-ui-all` 保持 deprecate 于 0.3.6。
- `main` 现在带有被取代的 bump 提交 78f52afbc 与树内容等于 `dev` 的 merge 36bedf8d8；`dev` 刻意不从 `main` 合回（它已包含 amend 后的发版提交，吸收 merge 会把被取代的提交拖进 `dev` 历史）。
- Release notes 为已提交的双语 `docs/release-notes/v0.3.11.md`（中文默认视图 + English 折叠）；管线采用了已提交文件。
