# Agent Note: Release v0.3.12

Status: implemented

## Problem

The family needed its next unified release covering the `v0.3.11..dev` range: the aggregate client-children mount fix (family client UIs vanished under the fault-isolation shell because the folded rows were invisible to the client module scanner), the session-archive settings-scope method binding fix, the market telemetry read-path scaling batch (rollup cache and indexes against D1 batch limits, pre-warm slot rotation and long-window TTL, skipped-window logging), the official SDK cohort bump to 0.1.2-alpha.4 (the first non-additive cohort delta: branded session sequence numbers, `Session.events` replaced by `eventAt`/`ownEvents`, reshaped fork headers, the v0 wire header, the keyed-hooks slots compartment), and the removal of the deprecated `@morlay/better-session` aggregate integration. The cohort commit 46d03a10b was still unpushed with its live verification chain open when the release started.

## Decision

Release v0.3.12 (next patch after 0.3.11) by the standard unified-version flow. `main` carried the v0.3.11 push-race bookkeeping (superseded 78f52afbc plus merge 36bedf8d8) with a zero tree delta against the merge base, so `dev` merged into `main` as a true merge commit (5ca3dc75d) after verifying the delta was empty; the bump commit fc8896ccd and the tag were then cut from `main`. The audit closed the range as safe for automatic upgrade:

- The cohort bump moves the family host floor to `>= 0.1.2-alpha.4` everywhere (21 family packages, the plugin scaffold, the README badge, the CI and release mount-smoke pins), so hosts below the floor get a clean engine refusal instead of a broken mount.
- No persisted or wire identifier authored by this repository changed: the market worker changes are read-path only, the session-archive fix is client-internal binding, and the aggregate client-children mount keeps every loader id while deduping mounts through `mountOnce` symbols.
- The better-session removal drops the `web-ui-session-branch` / `web-ui-session-rdb` / `web-ui-conversation-message-actions` rows from the generated patch; existing profile overrides naming them become no-ops, environments that want better-session install it directly, and the dsh-perf Better Session card stays as the legacy-session migration surface.
- The legacy aggregate dual-publish window stays closed: `@linxin666/dsh-web-ui-all` remains deprecated at 0.3.6 and the pipeline step is a no-op for 0.3.12.

The live verification chain from the cohort landing completed before the tag: the host CLI was already at 0.1.2-alpha.4, the user restarted `dsh web` eleven minutes after the cohort commit (boot materialized alpha.4 into the web profile), the shared checkout was reinstalled and rebuilt against the alpha.4 lockfile, the full local gate set ran green, and a read-only probe of the running GUI confirmed the settings nav renders every family first-level section (skin center, pet, workshop, usage, session archive, task board) with no error toasts — the aggregate client-children mount working against the alpha.4 host.

Validation evidence: full gate set green (`sync-shared`, `typecheck`, `test`, `test:scripts`, `aggregate:check`, `runtime-deps:check`, `docs:check`, `i18n:check`, `market:check`, `skin-center:check`), bundles and market assets rebuilt from the same version bump and committed together, and the release pipeline (run 33581505792) succeeded end to end in 6m19s including the gated npm publish and the GitHub Release creation from the committed bilingual notes.

## Alternatives considered

- Tagging without waiting for the live-instance restart and GUI probe: rejected — the cohort commit was unpushed and the restart-then-verify chain was the designed activation gate; the restart landed minutes after the commit, so the wait cost nothing.
- Resetting `main` to drop the v0.3.11 bookkeeping commits and regain a fast-forward: rejected — rewriting protected `main` history for a zero tree delta is disproportionate; the merge commit is honest and keeps the push-race audit trail.

## Consequences

- npm `@linxin666/*` moves to 0.3.12; all 21 family packages verified against the registry, and the legacy `dsh-web-ui-all` stays deprecated at 0.3.6.
- `dev` and `main` both sit at fc8896ccd; the residual v0.3.11 docs-only delta rode this merge as planned, closing the deliberate branch split.
- The family now requires a DSH host `>= 0.1.2-alpha.4`, and the family-internal better-session integration is gone (stock jsonl owns session storage; direct installs keep working against their own profiles).
- Release notes are the committed bilingual `docs/release-notes/v0.3.12.md` (Chinese default view, English fold); the pipeline used the committed file.
