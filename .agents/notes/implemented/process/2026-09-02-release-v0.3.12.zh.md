# Agent Note：发布 v0.3.12

Status: implemented

## 问题

全家桶需要下一次统一发布，覆盖 `v0.3.11..dev` 区间：聚合包客户端子插件挂载修复（fault-isolation shell 折叠行对客户端模块扫描器不可见，导致各家族客户端 UI 消失）、session-archive 设置作用域方法绑定修复、market 遥测读路径扩容批次（汇总缓存与索引应对 D1 批量上限、预热槽位轮换与长窗口 TTL、跳过窗口日志）、官方 SDK cohort 升级到 0.1.2-alpha.4（首个非增量式 cohort 差异：会话序列号品牌化、`Session.events` 替换为 `eventAt`/`ownEvents`、fork 头重塑、v0 wire 头、keyed-hooks 槽位舱），以及移除弃用的 `@morlay/better-session` 聚合集成。发版开始时 cohort 提交 46d03a10b 尚未推送，线上验证链还未走完。

## 决策

按标准统一版本流程发布 v0.3.12（0.3.11 的下一个补丁版本）。`main` 上留有 v0.3.11 推送竞态的记账提交（被取代的 78f52afbc 与合并 36bedf8d8），相对合并基的树差异为零，因此 `dev` 合入 `main` 走真实合并提交（5ca3dc75d）；随后从 `main` 切出发版提交 fc8896ccd 与 tag。兼容性审计结论为可安全自动升级：

- cohort 升级把家族宿主下限全面移到 `>= 0.1.2-alpha.4`（21 个家族包、插件脚手架、README 徽章、CI 与 release 的 mount-smoke 固定），低于下限的宿主会得到干净的 engine 拒绝而不是坏挂载。
- 本仓库自己持有的持久化与线协议标识符均未变化：market worker 改动只在读路径，session-archive 修复是客户端内部绑定，聚合客户端子插件挂载保留全部 loader id 并通过 `mountOnce` 符号去重。
- better-session 移除会从生成的 patch 中删掉 `web-ui-session-branch` / `web-ui-session-rdb` / `web-ui-conversation-message-actions` 三行；已有 profile 中命名这些行的覆盖变成 no-op，需要 better-session 的环境直接自行安装，dsh-perf 的 Better Session 卡片保留为旧会话迁移面。
- 旧聚合包双发窗口保持关闭：`@linxin666/dsh-web-ui-all` 维持 0.3.6 已弃用状态，管线步骤对 0.3.12 是 no-op。

cohort 落地时的线上验证链在打 tag 前已走完：宿主 CLI 已在 0.1.2-alpha.4，用户在 cohort 提交十一分钟后重启了 `dsh web`（启动时把 alpha.4 物化进 web profile），共享检出按 alpha.4 lockfile 重装并重建，本地全量门禁通过，对运行中 GUI 的只读探测确认设置导航渲染出全部家族一级版块（皮肤中心、宠物、创意工坊、使用统计、会话归档、任务看板）且无错误提示——即聚合客户端子插件挂载在 alpha.4 宿主上工作正常。

验证证据：全量门禁通过（`sync-shared`、`typecheck`、`test`、`test:scripts`、`aggregate:check`、`runtime-deps:check`、`docs:check`、`i18n:check`、`market:check`、`skin-center:check`），bundle 与市场资产由同一次版本 bump 重建并一起提交，发布管线（run 33581505792）端到端成功（6m19s），含受门控的 npm 发布与用已提交双语 notes 创建的 GitHub Release。

## 备选方案

- 不等线上实例重启与 GUI 探测直接打 tag：否决——cohort 提交尚未推送，重启后验证链是设计好的激活门；重启在提交数分钟后即完成，等待没有成本。
- 重置 `main` 丢掉 v0.3.11 记账提交以恢复快进合并：否决——为零树差异重写受保护的 `main` 历史不成比例；合并提交诚实且保留推送竞态的审计轨迹。
