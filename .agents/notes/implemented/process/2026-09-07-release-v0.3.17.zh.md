# Agent Note：v0.3.17 发布运行记录

Status: implemented

## Problem

v0.3.17 这次发布本身没有决策记录：它是 desktop-release workflow 的新 Windows 车道第一次真实执行的发布，运行暴露的故障需要共享同一 checkout 的两个并行 agent 会话协同修复。

## Decision

- 目标版本默认取 v0.3.16 的下一个补丁号（已从 registry 验证 npm latest 为 0.3.16）；本地门禁全套与 v0.3.16..dev 的自动升级兼容性审计未发现持久化标识符或线协议变更——聚合包 tombstone 子路径导出本身就是陈旧 profile 行的确定性迁移垫片（#1381）。
- 发布前和解：main 上有一个未推送的 notes 提交（e9ffd799），其补丁在 dev 上已存在（5f64f101，patch-id 相同）；在集成分支上解决——main 先并入 dev，再把 main 快进回 dev。
- 发布提交 46f1616f（chore(release): bump to 0.3.17），tag v0.3.17 从 main 打出；release.yml 5 分 35 秒全绿：19 个家族包以 0.3.17 发布，legacy 聚合包保持终版 0.3.6 且带弃用元数据（窗口已关闭），挂载冒烟与无头渲染通过，GitHub Release 使用入库的双语 notes 创建（中文默认视图、English 折叠视图、user-mention 计数为 0）。
- 桌面发布在 Windows 车道前两次真实执行中失败；三个缺陷、三个提交：
  - Git-bash 的 GNU tar 拒绝盘符路径且读不了 zip：Windows 安全的 bsdtar 解压（36de9e36，[tar 解压修复](../bug-fix/2026-09-07-desktop-tar-windows-bsdtar.md)）。
  - spawnSync 不经 shell 无法执行 pnpm.cmd 垫片（404f0c4a，[pnpm spawn shell 修复](../bug-fix/2026-09-07-desktop-pnpm-spawn-windows-shell.md)）——由并行修复同一次发布的另一会话落地；两会话各自以精确路径提交不相交的文件集，互未覆盖。
  - setup-node v5 默认的包管理器缓存向只依赖 Node 内置模块的 windows CI job 索要 pnpm（e4b0b21a，记录于 [Windows CI 车道笔记](../testing/2026-09-06-windows-ci-lanes-for-desktop.md)）。
- 安装包不重打 tag 重建：desktop-release.yml 对既有 tag v0.3.17 以 ref main dispatch（run 34077860441），该运行包含两处桌面修复。

## Alternatives considered

- 重切 v0.3.18 来带上桌面修复：否决——npm 版本号不可复用且 npm 家族已发布且正确；桌面资产可以按既有 tag dispatch 重建，需要修复的只有桌面车道。
- 不做真实 Windows 启动直接挂安装包：否决——这份证据正是新门禁存在的意义。

## Consequences

- 两条 Windows 车道在发布时点都持有真实执行证据；同类故障无法在不触发红灯的情况下静默回归。
- 共享 checkout 上的并行会话协作在精确路径纪律下成立：文件集不相交、无整体暂存、无强制推送；唯一成本是对刚被另一会话重写的文件做了一次多余的本地编辑尝试。
- 以后的 workflow 车道应在首次依赖它的发布窗口之前，先在其目标平台上真实执行一次（push 或 dispatch）——tag 时点门禁按设计抓住了这些缺陷，但发布因此要等修复。
