# Agent Note: v0.3.20 release run

Status: implemented

## Problem

No decision record existed for the v0.3.20 release: it is the release that moves the family from the `0.1.2-rc.1` host contract to the `0.1.5-rc.1` cohort and raises the declared host floor, so the mandatory automatic-upgrade audit had to classify a host-contract change rather than only feature work.

## Decision

- Target defaulted to the next patch after v0.3.19 (registry `latest` verified 0.3.19); `node scripts/verify-version.mjs 0.3.20` reports all 21 family packages matching the tag.
- The v0.3.19..dev compatibility audit found no persisted-identifier, profile-format, wire-protocol, or migration-surface change: settings section ids, API paths, localStorage and configuration keys, request headers, the legacy `@linxin666/dsh-web-ui-all` to `@linxin666/dsh-web-all` mapping (`shared/host/legacy-migration.ts`, `packages/dsh-doctor/src/agent/migrate.ts`), the plugin-manager and Doctor profile writers, and the aggregate row namespace are untouched. Outside notes, lockfiles, and generated artifacts the source delta is four `packages/dsh-pet/src` files, the orca-link skin CSS, `shared/web-platform.ts`, and release scripts.
- One host-contract change is deliberate: `dsh.engines.dsh` rises from `>=0.1.2-rc.1` to `>=0.1.5-rc.1` in the 20 family packages plus `scripts/plugin-template`, matching the `@deepseek-ai` cohort the sources build against. The CI and release mount pins already name `0.1.5-rc.1`, so the declared floor is not above the host the pipeline verifies. Classification: backward compatible for hosts at or above `0.1.5-rc.1`, unsupported below it.
- The floor is enforced fail-closed on the plugin-manager update path: `meetsMinimumDsh` rejects `0.1.5-alpha.2` and `0.1.2-rc.1` while accepting `0.1.5-rc.1`, and the update control is disabled while `compatible === false`. The direct `dsh plugin add` path and Doctor's legacy migration do not evaluate the floor - measured on 0.1.2-rc.1, which installed the 0.3.20 aggregate and passed `--dump-config` - so the release notes carry the support statement and the rollback command instead of an unsupported compatibility claim.
- The pet's durable `assistant/chunk` projection is replaced by the process-local `agent/assistant-stream` publication; that is the same host-contract move and is covered by the floor.
- The legacy dual-publish window stays hard-closed (`LEGACY_DUAL_PUBLISH_WINDOW_OPEN = false` in `scripts/publish-legacy-aggregate.mjs`): `@linxin666/dsh-web-ui-all` is frozen at its final 0.3.6 with the migration deprecation message, and the pipeline's legacy step is a no-op.
- Desktop packaging resolves the preinstalled profile seed from the registry at build time; the committed seed stays at 0.3.19 as the disabled-lane fallback.
- `.gitattributes` normalization is verified, not assumed: `git ls-files --eol` reports zero CRLF entries and `*.sh` resolves to `text eol=lf`.
- The bump commit `chore(release): bump to 0.3.20` carries the 21 manifests, the three regenerated bundles, and `docs/release-notes/v0.3.20.md`; it was committed on dev, fast-forwarded into main, and the tag was cut from main.

## Alternatives considered

- Blocking the release or lowering the declared floor: rejected - the sources already build against the 0.1.5-rc.1 cohort (shell module table, packageExtensions, `agent/assistant-stream`), so `>=0.1.2-rc.1` was a false declaration that let a host install a plugin set it cannot run.
- Bumping the committed desktop seed to 0.3.20: rejected - the packaging path resolves the tag version from the registry, and the committed value is the documented fallback for a disabled publish lane, so it must keep naming a version that exists.
- Shipping the auto-generated notes draft: rejected by the bilingual split-view convention.
- Verifying only the fresh install: rejected - the isolated upgrade from a published 0.3.19 profile is the path existing users take.

## Consequences

- A host below `0.1.5-rc.1` cannot auto-update through the plugin manager until the CLI is upgraded; the update row reports the requirement instead of failing mid-install.
- The declared floor remains advisory on `dsh plugin add` and the Doctor legacy migration; the release notes state the limitation and the rollback command.
- The next family release can drop the two `packageExtensions` blocks only when the upstream manifests declare their runtime imports.
- The desktop seed stays a fallback value; the registry lookup is what keeps installers current.
