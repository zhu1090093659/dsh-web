# Agent Note: v0.3.20 发布运行记录

Status: implemented

## Problem

v0.3.20 这次发布本身没有决策记录：它是把全家桶从 `0.1.2-rc.1` 宿主契约迁到 `0.1.5-rc.1` cohort、并提升宿主声明下限的版本，因此强制性的自动升级审计必须对一个宿主契约变更定性，而不只是功能改动。

## Decision

- 目标版本默认取 v0.3.19 的下一个补丁号（registry 的 `latest` 已验证为 0.3.19）；`node scripts/verify-version.mjs 0.3.20` 报告 21 个家族包全部与 tag 一致。
- v0.3.19..dev 的兼容性审计未发现持久化标识符、profile 格式、线协议或迁移面变更：设置 section id、API 路径、localStorage 与配置键、请求头、旧包 `@linxin666/dsh-web-ui-all` 到 `@linxin666/dsh-web-all` 的映射（`shared/host/legacy-migration.ts`、`packages/dsh-doctor/src/agent/migrate.ts`）、plugin-manager 与 Doctor 的 profile 写入器、聚合包行命名空间均未改动。除 notes、lockfile 与生成产物外，源码增量是四个 `packages/dsh-pet/src` 文件、orca-link 皮肤 CSS、`shared/web-platform.ts` 与发布脚本。
- 一处宿主契约变更是有意为之：20 个家族包加 `scripts/plugin-template` 的 `dsh.engines.dsh` 由 `>=0.1.2-rc.1` 升至 `>=0.1.5-rc.1`，与源码构建所用的 `@deepseek-ai` cohort 一致。CI 与发布管线的挂载 pin 本就是 `0.1.5-rc.1`，声明下限不高于管线验证的宿主。归类：宿主达到或高于 `0.1.5-rc.1` 时向后兼容，低于该下限不受支持。
- 该下限在 plugin-manager 更新路径上 fail-closed 生效：`meetsMinimumDsh` 拒绝 `0.1.5-alpha.2` 与 `0.1.2-rc.1`、接受 `0.1.5-rc.1`，`compatible === false` 时更新控件被禁用。裸 `dsh plugin add` 与 Doctor 的旧聚合包迁移不判定该下限——在 0.1.2-rc.1 上实测：它能装上 0.3.20 聚合包且 `--dump-config` 通过——因此 release notes 给出支持声明与回退命令，而不是宣称该路径也受校验。
- 宠物的持久 `assistant/chunk` 投影被进程内的 `agent/assistant-stream` 发布取代；这属于同一次宿主契约迁移，由下限覆盖。
- legacy 双发窗口保持硬关闭（`scripts/publish-legacy-aggregate.mjs` 的 `LEGACY_DUAL_PUBLISH_WINDOW_OPEN = false`）：`@linxin666/dsh-web-ui-all` 冻结在终版 0.3.6 并带迁移弃用说明，管线的 legacy 步骤为空操作。
- 桌面打包在构建时从 registry 解析预装 profile 种子；仓库内提交的种子保持 0.3.19，作为发布通道关闭时的回退值。
- `.gitattributes` 归一化是实测而非假设：`git ls-files --eol` 报告零个 CRLF 条目，`*.sh` 解析为 `text eol=lf`。
- 发布提交 `chore(release): bump to 0.3.20` 承载 21 个 manifest、三个重新生成的 bundle 与 `docs/release-notes/v0.3.20.md`；它在 dev 上提交，快进合入 main，tag 从 main 打出。

## Alternatives considered

- 阻断发布或下调声明下限：否决——源码本就基于 0.1.5-rc.1 cohort 构建（shell 模块表、packageExtensions、`agent/assistant-stream`），`>=0.1.2-rc.1` 是虚假声明，会让宿主装上自己跑不动的插件集。
- 把提交的桌面种子升到 0.3.20：否决——打包路径会从 registry 解析当次 tag 版本，而提交值是发布通道关闭时的既定回退，必须始终指向真实存在的版本。
- 直接采用自动生成的 notes 草稿：否决，违反双语分视图约定。
- 只验证全新安装：否决——从已发布的 0.3.19 profile 升级才是存量用户实际走的路径。

## Consequences

- 宿主低于 `0.1.5-rc.1` 时无法经 plugin-manager 自动更新，需先升级 CLI；更新行会报出该要求，而不是安装到一半失败。
- 声称的下限在 `dsh plugin add` 与 Doctor 旧包迁移路径上仍是建议性的；release notes 已写明该限制与回退命令。
- 下一次家族发布只有在两个上游包声明其运行时依赖之后，才能移除这两块 `packageExtensions`。
- 桌面种子仍是回退值；让安装包保持最新的是 registry 解析。
