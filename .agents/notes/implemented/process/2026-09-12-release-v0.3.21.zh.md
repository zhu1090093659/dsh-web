# Agent Note: v0.3.21 release run

Status: implemented

## Problem

v0.3.20 的记录覆盖的是一次源码增量很小、但改了宿主契约的发布。v0.3.21 正好相反：108 个提交、1674 个改动文件，横跨各插件、皮肤、市场站点与共享客户端运行时，而且它是第一个必须在提交里同时携带刷新后 lib 产物指纹的发布。因此强制性的自动升级审计要为一个宽增量定性，发布流程本身也需要补上既有记录没有点名的步骤。

## Decision

- 目标版本默认取 v0.3.20 的下一个补丁号（registry 的 `latest` 已验证为 0.3.20）；`node scripts/verify-version.mjs 0.3.21` 报告 21 个家族包与根聚合包钉版全部与 v0.3.21 一致。
- v0.3.20..dev 的兼容性审计未发现持久化标识符、profile 格式、线协议或迁移面的破坏性改动。经核验保持不变的有：`packages/dsh-web-all/cordis.patch.yml`（全部 `web-ui-*` 行 id、self 行、`config.plugin`、默认禁用行）、聚合包 `exports` 映射与浏览器 loader id、每个包的 `name`、每个 `dsh.engines.dsh`（保持 `>=0.1.5-rc.1`，未高于管线挂载的宿主版本）、`shared/host/legacy-migration.ts`、`scripts/publish-legacy-aggregate.mjs` 以及 Doctor 的迁移代码。聚合包成员未变：`aggregate.yml` 只有一行注释不同，`aggregate:check` 在两个版本都报告 20 行 / 19 个依赖 / 17 个客户端子包。
- 本次改动均为增量且向后兼容：`dsh-better-sidebar` 升到 0.19.0，其 bundle patch、`exports`、`dsh.client.inject`、依赖与 `files` 完全一致（仅版本、peer 区间与文案不同）；新增 `POST /api/pet/set-skin` 路由；宠物持久化新增 `skins` 映射与 `incomeCarryMs`、`restoreCarryMs` 字段，用量快照新增 `spendWatch` 字段，均为可缺失容忍的新字段；市场 Worker 的 `kind` 枚举加入 `preset`，由于 `kind` 是无约束的 TEXT 列，不需要 D1 迁移；dsh-liangshen 新增 `./client` 导出与 `dsh.client` 块（其新增的 `@deepseek-ai/*` 条目是 devDependencies，不是 peerDependencies）。
- 两个只影响窄人群、且不阻断发布的降级写进了 release notes 而不是省略：评审哈希重钉会让没有 provenance 记录的工坊版 `xp` 或 `maid-atelier` 失去可执行 hooks 面，直到从工坊重装（皮肤本身照常渲染）；梁神预设重写会覆盖并清理 `~/.dsh/.agent-presets/liangshen`，因此更早版本产生、历史中已含退役消息类型的老会话仍无法打开。
- 根别名钉版属于发布契约：只要根 `package.json` 的 `@linxin666/dsh-web-all` 依赖不等于 tag，`scripts/verify-version.mjs` 就让 tag 管线失败，`pnpm-lock.yaml` 的 importer specifier 必须同步移动。发布 skill 的 bump 命令块只覆盖 `packages/**`，所以本次显式提升了根钉版与 lockfile specifier。
- 版本 bump 会重写三个提交入库的 bundle（`dsh-market`、`dsh-web-all` 与 `skins/skin-center` 的 `lib/client.js`），因此发布提交把它们与 `pnpm libs:write` 刷新的 `scripts/lib-artifact-fingerprints.json` 一起携带；[committed lib artifact gate](2026-09-12-committed-lib-artifact-gate.md) 使这一步从本版起成为强制项。
- legacy 双发窗口保持硬关闭（`LEGACY_DUAL_PUBLISH_WINDOW_OPEN = false`）：`@linxin666/dsh-web-ui-all` 停在其最终版 0.3.6 并保留迁移弃用说明，管线里的 legacy 步骤是 no-op。
- 桌面打包在构建时从 registry 解析预装 profile 种子；提交入库的种子保持 0.3.19，作为发布通道关闭时的回退值。
- 双语 release notes 由人工校正而非直接采用草稿：生成器会丢弃以字节序标记开头或不含约定式前缀的提交主题，本次草稿因此静默漏掉了工程蓝图皮肤与 dsh-backup 社区索引登记两条。
- 发布提交 `chore(release): bump to 0.3.21` 承载 21 个 manifest、根钉版、lockfile specifier、三个重新生成的 bundle、刷新后的指纹与 `docs/release-notes/v0.3.21.md`；它在 dev 上提交，快进合入 main，tag 从 main 打出。

## Alternatives considered

- 直接采用生成的 notes 草稿：否决——它会漏掉上述两条提交，release 页面会低估这次发布的内容。
- 只按发布 skill 的命令块 bump `packages/**`：否决——根钉版与 lockfile specifier 会停在 0.3.20，`verify-version.mjs` 会在任何东西进入 npm 之前中止管线。
- 把评审哈希重钉当作发布阻断项：否决——这是评审身份的既定行为，其恢复路径被有意钉在当前版本；皮肤照常渲染，且受影响人群仅限于本次发布本来就要改动的两套皮肤中、没有 provenance 记录的安装。
- 把提交的桌面种子升到 0.3.21：否决——打包路径会从 registry 解析当次 tag 版本，而提交值是发布通道关闭时的既定回退，必须始终指向真实存在的版本。
- 只验证全新安装：否决——从已发布的 0.3.20 profile 就地升级才是存量用户实际走的路径。

## Consequences

- 从 v0.3.20 升级不需要迁移。执行该版本升级的只有插件管理器更新路径，因为对已经使用当前包名的 profile，Doctor 的启动前迁移是 no-op。
- 没有 provenance 记录的工坊版 `xp` 或 `maid-atelier` 会失去可执行 hooks 面，直到从工坊重装；release notes 给出了恢复方式。
- 更早梁神版本产生、已含退役消息类型的会话保持无法打开；本版不再产生新的此类会话。
- 之后每次发布都必须在 bump 家族版本的同时提升根钉版与 lockfile specifier，并刷新 lib 指纹。

## Testing

- 在 bump 后的树上跑本地门禁：sync-shared:check、typecheck、test、test:scripts、aggregate:check、runtime-deps:check、market:check、skin-center:check、libs:check、i18n:check、docs:check——全部通过。
- 挂载冒烟 `bash scripts/e2e-mount.sh`：新打出的 0.3.21 聚合包在真实 0.1.5-rc.1 CLI 下装进 scratch profile，`dsh web` 正常启动，Playwright 无头渲染 1/1 通过，better-sidebar 已挂载、被排除的 archive-manager 缺席。
- 隔离的就地升级（scratch DSH_HOME 位于 /tmp，真实 home 未被触碰）：profile 先从 registry 安装 `@linxin666/dsh-web-all@0.3.20`，再用本地打出的 0.3.21 聚合包升级，其中尚未发布的家族依赖被改写为 workspace tarball。`dsh --profile web --dump-config` 在升级前后逐字节一致——各 173 行、173 个唯一 id、零重复、零增删——profile 的 bundles 列表也未变，因此升级没有引入双挂载、重复行或配置丢失。
- 升级后的 profile 可启动并对外服务：未认证根路径被拒绝，带 token 的启动 URL 返回 303，带 cookie jar 后返回 200，服务出的页面同时引用 `@linxin666/dsh-web-all/client.js` 与 `dsh-better-sidebar/client.js`。
- 本地未覆盖：Windows 与 Linux 的运行时验证（tag 管线在 ubuntu-latest 上跑挂载冒烟，并启动 Windows 桌面载荷）、升级路径的失败注入与重试，以及一次真实的 LLM 工具调用。
