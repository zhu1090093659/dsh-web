# Agent Note: v0.3.22 release run

Status: implemented

## Problem

v0.3.21 的记录确立了常驻发布规则：根别名钉版与 lockfile specifier 随 tag 一起移动，内嵌版本号的 bundle 在同一次提交里重新生成，自动升级兼容性审计是硬门禁。v0.3.22 是这些规则确立后第一次用在普通插件与皮肤增量（39 个提交、212 个改动文件）上的发布，因此本记录写下审计冻结了哪些面、以及这次 bump 实际动了哪些产物。

## Decision

- 目标版本默认取 v0.3.21 的下一个补丁号（registry 的 `latest` 已验证为 0.3.21）；`node scripts/verify-version.mjs 0.3.22` 报告 21 个家族包与根聚合包钉版全部与 v0.3.22 一致。
- v0.3.21..dev 的兼容性审计未发现持久化标识符、profile 格式、线协议或迁移面的破坏性改动。经核验保持不变的有：`packages/dsh-web-all/cordis.patch.yml`（全部行 id 与 self 行）、聚合包成员（两个版本都报告 20 行 / 19 个依赖 / 17 个客户端子包）、聚合包 `exports` 映射与浏览器 loader id、每个包的 `name`、每个 `dsh.engines.dsh` 下限（保持 `>=0.1.5-rc.1`，未高于管线挂载的 `0.1.5-rc.1` 宿主）、`shared/host/legacy-migration.ts`、`scripts/publish-legacy-aggregate.mjs` 以及 Doctor 的迁移代码。
- 本次改动均为增量且向后兼容。`dsh-task-board` 在持久化任务记录上新增可选的 `tags` 字段：store 读取时逐项修复（`normalizeTags`），import 路径做严格校验（`isTaskTagList`），旧客户端仍可读写该行。皮肤中心在背景配置中新增可选的 `bubbleBlur` 字段（缺省 10px）。两处都没有重命名既有键，也没有改变任何其他字段的持久化形态。
- 一个只影响窄人群、且不阻断发布的降级写进了 release notes 而不是省略：初音未来皮肤重做改变了皮肤 manifest，评审 hooks 身份随之重钉（其 `manifestSha256` 变化而 `hooksSha256` 不变），早先安装会失去可执行 hooks 面，直到从工坊重装；皮肤本身照常渲染。
- 纯版本 bump 只移动三个提交入库的 bundle（`dsh-market`、`dsh-web-all` 与 `skins/skin-center` 的 `lib/client.js`），`scripts/lib-artifact-fingerprints.json` 保持不变：产物门禁对源码输入取指纹，而本次 bump 没有改源码，因此 `pnpm libs:check` 在 bump 后的树上通过。发布提交携带 21 个 manifest、根钉版、lockfile specifier、这三个 bundle 与 `docs/release-notes/v0.3.22.md`；它在 `main` 上提交，tag 从 main 打出，随后合并回 `dev`。
- legacy 双发窗口保持硬关闭（`LEGACY_DUAL_PUBLISH_WINDOW_OPEN = false`）：`@linxin666/dsh-web-ui-all` 停在其最终版 0.3.6 并保留迁移弃用说明，管线里的 legacy 步骤是 no-op。
- 桌面打包在 tag 构建时从 registry 解析预装 profile 种子，因此提交入库的种子不做提升。
- 本记录写下时 tag 已经推送，因此记录随其后的 `dev` 提交入库而不是进入 tag 提交；已发布的版本不受影响。

## Alternatives considered

- 只按发布 skill 的命令块 bump `packages/**`：否决——根钉版与 lockfile specifier 会停在 0.3.21，`verify-version.mjs` 会在任何东西进入 npm 之前中止管线。
- 重跑 `pnpm market:build` 并提交 `market/dist`：否决——市场产物的输入是社区索引、皮肤目录与预设，它们都不携带家族包版本；重跑没有产生差异，`market:check` 在提交的 dist 上保持通过。
- 把初音评审哈希重钉当作发布阻断项：否决——这是评审身份的既定行为，皮肤照常渲染，重装恢复方式也写进了 release notes。
- 强制移动已推送的 tag 以纳入本记录：否决——tag 已发布，npm 不允许复用版本号，改写 tag 会让发布通道对着已占用的版本再跑一遍。
- 用 rebase 取代合并回 `dev`：否决——tag 所指的提交必须留在集成分支的祖先链上，而且 `origin/dev` 已经带着并发推进。

## Consequences

- 从 v0.3.21 升级不需要迁移：两条自动路径都没有要改的东西，插件管理器更新与 Doctor 启动前迁移落在同一套包上。
- 没有 provenance 记录或更早的工坊版初音皮肤安装会失去可执行 hooks 面，直到从工坊重装；release notes 写明了恢复方式。
- 之后的每次发布都必须把根钉版、lockfile specifier 与内嵌版本号的 bundle 放在同一次提交里；源码指纹只在源码变化时才变。
- `dev` 会收到其他会话的并发推进，因此只要 `origin/dev` 已经前进，发布后的整合就是合并而不是快进。

## Testing

- tag 之前对 bump 后的树跑的本地门禁：`pnpm sync-shared:check`、`pnpm typecheck`、`pnpm test`、`pnpm test:scripts`、`pnpm aggregate:check`、`pnpm runtime-deps:check`、`pnpm market:check`、`pnpm skin-center:check`、`pnpm skin-hooks:check`、`pnpm community:check`、`pnpm docs:check`、`pnpm i18n:check` 与 `pnpm libs:check` 全部通过。
- tag 管线 run 34762329210 在 11m15s 内成功；两个 job 都完成，包括 `Verify package versions match the tag`、`Publish packages to npm`、`Verify published versions on the registry`、挂载冒烟与 `Create GitHub Release`。
- 发布后核验：21 个家族包全部能从 registry 解析到 0.3.22；`@linxin666/dsh-web-ui-all` 停在 0.3.6 并带弃用说明；GitHub Release 正文使用提交入库的双语 notes，渲染出的 `user-mention` 为 0。
- 把 `origin/dev` 的五个并发提交合并进发布提交后，在合并后的树上重跑了完整门禁，并且用合并后的源码重新构建聚合包，结果与 git 自动合并出的 bundle 逐字节一致。
- 本地未覆盖：Windows 与 Linux 的运行时验证（tag 管线的挂载冒烟跑在 ubuntu-latest）、升级路径的故障注入与重试，以及一次真实的 LLM 工具调用。
