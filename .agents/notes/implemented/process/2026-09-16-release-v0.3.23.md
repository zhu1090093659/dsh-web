# Agent Note: v0.3.23 release run

Status: implemented

## Problem

The v0.3.22 release established the patch execution protocol: the root alias pin and the lockfile specifier move with the tag, version-embedding bundles are regenerated in the same commit, and the automatic-upgrade compatibility audit is a hard gate. v0.3.23 ships accumulated feature and maintenance updates across multiple packages, skins, and the market site (68 commits, 261 changed files), so this note records what the audit verified, what changed, and which artifacts the bump moves.

## Decision

- Target version explicitly specified as 0.3.23 (previous release: 0.3.22, verified published on npm); `node scripts/verify-version.mjs 0.3.23` reports all 21 family packages and the root aggregate pin matching v0.3.23.
- The v0.3.22..dev compatibility audit found no persisted-identifier, profile-format, wire-protocol, or migration-surface break. Frozen and verified unchanged: `packages/dsh-web-all/cordis.patch.yml` (every row id and the self row), aggregate membership (20 rows / 19 dependencies / 17 client children at both revisions), aggregate `exports` map and browser loader id, every package `name`, every `dsh.engines.dsh` floor (`>=0.1.5-rc.1`), `shared/host/legacy-migration.ts`, `scripts/publish-legacy-aggregate.mjs`, and Doctor migration logic.
- The changes are additive and backward compatible: `dsh-usage` adds whale yuan token vouchers for official API usage; `dsh-task-board` adds model-based text parsing and project partitioning; `dsh-pet` scales bubble typography with pet dimensions; `dsh-remote-web-ui` preserves public host addresses across tunnel reconnects; `dsh-market` adopts the deep-sea gallery home layout with telemetry window freshness guards; three new CSS-only skins (`hive-maw`, `ember-fall`, `astral-choir`) ship without executable hooks.
- A version-only bump moves exactly three committed bundles (`dsh-market`, `dsh-web-all`, and `skins/skin-center` `lib/client.js`) and keeps `scripts/lib-artifact-fingerprints.json` in sync: `pnpm libs:write` and `pnpm libs:check` pass on the bumped tree. The release commit carries the 21 manifests, the root pin, the lockfile specifier, the three bundles, `docs/release-notes/v0.3.23.md`, and this decision record; it is committed on `main`, tagged from there, and merged back into `dev`.
- The legacy dual-publish window stays hard-closed (`LEGACY_DUAL_PUBLISH_WINDOW_OPEN = false`): `@linxin666/dsh-web-ui-all` stays frozen at 0.3.6 with its deprecation notice, and the pipeline legacy step is a no-op.
- Desktop packaging resolves the preinstalled profile seed from the registry at tag time, so the committed seed is not bumped.

## Alternatives considered

- Bumping only `packages/**` manifests: rejected - root alias pin and lockfile specifier would stay at 0.3.22 and `verify-version.mjs` would abort the pipeline before publishing.
- Rebuilding market dist without checking hash manifests: rejected - `pnpm market:build` and `pnpm market:check` verify that generated bundles, catalogs, and previews match committed assets exactly.
- Delaying the release notes until after publishing: rejected - the release pipeline prioritizes committed bilingual notes in `docs/release-notes/vX.Y.Z.md` over script-generated drafts.

## Consequences

- Upgrading from v0.3.22 requires no manual migration: both automatic upgrade paths (plugin-manager update and Doctor pre-start migration) land on the same package set without schema conflict.
- The three new skins are immediately installable via the Workshop without client code modifications.
- The released artifacts maintain full compatibility with the existing DSH host runtime.

## Testing

- Local pre-tag gates on the bumped tree: `pnpm sync-shared:check`, `pnpm typecheck`, `pnpm test`, `pnpm test:scripts`, `pnpm aggregate:check`, `pnpm runtime-deps:check`, `pnpm market:check`, `pnpm skin-center:check`, `pnpm skin-hooks:check`, `pnpm docs:check`, `pnpm i18n:check`, and `pnpm libs:check` all pass.
- Version verification: `node scripts/verify-version.mjs 0.3.23` confirms all 21 packages and the root dependency pin match `0.3.23`.
- Post-publish verification: tag pipeline execution, registry version resolution across all packages, and release note presentation without raw mentions.
