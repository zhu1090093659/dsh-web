# Agent Note: v0.3.24 release run

Status: implemented

## Problem

The [v0.3.23 release record](2026-09-16-release-v0.3.23.md) fixed the patch release protocol: the root alias pin and the lockfile specifier move with the tag, version-embedding bundles are regenerated in the same commit, and the automatic-upgrade compatibility audit is a hard gate. v0.3.24 ships 82 commits and 444 changed files accumulated across packages, skins, the market site, desktop packaging, and CI, so this note records what the audit verified, what changed, and which artifacts the bump moves.

## Decision

- Target version explicitly specified as 0.3.24 (previous release: 0.3.23, verified published on npm); `node scripts/verify-version.mjs 0.3.24` reports all 21 family packages and the root aggregate pin matching v0.3.24.
- The v0.3.23..dev compatibility audit found no persisted-identifier, profile-format, wire-protocol, or migration-surface break. Frozen and verified unchanged: every package `name`, `exports` map, `dsh.bundle` / `dsh.client` key set and browser loader id; every `dsh.engines.dsh` floor (`>=0.1.5-rc.1`, satisfied by the pinned `@deepseek-ai/dsh@0.1.5-rc.1` the release lane installs); `packages/dsh-web-all/cordis.patch.yml` and `packages/dsh-web-all/aggregate.yml` (both byte-identical to v0.3.23, so aggregate membership, every row id, and the self row are unchanged); all six `settings.section` registrations and their ids; every slot registration name; the `/api/dsh-usage/overview` and `/api/dsh-usage/refresh` API paths; `shared/host/legacy-migration.ts`; `scripts/publish-legacy-aggregate.mjs`; and the Doctor and plugin-manager migration code.
- Every change classifies as backward compatible without migration:
  - `dsh-usage` drops the optional `bubbleMode` key from its settings `Config` and removes the desktop-pet bubble announcement. This is a dropped field, not a rename: the legacy key left in a persisted profile settings document is accepted by the schemastery object (verified by executing the target schema against a legacy document), so no reader fails and no migration is required. The same package folds dormant catalog aliases into their live route at enumeration time only, which changes which rows render, not any stored identifier.
  - `dsh-task-board` adds the new `dsh-task-board.parse-model` localStorage key and remembers the parse model; no pre-existing key was renamed or removed. The host ledger keeps its on-disk lock format and gains a `Win32_Process` CIM fallback probe so a lock whose PID was reused by a protected process (System, svchost) can still be proven stale.
  - `dsh-liangshen` reworks its bundled preset tree (programmatic tool presentation defaulting to `ptc`, tool-family paging with `tool_activate`, a plugin settings card, an opt-in phase-based reasoning budget). Startup sync replaces the preset directory, prunes target-only files, and removes only the preset ids named in the retire list, while the operator's `agent.cordis.yml` overlay is preserved.
  - The rest is additive: four new asset skins (`whale-maid`, `pixel-anime`, `island-life`, `remiel-starlit`), community-index entries for seven PerryLink plugins plus `dsh-ppt-studio` and `dsh-workbench`, the Workshop editor-picks category, the CI test-discipline gate with a coverage ratchet, and sequential macOS desktop packaging.
- A version-only bump moves the committed bundles (`dsh-market`, `dsh-web-all`, and `skins/skin-center` `lib/client.js`) and keeps `scripts/lib-artifact-fingerprints.json` in sync: `pnpm build`, `pnpm libs:write`, and `pnpm libs:check` pass on the bumped tree. The release commit carries the 21 manifests, the root pin, the lockfile specifier, the refreshed bundles and fingerprints, `docs/release-notes/v0.3.24.md`, and this decision record; it is committed on `main`, tagged from there, and merged back into `dev`.
- The legacy dual-publish window stays hard-closed (`LEGACY_DUAL_PUBLISH_WINDOW_OPEN = false`): `@linxin666/dsh-web-ui-all` stays frozen at 0.3.6 with its deprecation notice, and the pipeline legacy step is a no-op.
- Desktop packaging resolves the preinstalled profile seed from the registry at tag time, so the committed seed is not bumped.

## Alternatives considered

- Bumping only the `packages/**` manifests: rejected - the root alias pin and the lockfile specifier would stay at 0.3.23 and `verify-version.mjs` would abort the pipeline before publishing.
- Adding a migration for the dropped `bubbleMode` settings key: rejected - it was a UI-only preference with a safe default and the target schema accepts the legacy key, so a migration would add a failure mode without changing any observable behavior.
- Listing the reverted namespace-resolution fix in the release notes: rejected - the revert restores the pre-release behavior exactly (the net `allowlist.ts` diff against v0.3.23 is empty), so presenting it as a shipped fix would misreport the artifact. The item is omitted and the fix count adjusted.
- Delaying the release notes until after publishing: rejected - the release pipeline prioritizes committed bilingual notes in `docs/release-notes/vX.Y.Z.md` over script-generated drafts.

## Consequences

- Upgrading from v0.3.23 requires no manual migration: both automatic upgrade paths (plugin-manager update and Doctor pre-start migration) land on the same package set without schema conflict.
- A profile that still carries `bubbleMode` keeps loading; the setting simply has no effect.
- The four new skins are immediately installable via the Workshop without client code modifications.
- Sessions already using the LiangShen preset pick up the reworked presentation defaults on restart; `native` and `both` remain selectable in its plugin settings card.

- Version verification: `node scripts/verify-version.mjs 0.3.24` confirms all 21 packages and the root dependency pin match `0.3.24`.
- Upgrade-path evidence: the shared legacy-migration, Doctor migrate, and plugin-manager update suites run under `pnpm test`; the fresh-install mount smoke (`scripts/e2e-mount.sh`) installs the tag's aggregate tarball into a scratch DSH_HOME with the pinned official CLI and headless-renders it, and the release pipeline gates the GitHub Release on it.
- Post-publish verification: tag pipeline execution, registry version resolution across all packages, and release-note presentation without raw mentions.
