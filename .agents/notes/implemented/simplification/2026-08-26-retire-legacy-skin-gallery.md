# Agent Note: Retire the legacy skin gallery

Status: implemented

## Problem

The original dsh-web skin gallery — the `gallery/` static site (index page, static preview simulator `preview.html`, `manifest.js`/`styles.js`/`official-facade.js` assets) plus its `scripts/gallery-build` pipeline — was superseded by the dsh-market.com Workshop. The market owns the storefront, the try-on simulator (`market/src/preview.html`, vendored `market/shell` try-on), and on-demand skin installation; the gallery added a second static renderer and a second asset registry, maintained by `gallery:check`/release gates and referenced across docs, skills, the PR review tool, and the scaffolder. Its domain survives only as a 301 redirect (`gallery.dsh-market.com`) re-created on every market deploy by `scripts/deploy-market`, and its old Cloudflare Pages project (`dsh-market-gallery`) still exists account-side.

## Decision

- Delete the whole gallery surface: `gallery/` (index.html, manifest.js, styles.js, official-facade.js, preview.html, _headers), `scripts/gallery-build`, `scripts/gallery-headers.test.mjs`, `scripts/gallery-layout.test.mjs`, and the `gallery:check` / `gallery:build` / `gallery:capture` npm scripts; drop the gallery steps and comments from `ci.yml`, `release.yml`, `deploy-market.yml`, and the `gallery` gate entries from docs, skills, and the PR template.
- Move the surviving shared artifact: `official-facade.js` is now generated by `scripts/export-official-facade` into `market/src/official-facade.js` and copied into `market/dist` by `scripts/market-build` (its only consumer). `scripts/market-build-clean.test.mjs` fixture follows the new location.
- Repoint the preview tooling at the market: `scripts/capture-previews` renders `market/dist/preview.html` from `market/dist/manifest.js` (it was already the same simulator and the same skin preview contract); `scripts/skins-montage.mjs` reads the market catalog for the README collage.
- Remove the gallery 301 maintenance: `scripts/deploy-market` no longer creates or updates the `gallery.dsh-market.com` redirect ruleset (`--skip-redirect` / `--redirect-only` are gone; the script is D1 + worker deploy only).
- The Cloudflare-side cleanup (Pages project `dsh-market-gallery`, the `gallery.dsh-market.com` DNS record, the zone 301 ruleset) is account-side and no repo code maintains it; the maintainer deletes it in the dashboard.
- `scripts/pr-review.mjs` drops the gallery page screenshot and the gallery-registry adaptation check; the skin PR check is now `checkSkinPreviews` (new skins must add `preview/{light,dark}.jpg`), and the preview copy path is fixed to `packages/skins/skin-center/skins/<id>/preview/<mode>.jpg` (it pointed at the pre-move path with a stale `.png` extension).
- Skin README pairs and the skin developer skill now instruct `pnpm market:build` + `open market/dist/preview.html?...` instead of gallery commands; `docs:write-pair` re-recorded the touched skins.

## Alternatives considered

- Keep the gallery as the simulator source and only stop deploying it: rejected — the market simulator is the same renderer fed from the same v2 skin assets, and every skin change already regenerates `market/dist`; a second renderer plus its asset registry is pure duplicated maintenance, which is what broke the gallery consistency gates across every skin PR.
- Keep publishing the redirect rule and retire only the site: rejected — the domain is being retired entirely; the 301 is precisely the thing that keeps the old host and domain alive, and dropping it from `deploy-market` is what makes the dashboard-side deletion complete.
- Copy `gallery/preview.html` + facade into `market/src/` and keep the gallery's own page generator: rejected — `market/src/preview.html` already is the simulator's home (it evolved from the gallery page), so only the facade file needed a new home; the gallery index/manifest/styles duplication carries no unique value.

## Consequences

- New skin onboarding: `pnpm market:build` regenerates `market/dist` (registry + styles + zips) and `pnpm market:check` is the single storefront consistency gate; `skin-center:check` still validates the v2 catalog, `community:check` the plugin index.
- `capture-previews` now requires a fresh `market/dist` (committed dist is always current per `market:check`), and reads the market manifest with site-root-relative asset paths.
- The publish-prep and release gate lists drop `gallery:check`; release version bumps rebuild `market/dist` instead of gallery assets.
- Remaining textual "gallery" occurrences live only in frozen history (`docs/archive/`, `docs/release-notes/`, older Agent Notes), the official GUI facade snapshot (an external capture), and vendored `market/shell` build outputs; they are not repository-owned gallery infrastructure.

## Testing

- `scripts/market-build` regenerated `market/dist` (1138 files) and `market:check` reports "dist up to date" in build- and check-mode (shell dist moved aside to reuse the committed tryon hash manifest, matching CI).
- `pnpm test:scripts` (209 tests), `pnpm docs:check`, and `scripts/pr-review.test.mjs` (38 tests, including the replaced gallery-adaptation test) pass.
- `scripts/deploy-market` and `scripts/pr-review.mjs` pass `node --check`.
