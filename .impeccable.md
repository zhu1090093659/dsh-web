## Design Context

### Users

Developers using DSH Web for sustained technical conversations and session management. They value fast, predictable controls that do not distract from the conversation.

### Brand Personality

Calm, technical, restrained, and dependable. Controls should feel native to the existing DSH interface instead of looking like a separate application layered on top.

### Aesthetic Direction

Follow the host composer's visual language across light, dark, and custom skins. Prefer subtle surfaces, rounded containers, compact actions, and low-contrast boundaries. Avoid nested card effects, loud focus colors, and sharp rectangular frames inside rounded controls.

### Design Principles

- Match existing host controls before introducing plugin-specific styling.
- Keep the conversation content visually dominant and controls secondary.
- Preserve one clear container boundary; do not add an inner textarea frame.
- Support host themes and skins without allowing broad skin selectors to break component structure.
- Keep focus and disabled states usable without making them visually aggressive.
