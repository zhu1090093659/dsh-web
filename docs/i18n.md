# 双语文档契约（i18n）

本仓库面向人机双读者，所有包 README 均维护英文与简体中文两份，规则见
[docs/AGENTS.md](AGENTS.md)。本文件定义配对机制、维护流程与门禁。

## 配对机制

一份双语文档是一组三个文件，同目录平铺：

| 文件 | 内容 |
| --- | --- |
| README.md | 英文版 |
| README.zh.md | 中文版 |
| README.i18n.yaml | 配对一致性记录：两侧的 git blob hash |

`README.i18n.yaml` 记录两侧文件在「最后确认一致」时点的内容 hash（git
hash-object，内容寻址，不依赖提交）。编辑任一侧后，配对记录与另一侧即
失同步，`pnpm docs:check` 变红。

## 维护流程

1. 编辑任一侧（中英同等权威，先写哪侧都行）。
2. 同一次改动内把另一侧同步成同一事实，保持结构镜像。
3. 确认两侧表达一致后重录配对记录：

```sh
pnpm docs:write-pair <包目录名>   # 如 dsh-ssh 或 dsh-usage
```

重录产生的 yaml diff 就是「我确认了这次一致性」的可审查动作。

## 结构镜像要求

两侧除语言切换行与正文文本外，结构必须一一对应：

- 标题层级与顺序一致；
- 代码块（围栏与内容）一一对应；
- 表格行数与列数一致；
- 列表种类与条目数一致；
- 链接目标一致（切换行除外）。

语言切换行：英文 H1 后 `English | [中文](README.zh.md)`；中文 H1 后
`[English](README.md) | 中文`。

## 门禁

`pnpm docs:check`（scripts/verify-docs.mjs）机械校验：三件套完整、记录
hash 与当前内容一致、切换行存在、结构签名匹配。门禁只证明「记录时两侧
一致」，不判断翻译质量——忠实与通顺由评审负责。

## 范围

- 覆盖：packages/ 下所有插件包与皮肤包的 README；
- 不含：docs/archive/ 冻结历史、构建产物、第三方代码；
- 新增包必须自带完整三件套（`scripts/dsh-plugin-new` 已生成骨架）。

## UI 语言包机制与 dsh-i18n

README 双语契约之外，插件 UI 文案本身走官方 locale 服务：各包在
`src/client/` 字典文件里以 `zh` 字典为 key 源、`en` 完整对照，经
`ctx.locale.register(ns, { zh, en })` 注册；SDK 缺键回退链为
ns -> common -> en -> key。

- 第三语言 Русский（ru）由 `packages/dsh-i18n` 集中承载：该包经
  `ctx.locale.addLanguage({ id: 'ru', label: 'Русский', fallback: 'en' })`
  注册语言目录项，再用单语言非 typed 的
  `ctx.locale.register(ns, 'ru', dict)` 为每个家族插件命名空间注册 ru
  字典；来源包不自带 ru 字典。各包新增/修改 zh 键后必须同步补 ru 并通过
  `pnpm i18n:check`。
- `pnpm i18n:check`（scripts/i18n-audit.mjs）是合并前主门禁之一：校验各包
  zh/en 键集一致、`{placeholder}` 占位符集合在 zh/en/ru 间一致、ru 字典覆盖
  每个 ns 的 zh 键集、client 侧文件剥注释后无漏网 CJK 文案（行级豁免用
  `i18n-allow: <理由>` 注释，host 半区仅告警）。`--report` 输出各 ns 键数与
  ru 覆盖率，`--template` 导出待翻译模板 JSON。

## 插件页展示元数据

官方插件列表（设置 → 插件列表）的行标题与灰色用途说明来自各包导出的 `<specifier>/locale/<lang>.json` 中的 `meta.title` 与 `meta.description`。

- **官方通道与解析规则**：宿主 `@deepseek-ai/dsh-app-boot` 的 `readPluginMeta` 先解析 `<specifier>/locale/en.json`，再枚举该目录里的每一个 `*.json` 文件并逐个通过 `exports` 解析。宿主按请求实时读取展示元数据，修改 `locale` 文件后只需在浏览器中刷新页面即可即时生效，无需重启 `dsh web` 服务。
- **exports 与 files 的硬约束**：包根 `locale/` 目录在盘上的文件集合与 `package.json` 中的 `exports` 键（`./locale/<lang>.json`）必须**严格一一对应**，多一个文件缺 export 或多一个 export 缺文件，都会导致整条元数据读取抛错，整行静默回落为 npm 包名且不显示描述和图标。同时，`locale` 目录必须显式写入 package.json 的 `files` 白名单，否则发布 tarball 会丢失该元数据。
- **根 bundle 包的解析差异**：仓库根的 bundle 包（`package.json`，name 为 `dsh-web`、private、`dsh.bundle.patch` 指向聚合 patch）同样随包提供 `locale/zh.json`（全家桶 / 一键装齐 DSH Web 官方插件）与 `locale/en.json`（Web bundle / Install every DSH Web plugin in one step.），并在根 `package.json` 的 `files` 里加入 `"locale"`。根 bundle 没有 `exports` 字段，宿主按文件路径直接解析即可，不需要 `./locale/*.json` 导出键；新门禁 `scripts/plugin-display-metadata.test.mjs` 只扫描 `packages/*`，不校验根目录。
- **语言范围与回落机制**：包级展示元数据统一随包提供 `zh` 与 `en` 两份（`locale/zh.json` 与 `locale/en.json`）。宿主在当前语言缺对应文件时（例如俄语 `ru`）自动回落到 `en`，因此包级无需自带 `ru.json`；聚合家族行的 ru 文案由 `dsh-web-all` 的 `shell-metadata` 单独维护。
- **文案约束**：`meta` 对象只包含非空的 `title` 与 `description`。中文标题写产品名，中文描述必须包含汉字且**严格不超过 20 个汉字**（以保证在插件卡片单行完整展示），且中英文案不得完全相同。
- **卡片图标（icon）**：插件卡片图标由 `package.json` 顶层的 `icon` 字段声明（相对路径，如 `"icon.svg"`），格式支持 SVG/PNG/JPEG/WebP，文件大小**上限 256 KiB**，且该图标文件必须位于包内并加入 `files` 白名单。
- **门禁把关**：`scripts/plugin-display-metadata.test.mjs`（`node:test`）对 `packages/` 下全部包进行机械校验，把关盘上文件与 exports 映射的一一对应、文案非空与长度限制、以及图标位置与大小。该测试与 `scripts/aggregate.test.mjs` 一同在 `pnpm test:scripts` 中运行。
