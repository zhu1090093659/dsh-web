本次发布包含多项核心架构升级与新特性：远程访问链路（`remote-bridge`）接管全部网络接入基建并收敛入站网关，家族聚合包正式退役旧浏览器镜像 `remote-web-ui`；任务看板引入基于 Go 独立自建中枢 `team-hub` 的团队协作扩展体系，并支持卡片图片与文件附件；浏览器视图新增直连外部浏览器的 real-browser CDP 模式；官方插件页面接入统一展示元数据通道与内置插件分组。四个卫星仓在本版同版本对齐到 `0.4.13`，其中皮肤中心彻底修复 Windows 平台原生 addon 引起的插件安装阻塞缺陷。

> **远程接入栈完整迁入 `remote-bridge`，聚合包退役 `remote-web-ui`**：网络接入基建（中继注册、云穿透隧道、Durable Object 连接器、局域网绑定转发与防火墙控制）全数收敛至 `packages/dsh-remote-bridge`，新增仅绑定回环地址的入站网关（`ingress-gate`），严格将外部暴露面收敛至 `/ios/v1` 协议。家族聚合包 `@linxin666/dsh-web-all` 移除 `remote-web-ui` 挂载行，存量 profile 凭 tombstone 导出与 `retiredPlugins` 清单平滑兼容，不中断启动流程；中继身份目录与设备状态保留历史路径，已配对移动端无需重新配对。
> **任务看板团队协作与 Go 单二进制自托管服务 `team-hub`**：引入多 Host 共享的团队协作扩展（`@linxin666/dsh-task-board-team`），配合全新独立 Go 服务 `team-hub`（SQLite 存储、内存重放与实时 WebSocket 频道，零外部依赖）。看板扩展契约新增 `followUp` 与 `rework` 可选能力；支持人类或 Agent 负责人、GitHub OAuth 登录与管理员邮箱初始化引导、Host Token 节点认领与带租约执行、待答问题求助路由与前置运行工作区认领闸门。
> **任务看板支持卡片附件，隔离模型凭据**：看板 schema 升级至 v7，卡片支持上传图片与文件附件；账本严格遵循「只存元数据与 sha256 摘要，绝不存原始字节」，字节经由官方附件存储（`ctx.attachments`）校验。修复模型选择器中提供商名称的展示；provider 集成凭据不再裸露在线上广播账本中。
> **浏览器视图新增真实浏览器 CDP 模式**：`dsh-browser-view` 新增对外部 Chrome/Edge 进程 CDP 端点（`http://127.0.0.1:9222`）的直连接管模式（显式 opt-in），支持在真实 profile 登录态下接管页面与投屏，且不干扰默认隔离浏览器模式。
> **插件页展示元数据与内置插件分组**：全家族包补齐官方 `locale/<lang>.json` 展示元数据（支持中英双语，部分含俄语），聚合包家族行展示面向用户的本地化名称；官方插件页面底部新增内置插件分组与更新检测工具栏；彻底清除 5 个历史已退役家族的空壳导出。
> **四个卫星仓同版本对齐到 `0.4.13`**：四个卫星仓先发并对齐至 `0.4.13`。皮肤中心（`dsh-skins`，`66ec9f1`）将 CSS 安全转换隔绝在短生命周期 worker 进程中，彻底解决 Windows 下原生 addon 导致插件安装失败的问题；宠物（`dsh-pet`，`9ccb048`）、社区插件索引（`dsh-community-plugins`，`3b0673d`）与预设中心（`dsh-presets`，`92c3154`）在本区间无功能变更，同批对齐发布。

### 升级须知

- **更新任务误报已在 0.4.13 修复**：`plugin-manager` 不再把 pnpm 11 的构建脚本门禁（`ERR_PNPM_IGNORED_BUILDS`）造成的非零退出码报成失败；此前该情形会被报成更新失败，而安装其实已经生效。措辞按本版修复处理，状态判定与实际安装结果保持一致。
- **远程访问路径变更**：浏览器配对路径随 `remote-web-ui` 从聚合退役，手机端走 `remote-bridge` 的 `/ios/v1` 协议；若此前曾**单独安装**过 `@linxin666/dsh-remote-web-ui`，升级后必须卸载它（否则与 bridge 争同一个中继身份与租约）。已配对的移动端无需重新配对。
- **两处行为变化**：设置页「内置插件」分区由聚合默认下线（禁用本插件可恢复）；任务看板 wire 不再下发 provider 集成凭证字段。
- **0.3.x 存量人工迁移**：不存在 Doctor 预启动迁移；旧包 `@linxin666/dsh-web-ui-all` 冻结在 0.3.6 且已 deprecated，其网关在当前运行时（rc.5）不服务，无法 GUI 自动迁移。给出可执行的三步迁移步骤：
  1. `dsh plugin remove @linxin666/dsh-web-ui-all`
  2. `dsh plugin add @linxin666/dsh-web-all@0.4.13`
  3. 把 `dsh.profile.bundles` 里的旧名**原位替换**为新名 `@linxin666/dsh-web-all`（官方 CLI 只写 `dependencies`，不写 `bundles`；漏掉第三步会 `skipping profile bundle`）。

  若迁移中途中断（profile 变成空 `dependencies`、`bundles` 仍指旧名），**不要**按提示执行 `dsh plugin install`（会把已废弃的 0.3.6 装回来），按上面三步重做。
- **平台验证声明**：本版在 macOS 实测通过；Linux 与 Windows **未验证**。未验证的具体面包括：新增回环监听（`ingress-gate`）、`$DSH_HOME/remote-bridge/model-efforts.json` 的新权限位（目录 0700 / 文件 0600）、以及 `task-board-team` 的路径解析（含 Windows 盘符与 `~`，只读）。
- **退役家族说明**：`doctor` / `desktop-launcher` / `dsh-perf` / `describe-image` / `model-capabilities` 五个家族的残留导出已清除，它们在 0.4.12 就已不挂载，无功能损失；残留行会被记为 `failed import` 但**不影响宿主启动**。

This release delivers core architectural upgrades and new capabilities: the remote access path (`remote-bridge`) takes over the full network ingress infrastructure with a hardened ingress gate, while the aggregate package officially retires the legacy browser mirror `remote-web-ui`; the task board introduces team collaboration powered by the standalone Go self-hosted hub `team-hub` and adds card attachments for images and files; the browser view introduces a real-browser CDP mode; and official plugin page display metadata and built-in plugin grouping are established. The four satellite repositories align to `0.4.13`, with the skin center isolating CSS safety transforms in short-lived workers to eliminate plugin installation failures on Windows.

> **The remote ingress stack moves into `remote-bridge`, and the aggregate retires `remote-web-ui`**: All network ingress infrastructure (relay registry, cloudflared tunnels, Durable Object connectors, LAN forwarding and firewall controls) converges into `packages/dsh-remote-bridge`. A loopback-only ingress gateway (`ingress-gate`) strictly restricts the external attack surface to the `/ios/v1` protocol. The aggregate `@linxin666/dsh-web-all` removes `remote-web-ui`, with existing profiles smoothly supported via tombstone exports and `retiredPlugins` registration without launcher interruptions; relay identity and device states keep their historical paths so paired devices remain paired.
> **Task board team collaboration and the Go standalone service `team-hub`**: Introduces multi-host team collaboration via `@linxin666/dsh-task-board-team` and the standalone Go service `team-hub` (SQLite storage, in-memory replay and real-time WebSocket channels, zero external dependencies). The task board extension contract adds optional `followUp` and `rework` capabilities, supporting human or Agent assignees, GitHub OAuth login and admin email bootstrap, Host Token node claims with leases, question routing and workspace claim gates.
> **Task board card attachments and credential isolation**: The task board schema upgrades to v7, supporting image and file card attachments. The ledger stores metadata and sha256 digests only—never raw bytes—with bytes validated through official attachment storage (`ctx.attachments`). Model pickers now display the model provider name, and provider integration credentials stay off the public board wire.
> **Browser view gains real-browser CDP mode**: `dsh-browser-view` adds an explicit opt-in mode connecting directly to an external Chrome/Edge CDP endpoint (`http://127.0.0.1:9222`), allowing page inspection and screencasting using real profile logins without altering the default isolated browser mode.
> **Plugin page display metadata and built-in plugin group**: All family packages supply official `locale/<lang>.json` display metadata (bilingual Chinese/English, with Russian where applicable), rendering localized display titles in the aggregate; the official Plugins page gains a built-in plugin group and an update toolbar; five retired plugin shells are fully removed.
> **The four satellite repositories align to `0.4.13`**: All four satellites publish first and align to `0.4.13`. The skin center (`dsh-skins`, `66ec9f1`) isolates CSS safety transforms inside short-lived worker processes, resolving Windows plugin install failures caused by native addons; pet (`dsh-pet`, `9ccb048`), community plugin index (`dsh-community-plugins`, `3b0673d`) and preset center (`dsh-presets`, `92c3154`) carry no functional changes and align their version numbers.

### Upgrade Notes

- **Update Task False Alarms Fixed in 0.4.13**: `plugin-manager` no longer reports a non-zero exit code caused by pnpm 11's build script gate (`ERR_PNPM_IGNORED_BUILDS`) as a failure; previously this condition was reported as an update failure even though installation had already taken effect. Fixed in this release to align status reporting with actual installation results.
- **Remote Access Path Changes**: The browser pairing path is retired from the aggregate along with `remote-web-ui`, and mobile devices connect via `remote-bridge`'s `/ios/v1` protocol; if `@linxin666/dsh-remote-web-ui` was previously installed **standalone**, it must be uninstalled after upgrading (otherwise it will contend with bridge for the same relay identity and lease). Paired mobile devices do not need to re-pair.
- **Two Behavioral Changes**: The "Built-in Plugins" section in Settings is taken offline by default by the aggregate (disabling this plugin restores it); the task board wire no longer transmits provider integration credential fields.
- **Manual Migration for 0.3.x**: There is no Doctor pre-launch migration; the legacy package `@linxin666/dsh-web-ui-all` is frozen at 0.3.6 and deprecated, and its gateway does not serve under the current runtime (rc.5), making automatic GUI migration impossible. Follow these three executable steps:
  1. `dsh plugin remove @linxin666/dsh-web-ui-all`
  2. `dsh plugin add @linxin666/dsh-web-all@0.4.13`
  3. **In-place replace** the legacy name with the new name `@linxin666/dsh-web-all` in `dsh.profile.bundles` (the official CLI only writes `dependencies`, not `bundles`; omitting the third step results in `skipping profile bundle`).

  If migration is interrupted halfway (the profile ends up with empty `dependencies` while `bundles` still references the legacy package name), **do not** run `dsh plugin install` as prompted (which reinstalls the deprecated 0.3.6); redo the three steps above instead.
- **Platform Verification Notice**: This release was tested and verified on macOS; Linux and Windows remain **unverified**. Specific unverified areas comprise: the newly added loopback listener (`ingress-gate`), new permission bits for `$DSH_HOME/remote-bridge/model-efforts.json` (directory 0700 / file 0600), and path resolution in `task-board-team` (including Windows drive letters and `~`, read-only).
- **Retired Plugin Families Notice**: Residual exports for the five families `doctor` / `desktop-launcher` / `dsh-perf` / `describe-image` / `model-capabilities` have been cleared; they were already unmounted in 0.4.12, with no loss of functionality; residual lines will be logged as `failed import` but **do not affect host startup**.
