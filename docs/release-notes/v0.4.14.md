This release focuses on control plane governance, cross-platform runtime hardening, and low-level protocol resilience: the Workshop (`dsh-market`) relay control plane has been overhauled with a convergence cache and unified rate-limit budgets to eliminate Cloudflare account API exhaustion, and its deployment pipeline is fully migrated to the Cloudflare official `cf` CLI; remote access (`dsh-remote-bridge`) corrects the default push relay address and routes relay leases by subscription tier; the plugin manager (`dsh-plugin-manager`) adds systemd user unit restarts and bundle landing verification; the aggregate package retires the `web-ui-update` row; the Windows shell (`dsh-win-bash`) runs payloads from a verified cache outside the package and cleans up private temporary directories upon exit to eliminate `ERR_PNPM_EPERM` locks; the browser view (`dsh-browser-view`) supports clipped and scaled lossless PNG screenshots; and `dsh-git-graph` pins child git processes to English to prevent overwrite guard misjudgment. The four satellite repositories align to `0.4.14`.

> **Relay control plane overhaul and rate-limit budget tightening**: The relay control plane introduces a convergence cache and a D1 account budget guard (capped at 600 calls per 5 minutes), answering active claims directly from cached state without spending Cloudflare account API quota and resolving claim storm throttles. The default transport mode flips to bridge, and leases support subscription-tier routing and multi-meeting-point distribution. D1 migration `0011` adds three nullable convergence cache columns. All 15 relay limits are unified and locked in `relay-limits.js`, with registration/claim and bridge connection windows tightened to 300 seconds. Relay failures return unified frozen error codes. `deploy-market` switches completely to the official `cf` CLI with network-layer retry logic, and the default push relay endpoint is corrected to the account service actually used by the mobile app.
> **Plugin manager adds systemd service restart and bundle landing verification**: When the host runs under a systemd user service, the plugin manager identifies the cgroup and `INVOCATION_ID` to request a unit-level restart via systemd, adding a fourth `systemd` state to the restart wire protocol. A new bundle landing verification check (`bundleSelectionMissing`) rejects updates where build-script gates write dependencies to the profile but drop bundle entries. The aggregate package officially retires the `web-ui-update` (`dsh-update`) row, maintaining smooth compatibility for existing profiles via tombstone exports and `retiredPlugins` registration.
> **Windows shell execution and lifecycle hardening**: Resolves the `ERR_PNPM_EPERM` package-directory lock defect on Windows (issue [#1996](https://github.com/zhu1090093659/dsh-web/issues/1996)), where persistent background bash processes blocked plugin updates and reinstalls; `dsh-win-bash` now unpacks and executes verified payloads outside `node_modules` under `<DSH_HOME>/win-bash/runtime/<key>`. Each shell process reclaims its private temporary directory upon termination, timeout, abort, or cancellation, and orphaned temporary directories are swept on plugin mount (issue [#1993](https://github.com/zhu1090093659/dsh-web/issues/1993)).
> **Browser view adds clipped and scaled lossless PNG screenshots**: `dsh-browser-view` adds `clip` (CSS pixel bounding box matching `browser_snapshot`), `scale` (1x/2x/3x), and `format` (defaulting to lossless `png`) parameters to `browser_screenshot`, preventing fine 1-2px layout details from being lost to lossy JPEG compression or wasting vision token budgets, while planning screenshot sizes based on the tab's active viewport.
> **Task board event stream resilience and team settings card refinement**: Resolves an issue where silent disconnects or write failures caused SSE event streams to stall without triggering browser reconnects; the transport now resynchronizes snapshots on connect/reconnect and polls in-flight tasks until settled. The team settings section is refactored into a standard nested settings card layout to prevent label squeezing and broken wrapping, and task boards support syncing GitHub issue close state grouped by repository.
> **The four satellite repositories align to `0.4.14`**: All four satellites publish first and align to `0.4.14`. ### Upgrade Notes

- **Relay Control Plane Rate Limit Budget Tightening**: The rate-limit window for the relay control plane (`dsh-market` Worker) is tightened from 60s to 300s, the per-id budget is lowered from 6 to 3, and the per-IP budget is adjusted to 60 (counted per client IP directly); the bridge door reuses this 300s window, effectively reducing connection budgets from 6 per minute to 6 per 5 minutes. This is a user-perceptible change: under network jitter or frequent reconnects, clients are more likely to receive HTTP 429 rate-limit responses, and clients will wait according to their backoff window.
- **Relay Database Migration and Transport Mode Flip**:
  - D1 migration `0011_relay_lease_convergence_cache.sql` adds three nullable columns (`converged_at` / `token_cache` / `token_at`) to `relay_leases`. Legacy rows reading NULL automatically re-converge and populate the cache without requiring a backfill. The deployment sequence in `scripts/deploy-market` strictly enforces `cf d1 migrations apply` before `cf deploy`.
  - The default relay lease transport mode flips from quick to bridge, but **existing lease rows retain their recorded transport mode** (the upsert's `ON CONFLICT` clause does not overwrite the `mode` column), so the default flip only affects newly created leases.
- **Restart Protocol Fourth State and Legacy Page Compatibility**: The restart wire protocol in `dsh-plugin-manager` adds a fourth state `systemd` (wire shape `{restart: {mode: 'systemd', unit}}`). On hosts managed by systemd user units, **an unrefreshed browser page** clicking Restart will display an error due to the unrecognized mode; simply refreshing the page restores normal behavior with no data loss.
- **Retirement of `web-ui-update` Row from Aggregate**: Aggregate `@linxin666/dsh-web-all` removes the `web-ui-update` (`dsh-update`) mount row while maintaining tombstone subpath exports and `retiredPlugins` registration. Profiles that previously set this entry to `disabled` will log a `patch: entry "web-ui-update" not found` warning on startup until the user runs an update via the plugin manager; host startup and data integrity are unaffected.
- **Upgrade Entry Support Matrix and Manual Recovery**:
  - The upgrade matrix follows 0.4.13: There is no Doctor pre-launch migration; executing `dsh web` directly does not install new versions (it only fixes row names after startup); only the plugin manager update task performs backups, `--dump-config` prechecks, and rollbacks. Manual CLI upgrades retain orphaned disabled override rows.
