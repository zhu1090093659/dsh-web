A reliability release across four plugins: `dsh-ssh` fixes hung connects, connection-pool races, terminal backpressure stalls and transfer cleanup; `dsh-task-board-ssh` adds the one-call `task_board_ssh` agent surface; `dsh-remote-bridge` judges attachment identity by the directory entry and stops rejecting valid attachments across platforms; `dsh-task-board` adds optional fields to execution records. The four satellite repositories (skin center, pet, community plugin index, preset center) and the main monorepo ship `0.4.21` together.

> **Satellites ship at the same version**: `@linxin666/dsh-client-ui-skin-center`, `@linxin666/dsh-pet`, `@linxin666/dsh-client-ui-community-plugins` and `@linxin666/dsh-client-ui-preset-center` are all published at `0.4.21`, and the aggregate's dependency ranges move to `^0.4.21`. Skin Center moves the market content of `remiel-starlit` to 0.1.2 (panel opacity pinned per platform), the community plugin index collects four new plugins and renames `dsh-man-031` to `dsh-man-report`, and Pet and Presets carry a version alignment only.

> **Compatibility**: no breaking changes in 0.4.21. Package names, aggregate row ids (`web-ui-*`), settings section ids, `/api/*` paths, request headers and local persistence keys (`dsh.taskBoard.v1`, `$DSH_HOME/dsh-ssh.json`, `$DSH_HOME/task-board/ledger-v2.json`) are unchanged, so upgrading from 0.4.19 or 0.4.20 needs no migration; restart DSH after the update. The `dsh.engines.dsh` floor stays `>=0.2.2-rc.3`. In the community plugin index `dsh-man-031` is now `dsh-man-report`; the store matches on `id` / `npm` / `repo` with no aliases, so anyone who installed the old package sees that entry as not installed and moves to the new package through the npm deprecation notice.

> **Rolling back**: existing board and SSH records still parse through their original fields; this release only adds optional ones (execution summary, error code, remote-run execution id and last-activity time). Remote run records written by 0.4.21 carry those new keys, which the 0.4.20 parser rejects, so drop the remote runs produced during 0.4.21 before rolling back to 0.4.20.
